# 검증 및 출시 기준

작성일: 2026-09-09 · 상태: 테스트 계획, 실제 통과 결과 없음

## 1. 기본 정책

모든 F 기능 ID를 테스트 ID 및 증거와 연결한다. '버튼이 존재함'은 기능 검증으로 인정하지 않는다. 실제 파일 fixture, 실제 창 조작, 재시작 후 상태, 실패 후 데이터까지 검사한다. 테스트는 별도 임시 볼륨·폴더에서 수행한다.

개별 기능 완료 조건:

- 정상 동작, 경계 입력, 오류, 취소와 재진입을 검증한다.
- 파일 변경은 전후 내용·메타데이터·대상 identity를 비교한다.
- UI는 마우스·키보드·VoiceOver를 확인한다.
- 사용자 설정은 저장·재시작·마이그레이션을 확인한다.
- 원본 대응 항목과 macOS 차이가 문서에 연결된다.

## 4. UI 비교 기준

원본 시각 기준은 M0의 실제 캡처에서 만든다. 현재 문서의 치수는 시작값이므로 원본 측정 없이 픽셀 일치했다고 기록하지 않는다.

필수 캡처: 홈, 5개 보기, 상하·좌우 분할, 검색, 정보·미리보기, 속성, 진행, 충돌, 이름 변경, 압축, 연결, Git, 팔레트, 각 설정 페이지. 각 화면에서 해당하는 normal/hover/focus/selected/disabled/loading/empty/error/drag 상태를 포함한다.

1. 동일 fixture·정렬·선택·창 논리 크기·언어·테마를 고정한다.
2. 원본 캡처와 macOS 결과의 비교 영역을 지정한다. traffic lights·OS 폰트 rasterization·시스템 권한 창·native material 차이는 이유와 함께 마스크한다.
3. 주요 패널 경계와 간격은 확정 설계 대비 ±2pt 이내를 초기 목표로 한다. 텍스트 겹침·잘림·보이지 않는 버튼은 허용하지 않는다.
4. 맥 내부 회귀 스냅샷은 동일 OS·scale·폰트를 고정하고 초기 pixel difference 기준 1% 이하로 시작한다. 렌더링 노이즈 보정은 실제 baseline에서 확정하며 실패를 없애기 위해 무분별하게 임계값을 늘리지 않는다.
5. Windows 대 macOS 이미지는 픽셀 오차율만으로 합격시키지 않는다. 정보 구조, 조작 가능성, 크기, 정렬, 상태, 원본 차이를 사람 검토와 함께 판정한다.
6. 접근성은 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1을 프로젝트 목표로 삼고 선택·오류를 색만으로 구분하지 않는다.

캡처 파일명: `<ui-id>_<state>_<theme>_<locale>_<size>_<scale>.png`. 테스트 보고서에는 source SHA, app SHA, macOS build, fixture version을 함께 기록한다.

## 5. 성능 예산

아래는 제안된 개발 목표이며 현재 측정 결과가 아니다. M0에서 기준 장비(최소 16GB RAM·로컬 SSD), release build, 데이터 분포를 고정한다. 네트워크와 클라우드 다운로드 시간은 로컬 성능과 분리한다.

| 지표 | 초기 목표 | 측정 방법 |
|---|---:|---|
| 콜드 시작→상호작용 | p95 ≤ 2초 | 캐시 조건 정의, 20회 |
| 로컬 10,000항목 첫 표시 | p95 ≤ 500ms | 첫 100개 표시 시점, 썸네일 제외 |
| 로컬 10,000항목 전체 열거 | p95 ≤ 2초 | 기본 metadata만, 실제 저장장치 기록 |
| 100,000항목 첫 표시 | p95 ≤ 1초 | 전체 완료와 구분, 진행 표시 |
| 보이는 행 스크롤 | 60Hz 화면에서 16.7ms frame budget 목표 | Instruments, hitch 비율 별도 기록 |
| 주요 조작 반응 | p95 ≤ 100ms | 입력→피드백; I/O 완료 시간과 구분 |
| 취소 클릭→상태 반영 | ≤ 100ms | I/O 종료 완료는 별도 측정 |
| 유휴 메모리 | ≤ 200MB 목표 | 기본 창 1개, 5분 안정화 |
| 10,000항목 탐색 | ≤ 500MB 목표 | 캐시 포함, 반복 후 plateau 확인 |
| 로컬 대용량 복사 | 기준 native copy 대비 ≥ 80% 목표 | 동일 보존·검증 정책에서 비교 |

썸네일·해시·Git 상태는 지연 로딩하고 가시 영역을 우선한다. 폴더 총 크기를 목록 표시 전에 재귀 계산하지 않는다. 100,000항목에서도 전체 view를 한 번에 생성하지 않는다. provider 감시는 사용 중인 위치를 중심으로 공유하고 닫은 탭의 작업을 해제한다.

8시간 연속 탐색·전송·탭 열기/닫기 시험에서 crash, 지속적인 메모리 증가, watcher/task 누수가 없어야 한다. 성능 목표를 못 맞추면 원인과 측정 증거를 기록하고 정식 출시 전에 해결하거나 명시적인 목표 변경 결정을 남긴다.

## 6. CI와 증거 저장

- 변경별: Swift 빌드, Domain·Operations 단위 테스트, 임시 파일 시스템 통합 테스트.
- UI 변경: macOS UI 자동화와 스냅샷, 실제 창 수동 검토.
- provider 변경: capability별 계약 테스트와 오류 주입.
- 릴리스 후보: 지원 환경 전체 회귀, 교차 볼륨, 네트워크, 성능, 장시간 시험.

향후 증거 위치: `docs/verification/<version>/` 아래 `coverage.csv`, `test-report.md`, `performance.json`, `ui/`, `platform-differences.md`, `release-checklist.md`. 실제 실행 전 빈 성공 보고서를 만들지 않는다.

coverage 지표를 분리한다.

- 목록 대응률 = 분류·대응 결정이 있는 원본 항목 / 원본 전체 항목.
- 적용 기능 검증률 = 검증 통과 E/A 항목 / 전체 E/A 항목.
- 플랫폼 차이 개수 = X 및 미해결 V 항목 수. 이를 분모에서 숨기지 않는다.

## 7. 정식 출시 게이트

- [ ] 원본 tag/SHA 및 맥 SHA 고정, 개별 명령·설정·화면 인벤토리 100% 대응.
