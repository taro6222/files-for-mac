## 4. UI 비교 기준

원본 시각 기준은 M0의 실제 캡처에서 만든다. 현재 문서의 치수는 시작값이므로 원본 측정 없이 픽셀 일치했다고 기록하지 않는다.

필수 캡처: 홈, 5개 보기, 상하·좌우 분할, 검색, 정보·미리보기, 속성, 진행, 충돌, 이름 변경, 압축, 연결, Git, 팔레트, 각 설정 페이지. 각 화면에서 해당하는 normal/hover/focus/selected/disabled/loading/empty/error/drag 상태를 포함한다.

1. 동일 fixture·정렬·선택·창 논리 크기·언어·테마를 고정한다.
2. 원본 캡처와 macOS 결과의 비교 영역을 지정한다. traffic lights·OS 폰트 rasterization·시스템 권한 창·native material 차이는 이유와 함께 마스크한다.
3. 주요 패널 경계와 간격은 확정 설계 대비 ±2pt 이내를 초기 목표로 한다. 텍스트 겹침·잘림·보이지 않는 버튼은 허용하지 않는다.
4. 맥 내부 회귀 스냅샷은 동일 OS·scale·폰트를 고정하고 초기 pixel difference 기준 1% 이하로 시작한다. 렌더링 노이즈 보정은 실제 baseline에서 확정하며 실패를 없애기 위해 무분별하게 임계값을 늘리지 않는다.
5. Windows 대 macOS 이미지는 픽셀 오차율만으로 합격시키지 않는다. 정보 구조, 조작 가능성, 크기, 정렬, 상태, 원본 차이를 사람 검토와 함께 판정한다.
6. 접근성은 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1을 프로젝트 목표로 삼고 선택·오류를 색만으로 구분하지 않는다.

캡처 파일명: `<ui-id>_<state>_<theme>_<locale>_<size>_<scale>.png`. 테스트 보고서에는 source SHA, app SHA, macOS build, fixture version을 함께 기록한다.

전체 AppKit 기능 회귀의 프로세스 제한은 여러 화면·검색·압축·탭 전환을 합친 실행 예산이다. `verify-ui.sh --timeout-seconds`로 30~900초 범위에서 명시하며 macOS 15 CI는 Apple Silicon 180초, Intel 600초다. 이 값으로 아래 성능 목표나 각 기능의 대기 제한을 완화하지 않는다. 검증 스크립트가 요구하는 모든 전체 검사와 최종 완료 기록이 일치해야 성공이며, 시간 초과 시 중간 `progress.json`과 프로세스 스택을 보존한다.

## 5. 성능 예산

아래는 제안된 개발 목표이며 현재 측정 결과가 아니다. M0에서 기준 장비(최소 16GB RAM·로컬 SSD), release build, 데이터 분포를 고정한다. 네트워크와 클라우드 다운로드 시간은 로컬 성능과 분리한다.

| 지표 | 초기 목표 | 측정 방법 |
|---|---:|---|
| 콜드 시작→상호작용 | p95 ≤ 2초 | 캐시 조건 정의, 20회 |
| 로컬 10,000항목 첫 표시 | p95 ≤ 500ms | 첫 100개 표시 시점, 썸네일 제외 |
| 로컬 10,000항목 전체 열거 | p95 ≤ 2초 | 기본 metadata만, 실제 저장장치 기록 |
| 100,000항목 첫 표시 | p95 ≤ 1초 | 전체 완료와 구분, 진행 표시 |
| 보이는 행 스크롤 | 60Hz 화면에서 16.7ms frame budget 목표 | Instruments, hitch 비율 별도 기록 |
| 주요 조작 반응 | p95 ≤ 100ms | 입력→피드백; I/O 완료 시간과 구분 |
| 취소 클릭→상태 반영 | ≤ 100ms | I/O 종료 완료는 별도 측정 |
| 유휴 메모리 | ≤ 200MB 목표 | 기본 창 1개, 5분 안정화 |
| 10,000항목 탐색 | ≤ 500MB 목표 | 캐시 포함, 반복 후 plateau 확인 |
| 로컬 대용량 복사 | 기준 native copy 대비 ≥ 80% 목표 | 동일 보존·검증 정책에서 비교 |

썸네일·해시·Git 상태는 지연 로딩하고 가시 영역을 우선한다. 폴더 총 크기를 목록 표시 전에 재귀 계산하지 않는다. 100,000항목에서도 전체 view를 한 번에 생성하지 않는다. provider 감시는 사용 중인 위치를 중심으로 공유하고 닫은 탭의 작업을 해제한다.

장시간 QA 실행의 소스와 후보 앱 소스를 대조하고, [Mach-O 빌드 대조](verification/m7/INCREMENT_182.md)에서 CPU별 플랫폼·최소 OS·SDK 값을 확인한다.

8시간 연속 탐색·전송·탭 열기/닫기 시험에서 crash, 지속적인 메모리 증가, watcher/task 누수가 없어야 한다. 성능 목표를 못 맞추면 원인과 측정 증거를 기록하고 정식 출시 전에 해결하거나 명시적인 목표 변경 결정을 남긴다.

## 6. CI와 증거 저장

- 인벤토리 변경: [고정 SHA·분류·근거 경로 구조 감사](verification/m7/INCREMENT_176.md). 적용 항목의 실제 동작 검증률은 별도 게이트로 판정한다.
- 변경별: [macOS CI](verification/m7/INCREMENT_172.md)에서 arm64·x86_64 Swift 빌드와 단위·임시 파일 시스템 통합 테스트.
- UI 변경: macOS UI 자동화와 스냅샷, 실제 창 수동 검토.
- provider 변경: capability별 계약 테스트와 오류 주입.
- 릴리스 후보: 지원 환경 전체 회귀, 교차 볼륨, 네트워크, 성능, 장시간 시험.

향후 증거 위치: `docs/verification/<version>/` 아래 `coverage.csv`, `test-report.md`, `performance.json`, `ui/`, `platform-differences.md`, `release-checklist.md`. 실제 실행 전 빈 성공 보고서를 만들지 않는다. 실환경을 설정하지 않아 건너뛴 시험은 통과 건수에서 제외한다.

coverage 지표를 분리한다.

- 목록 대응률 = 분류·대응 결정이 있는 원본 항목 / 원본 전체 항목.
- 적용 기능 검증률 = 검증 통과 E/A 항목 / 전체 E/A 항목.
- 플랫폼 차이 개수 = X 및 미해결 V 항목 수. 이를 분모에서 숨기지 않는다.

M1~M5 실행 가능 버전은 개발 프리뷰다. 완전 구현 목표의 완료 판정은 이 체크리스트와 대응표를 함께 통과한 뒤에만 한다.

[독립 APFS Spotlight 검증](verification/m7/INCREMENT_299.md)은 원본 SHA를 유지한 실제 콘텐츠 검색과 범위 검사를 수행한다. 로컬 네이티브 4개·전체 UI 네 조합 각각 283개, 소유권 보호 10개와 읽기 전용 최종 정리가 통과했다. 두 CPU 원격 결과와 실제 접근성·정식 서명 수용은 별도로 판정한다.

[수신 정리 기록 재조회](verification/m7/INCREMENT_300.md)는 디스크에 남은 정리 기록과 실제 폴더 identity·수신 receipt를 대조해 보관 위치를 표시한다. 손상·이전 형식·이동 위치 미기록은 자동 이동·삭제 없이 보존한다. 별도 프로세스 재기동·명시적 복원·재시도·실제 접근성 수용은 후속 검증·개발로 남는다.

[실제 프로세스 중단·재기동 검증](verification/m7/INCREMENT_301.md)은 휴지통 이동 후 위치 기록 전의 SIGKILL과 다른 FilesMac PID를 확인했다. 네 조합 각각 14개가 통과했고 위치 미확인 작업에도 새 기록의 수신 파일명을 표시한다. 다른 저장 단계·명시적 복원·실제 접근성 및 정식 배포 수용은 남는다.

[보관소로 복원](verification/m7/INCREMENT_302.md)은 저장된 부모·원본 identity와 전체 트리·receipt 검증을 통과한 보관본만 no-overwrite rename으로 되돌린다. 원본 정리 기록을 유지하고 복원 의도·결과를 별도 불변 파일에 기록한다. 게시 후 변경·취소·기록 오류는 실제 보관 위치를 남기고 완료로 표시하지 않는다. 위치 기록 후 실제 프로세스 중단·설치·접근성·최신 두 CPU 수용은 후속 판정한다.

[메타데이터 조회 실행 분리](verification/m7/INCREMENT_303.md)는 동기 I/O가 Swift 협력 실행기를 막지 않도록 하고 취소·완료를 한 번만 반환한다. 원격·초기 검색은 즉시 UI 피드백과 실제 요청 완료를 구분하며 고정 sleep으로 완료를 추정하지 않는다. 폴더의 기존 5초 대기·전체 UI 283개·성능 목표는 유지한다. 시험 이미지 busy 재시도는 소유권·현재 장치·UUID·원본 내용을 매번 재검증하고 강제 해제하지 않는다. Intel 후속 수용과 성능 목표 달성은 별도로 판정한다.

[이동 위치 기록 후 재기동 복원](verification/m7/INCREMENT_304.md)은 실제 `movedToTrash` 기록 직후 QA 자식을 SIGKILL하고 다른 앱 PID의 복원 동작으로 보관소에 되돌린다. 네 언어·외형 조합 각각 19개, 위치 미기록 회귀 14개, 기존 수신 계약 53개와 Swift 성공 304개·건너뜀 18개를 확인했다. 원본 기록·수신 내용·게시 복사본을 보존하며 Release에는 종료 지점 진입을 포함하지 않는다. 최신 두 CPU·장시간·실제 접근성·정식 서명 수용은 진행 중이다.

[최신 후보 장시간·원본 전송 상태 수집](verification/m7/INCREMENT_305.md)은 `5284cb3`의 별도 8시간 실행과 두 CPU 전체 검증을 시작하고 Windows 전송 중·취소 화면 수집 경로를 추가했다. 로컬 보호 시험 5개가 통과했으며 원격 실행·최종 장시간 결과는 진행 중이다.
