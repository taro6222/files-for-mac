# 기능 대응 및 개발 계획

작성일 2026-09-09. 2026-11-26 현재 M7 출시 검증을 진행한다. 원본 대응 및 단계별 미검증 항목은 [개발 현황](DEVELOPMENT_STATUS.md)과 [출시 검증 현황](verification/m7/RELEASE_GATES.md)에서 추적한다.

## 1. 추적 원칙

이 문서는 기능군 수준의 초기 대응표다. 원본의 모든 개별 명령·설정에 대한 전수 목록이 완성되었다고 주장하지 않는다. M0에서 개별 항목으로 확장하는 작업을 필수 완료 조건으로 둔다. 기본 기능만 개발한 후 나머지를 '추후 고려'로 바꾸지 않는다.

분류: `E`는 같은 사용자 기능 구현, `A`는 macOS에 맞춘 대응, `V`는 API/원본 동작 실험 후 확정, `X`는 Windows 고유 의미로 동일 제공 불가다. `X`도 목록에서 삭제하지 않는다. E/A는 목표 분류이며 현재 구현 상태가 아니다.

출처 약어:

- [S1 원본 저장소](https://github.com/files-community/Files)
- [S2 공식 기능 소개](https://files.community/)
- [S3 명령 팔레트 및 명령 목록](https://files.community/docs/features/command-palette)
- [S4 보기 선택](https://files.community/docs/features/layout-picker)
- [S5 분할 보기](https://files.community/docs/features/dual-pane)
- [S6 외형 설정](https://files.community/docs/customize-settings/appearance)

표의 상세 내용은 맥 구현 목표다. 출처는 기능군의 존재를 뒷받침하며 세부 구현·기본값을 모두 보증하지 않는다. 추가 설계 기능은 별도 표기한다.

## 3. Windows 고유 기능의 처리

| 원본 개념 | macOS 대응 결정 | 판정과 주의 |
|---|---|---|
| Explorer 기본 대체·COM 셸 확장 | 별도 파일 관리자 + Finder 위치 표시·공유·열기 | X/A: Finder 전체 또는 시스템 파일 대화상자 대체를 보장하지 않음 |
| QuickLook/SeerPro 외부 앱 | macOS Quick Look | A: 지원 포맷은 설치된 확장과 OS에 따라 검증 |
| Mica/Acrylic | AppKit material 및 테마 토큰 | A: Windows 렌더링과 픽셀 일치는 제외 영역으로 명시 |
| Windows 바로가기 | Finder alias 또는 symlink를 별도 명령으로 제공 | A: `.lnk` 의미와 동일하다고 하지 않음 |
| NTFS ADS | xattr 정보는 별도 제공 가능 | X: ADS를 xattr로 임의 변환하지 않음 |
| 시작 메뉴 고정 | 앱 사이드바 즐겨찾기 | A: OS 전역 고정과 차이를 남김 |
| 드라이브 포맷·Storage Sense | Disk Utility·시스템 저장 공간 도구로 연결 | A: 앱에서 무분별한 직접 포맷 구현 금지 |
| 관리자/다른 사용자 실행 | 필요한 시스템 앱·인증 흐름 검토 | V/X: 일반 앱 root 실행을 동등 기능으로 채택하지 않음 |
| PowerShell·Notepad | 사용자 지정 터미널·편집기 연결 | A: 설치된 PowerShell 선택은 별도 검증 |
| INF 설치 | 해당 없음 | X: Windows 드라이버 설치 의미를 숨기지 않음 |
| 폰트·인증서 설치 | Font Book·Keychain Access 등 시스템 앱 열기 | A/V: 공개 API와 파일 타입 검증 |
| 잠금 화면 슬라이드쇼 | 공개 macOS 지원 범위 조사 | V/X: 비공개 설정 변경을 사용하지 않음 |
| 휴지통 전체 목록·원래 위치·모두 복원 | 공개 API 실험 후 확정 | V: 앱 자체 저널 복원만으로 전체 대응 완료 처리 금지 |
| 클라우드 공급자 전용 셸 명령 | 공급자 공개 기능 또는 앱 열기 | V: 동작 없는 버튼을 노출하지 않음 |

완전성은 무조건 동일 기능이 있다고 주장하는 것이 아니라, 원본의 모든 항목을 대조해 차이를 남기지 않고 결정하는 것으로 관리한다. 위 X/V 항목이 사용자가 원하는 필수 경험을 충족하지 못하면 해당 버전은 완전 대응 출시로 승인하지 않는다.

## 4. M0 원본 전수 조사 절차

1. 최신 안정 릴리스와 main을 조회하고 비교 대상을 하나 고정한다. 릴리스 tag, commit SHA, Windows 빌드 번호, 문서 열람일을 `docs/reference/BASELINE.md`에 기록한다.
2. 고정 소스의 화면·ViewModel·명령 등록·설정 정의·리소스·메뉴를 검색한다. 경로와 줄 번호는 실제 확인된 값만 기록한다.
3. `docs/reference/COMMANDS.csv`에 원본 명령당 한 행을 작성한다: `source_id,label,source_path,source_sha,context,mac_command_id,classification,milestone,status,test_id,evidence,reason`.
4. `SETTINGS.csv`에는 키·유형·기본값·허용 값·저장 범위·의존 조건·맥 대응 키·테스트를 기록한다. `SCREENS.csv`에는 화면·상태·진입 동작·참조 이미지·검증 케이스를 기록한다.
5. Windows 기준 환경에서 홈, 5개 보기, 두 분할 방향, 모든 메뉴·설정·팝업을 촬영하고 사용자 흐름을 기록한다. 소스만으로 hover·타이밍·포커스가 검증되었다고 하지 않는다.
6. 같은 fixture를 맥 테스트에서 사용한다. 창 크기, 스케일, 테마, 언어, 선택 파일과 정렬을 고정한다.
7. 각 항목을 E/A/V/X로 분류하고 기능 F01~F40 또는 신규 ID에 연결한다. 전수 조사에서 새 기능이 나오면 범위를 확장한다.
8. API feasibility spike: 전체 휴지통 복원, 클라우드 metadata, 압축 backend, 로컬 메타데이터 보존, Intel 빌드, 폴더 감시, Git backend를 작은 실험으로 검증한다.
9. API 제약과 UI 차이는 `docs/reference/PLATFORM_DIFFERENCES.md`에 근거·대안·수용 여부를 기록한다.

Windows 실행 환경이 없으면 소스 조사와 맥 실험을 진행하되 시각 원본 검증은 '대기'로 유지한다. M0 일부 작업이 대기여도 독립 개발은 가능하지만 원본 완전 대응 판정은 차단한다.

| M7 출시 | 성능·장시간·서명·공증·설치·업데이트·복구 | DMG·릴리스 노트·검증 보고서 | VALIDATION_AND_RELEASE의 출시 게이트 전부 통과 |

기본 의존 순서: M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7. 2026-09-09 사용자 지시에 따라 M1 환경별 검증을 별도 추적하고 M2 실제 복사 구현에 착수했다. M1/M2 전체 완료 판정은 유지된 수용 기준을 따른다. 접근성·단위 테스트·파일 무결성 검증은 각 단계에 포함한다. M0에서 외부 API 제약을 미리 실험해 M5에서 핵심 구조를 다시 작성하는 위험을 줄인다.

정확한 기간은 원본 전수 목록과 개발 인력, Windows/Intel 장비, 인증서 준비가 확인되기 전에는 확정하지 않는다. M0 종료 후 기능별 작업량·불확실성·담당·선행 조건을 산정한다. 범위 전체를 짧은 UI 시제품 일정으로 약속하지 않는다.

## 6. 변경 관리

기능 상태는 `planned → implementing → implemented → verified`를 사용한다. `blocked`, `platform-adapted`, `not-applicable`은 이유와 증거가 필요하다. implemented는 빌드 가능한 코드가 있다는 뜻이고 verified만 완료로 집계한다.

PR 또는 변경 단위에는 기능 ID, 바뀐 동작, 테스트 결과, UI 캡처, 데이터 손상 위험과 잔여 차이를 포함한다. 원본 버전 업데이트는 새로운 비교 작업으로 처리하며 개발 도중 기준을 조용히 바꾸지 않는다.

[독립 APFS Spotlight 검증](verification/m7/INCREMENT_299.md)은 원본 SHA를 유지한 실제 콘텐츠 검색과 범위 검사를 수행한다. 로컬 네이티브 4개·전체 UI 네 조합 각각 283개, 소유권 보호 10개와 읽기 전용 최종 정리가 통과했다. 두 CPU 원격 결과와 실제 접근성·정식 서명 수용은 별도로 판정한다.

[수신 정리 기록 재조회](verification/m7/INCREMENT_300.md)는 디스크에 남은 정리 기록과 실제 폴더 identity·수신 receipt를 대조해 보관 위치를 표시한다. 손상·이전 형식·이동 위치 미기록은 자동 이동·삭제 없이 보존한다. 별도 프로세스 재기동·명시적 복원·재시도·실제 접근성 수용은 후속 검증·개발로 남는다.

[실제 프로세스 중단·재기동 검증](verification/m7/INCREMENT_301.md)은 휴지통 이동 후 위치 기록 전의 SIGKILL과 다른 FilesMac PID를 확인했다. 네 조합 각각 14개가 통과했고 위치 미확인 작업에도 새 기록의 수신 파일명을 표시한다. 다른 저장 단계·명시적 복원·실제 접근성 및 정식 배포 수용은 남는다.

[보관소로 복원](verification/m7/INCREMENT_302.md)은 저장된 부모·원본 identity와 전체 트리·receipt 검증을 통과한 보관본만 no-overwrite rename으로 되돌린다. 원본 정리 기록을 유지하고 복원 의도·결과를 별도 불변 파일에 기록한다. 게시 후 변경·취소·기록 오류는 실제 보관 위치를 남기고 완료로 표시하지 않는다. 위치 기록 후 실제 프로세스 중단·설치·접근성·최신 두 CPU 수용은 후속 판정한다.

[메타데이터 조회 실행 분리](verification/m7/INCREMENT_303.md)는 동기 I/O가 Swift 협력 실행기를 막지 않도록 하고 취소·완료를 한 번만 반환한다. 원격·초기 검색은 즉시 UI 피드백과 실제 요청 완료를 구분하며 고정 sleep으로 완료를 추정하지 않는다. 폴더의 기존 5초 대기·전체 UI 283개·성능 목표는 유지한다. 시험 이미지 busy 재시도는 소유권·현재 장치·UUID·원본 내용을 매번 재검증하고 강제 해제하지 않는다. Intel 후속 수용과 성능 목표 달성은 별도로 판정한다.

[이동 위치 기록 후 재기동 복원](verification/m7/INCREMENT_304.md)은 실제 `movedToTrash` 기록 직후 QA 자식을 SIGKILL하고 다른 앱 PID의 복원 동작으로 보관소에 되돌린다. 네 언어·외형 조합 각각 19개, 위치 미기록 회귀 14개, 기존 수신 계약 53개와 Swift 성공 304개·건너뜀 18개를 확인했다. 원본 기록·수신 내용·게시 복사본을 보존하며 Release에는 종료 지점 진입을 포함하지 않는다. 최신 두 CPU·장시간·실제 접근성·정식 서명 수용은 진행 중이다.

[최신 후보 장시간·원본 전송 상태 수집](verification/m7/INCREMENT_305.md)은 `5284cb3`의 별도 8시간 실행과 두 CPU 전체 검증을 시작하고 Windows 전송 중·취소 화면 수집 경로를 추가했다. 로컬 보호 시험 5개가 통과했으며 원격 실행·최종 장시간 결과는 진행 중이다.

[원본 입력 초점 보호·이름 변경 수집](verification/m7/INCREMENT_306.md)은 Windows 전송 수집의 주소 입력 실패를 보존하고 실제 초점 확인과 행 선택 탐색으로 보완한다. UI-12의 빈 이름·오류·정상·취소 상태 수집과 로컬 보호 시험 10개를 추가했다. 수정 후 원격 결과는 진행 중이며 수집 준비를 UI 수용 완료로 집계하지 않는다.

[두 CPU 최적화 성능 기준 실행](verification/m7/INCREMENT_307.md)은 기존 최적화 QA의 10,000항목 20개 프로세스 측정을 연결하고 원본 표본·요약·소스·CPU를 재검증한다. 500ms 첫 표시와 2초 모델 열거 기준을 유지한다. 보호 시험 6개·YAML 구문 검사를 통과했으며 실제 성능 결과와 정식 배포 수용은 진행 중이다.

[일괄 이름 입력 안내·실제 원본 상태](verification/m7/INCREMENT_308.md)는 빈 입력으로 시트가 닫히던 동작을 수정하고 모드별 오류 안내·미리보기 활성 조건을 연결했다. 로컬 네 조합의 파일 작업 UI 각각 78개와 전체 UI 각각 283개가 통과했다. Windows 실제 전송·취소 및 이름 입력·취소도 확인했다. 기존 소스의 두 CPU 전체 CI는 성공했으나 최적화 전체 열거 p95는 2초 기준에 미달했다. 새 입력 구성요소의 원격 수용과 전체 M7 완료는 진행 중이다.

[태그 보존 메타데이터 조회](verification/m7/INCREMENT_309.md)는 URL 순회와 태그 prefetch를 유지하고 나머지 조회를 묶음당 최대 네 작업으로 처리한다. 메타데이터·배치·취소 시험을 포함한 Swift 성공 307개·건너뜀 18개, 제한 실행기 10개, 네 조합의 파일 작업 UI 각각 78개·전체 UI 각각 283개를 통과했다. 2초 p95 기준은 유지하며 새 원격 최적화 결과와 M7 완료는 진행 중이다.

[최적화 표본·원격 실패 대조](verification/m7/INCREMENT_310.md)는 `4a19117`의 로컬 1만 항목 20회 p95 기준 통과와 `2899ed2` Intel의 자동 폴더 크기 실패를 분리한다. 기존 5초 대기와 성능 기준을 유지하며 두 CPU 후속 결과·장시간·정식 배포 수용은 진행 중이다.

[복사 중 논리 바이트](verification/m7/INCREMENT_311.md)는 네이티브 콜백의 데이터 포크 바이트를 현재 원본 파일·폴더별로 합산한다. 클론·희소 파일을 보존하고 임시 복사·내용/메타데이터 검증·비덮어쓰기 게시·Undo를 유지한다. 늦은 UI 알림은 이전 단계로 되돌리지 않는다. 이동·병합·여러 원본 전체의 진행률, 실제 접근성·원격·정식 배포 수용은 진행 중이다.

[교차 볼륨 이동 바이트 표시](verification/m7/INCREMENT_312.md)는 임시 복사에 네이티브 콜백을 연결하고 기존 검증·게시·원본 재검증 후 삭제·Undo를 유지한다. 실제 볼륨 7개·네 조합 파일 작업 UI 각각 79개와 Swift 성공 319개·건너뜀 18개를 확인했다. 이전 기준 소스의 8시간은 정상 종료했지만 물리 메모리 중앙값이 계속 증가해 안정성 기준은 미통과다. 새 백엔드의 장시간·SMB·접근성·정식 배포 수용은 남아 있다.

[최근 기록 행 재사용](verification/m7/INCREMENT_313.md)은 위치·파일 행의 URL·메뉴·접근성 레이블을 갱신하고 초점을 불변 값으로 복원한다. 같은 35사이클의 관찰 컨텍스트 증가가 490→175개로 감소했지만 잔여 증가와 최신 8시간 안정성은 미완료다. 원격 태그 CI 실패는 이 UI 수정과 별도로 추적한다.

[저장 Finder 태그 읽기](verification/m7/INCREMENT_314.md)는 정상 저장 plist를 목록·검색·속성·편집 스냅샷에 우선 적용하고 알 수 없는 저장 형식은 기존 공급자 값으로 대체한다. Swift 성공 324개·건너뜀 18개, 실제 볼륨 7개·제한 실행기 10개와 네 조합 UI 각각 79개·283개를 통과했다. 두 CPU 원격 태그 수용은 별도 실행 중이다.

[네이티브 탭 잔여 증가 분리](verification/m7/INCREMENT_315.md)는 명시적 탭 분리와 최초 탭 막대 표시 요청이 컨텍스트 5개/사이클 증가를 줄이지 못함을 확인했다. 독립 창 대조의 중간 힙은 유지됐으나 최종 로딩 대기 실패를 보존한다. 제품 수정·메모리 안정성 통과로 집계하지 않는다. `740ebf4`의 두 CPU Swift 시험·두 Xcode 빌드는 성공했고 전체 CI는 진행 중이다.
