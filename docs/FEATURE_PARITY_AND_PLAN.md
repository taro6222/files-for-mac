# 기능 대응 및 개발 계획

작성일: 2026-09-09 · 상태: M0/M1 진행 중 — 상세 현황은 [개발 현황](DEVELOPMENT_STATUS.md) 참조

## 1. 추적 원칙

이 문서는 기능군 수준의 초기 대응표다. 원본의 모든 개별 명령·설정에 대한 전수 목록이 완성되었다고 주장하지 않는다. M0에서 개별 항목으로 확장하는 작업을 필수 완료 조건으로 둔다. 기본 기능만 개발한 후 나머지를 '추후 고려'로 바꾸지 않는다.

분류: `E`는 같은 사용자 기능 구현, `A`는 macOS에 맞춘 대응, `V`는 API/원본 동작 실험 후 확정, `X`는 Windows 고유 의미로 동일 제공 불가다. `X`도 목록에서 삭제하지 않는다. E/A는 목표 분류이며 현재 구현 상태가 아니다.

출처 약어:

- [S1 원본 저장소](https://github.com/files-community/Files)
- [S2 공식 기능 소개](https://files.community/)
- [S3 명령 팔레트 및 명령 목록](https://files.community/docs/features/command-palette)
- [S4 보기 선택](https://files.community/docs/features/layout-picker)
- [S5 분할 보기](https://files.community/docs/features/dual-pane)
- [S6 외형 설정](https://files.community/docs/customize-settings/appearance)
- [S7 Git](https://files.community/docs/features/git)
- [S8 FTP](https://files.community/docs/features/ftp)
- [S9 Omnibar](https://files.community/docs/features/omnibar)

표의 상세 내용은 맥 구현 목표다. 출처는 기능군의 존재를 뒷받침하며 세부 구현·기본값을 모두 보증하지 않는다. 추가 설계 기능은 별도 표기한다.

## 3. Windows 고유 기능의 처리

| 원본 개념 | macOS 대응 결정 | 판정과 주의 |
|---|---|---|
| Explorer 기본 대체·COM 셸 확장 | 별도 파일 관리자 + Finder 위치 표시·공유·열기 | X/A: Finder 전체 또는 시스템 파일 대화상자 대체를 보장하지 않음 |
| QuickLook/SeerPro 외부 앱 | macOS Quick Look | A: 지원 포맷은 설치된 확장과 OS에 따라 검증 |
| Mica/Acrylic | AppKit material 및 테마 토큰 | A: Windows 렌더링과 픽셀 일치는 제외 영역으로 명시 |
| Windows 바로가기 | Finder alias 또는 symlink를 별도 명령으로 제공 | A: `.lnk` 의미와 동일하다고 하지 않음 |
| NTFS ADS | xattr 정보는 별도 제공 가능 | X: ADS를 xattr로 임의 변환하지 않음 |
| 시작 메뉴 고정 | 앱 사이드바 즐겨찾기 | A: OS 전역 고정과 차이를 남김 |
| 드라이브 포맷·Storage Sense | Disk Utility·시스템 저장 공간 도구로 연결 | A: 앱에서 무분별한 직접 포맷 구현 금지 |
| 관리자/다른 사용자 실행 | 필요한 시스템 앱·인증 흐름 검토 | V/X: 일반 앱 root 실행을 동등 기능으로 채택하지 않음 |
| PowerShell·Notepad | 사용자 지정 터미널·편집기 연결 | A: 설치된 PowerShell 선택은 별도 검증 |
| INF 설치 | 해당 없음 | X: Windows 드라이버 설치 의미를 숨기지 않음 |
| 폰트·인증서 설치 | Font Book·Keychain Access 등 시스템 앱 열기 | A/V: 공개 API와 파일 타입 검증 |
| 잠금 화면 슬라이드쇼 | 공개 macOS 지원 범위 조사 | V/X: 비공개 설정 변경을 사용하지 않음 |
| 휴지통 전체 목록·원래 위치·모두 복원 | 공개 API 실험 후 확정 | V: 앱 자체 저널 복원만으로 전체 대응 완료 처리 금지 |
| 클라우드 공급자 전용 셸 명령 | 공급자 공개 기능 또는 앱 열기 | V: 동작 없는 버튼을 노출하지 않음 |

완전성은 무조건 동일 기능이 있다고 주장하는 것이 아니라, 원본의 모든 항목을 대조해 차이를 남기지 않고 결정하는 것으로 관리한다. 위 X/V 항목이 사용자가 원하는 필수 경험을 충족하지 못하면 해당 버전은 완전 대응 출시로 승인하지 않는다.

## 4. M0 원본 전수 조사 절차

1. 최신 안정 릴리스와 main을 조회하고 비교 대상을 하나 고정한다. 릴리스 tag, commit SHA, Windows 빌드 번호, 문서 열람일을 `docs/reference/BASELINE.md`에 기록한다.
2. 고정 소스의 화면·ViewModel·명령 등록·설정 정의·리소스·메뉴를 검색한다. 경로와 줄 번호는 실제 확인된 값만 기록한다.
3. `docs/reference/COMMANDS.csv`에 원본 명령당 한 행을 작성한다: `source_id,label,source_path,source_sha,context,mac_command_id,classification,milestone,status,test_id,evidence,reason`.
4. `SETTINGS.csv`에는 키·유형·기본값·허용 값·저장 범위·의존 조건·맥 대응 키·테스트를 기록한다. `SCREENS.csv`에는 화면·상태·진입 동작·참조 이미지·검증 케이스를 기록한다.
5. Windows 기준 환경에서 홈, 5개 보기, 두 분할 방향, 모든 메뉴·설정·팝업을 촬영하고 사용자 흐름을 기록한다. 소스만으로 hover·타이밍·포커스가 검증되었다고 하지 않는다.
6. 같은 fixture를 맥 테스트에서 사용한다. 창 크기, 스케일, 테마, 언어, 선택 파일과 정렬을 고정한다.
7. 각 항목을 E/A/V/X로 분류하고 기능 F01~F40 또는 신규 ID에 연결한다. 전수 조사에서 새 기능이 나오면 범위를 확장한다.
8. API feasibility spike: 전체 휴지통 복원, 클라우드 metadata, 압축 backend, 로컬 메타데이터 보존, Intel 빌드, 폴더 감시, Git backend를 작은 실험으로 검증한다.
9. API 제약과 UI 차이는 `docs/reference/PLATFORM_DIFFERENCES.md`에 근거·대안·수용 여부를 기록한다.

Windows 실행 환경이 없으면 소스 조사와 맥 실험을 진행하되 시각 원본 검증은 '대기'로 유지한다. M0 일부 작업이 대기여도 독립 개발은 가능하지만 원본 완전 대응 판정은 차단한다.

의존 순서: M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7. 접근성·단위 테스트·파일 무결성 검증은 각 단계에 포함한다. M0에서 외부 API 제약을 미리 실험해 M5에서 핵심 구조를 다시 작성하는 위험을 줄인다.

정확한 기간은 원본 전수 목록과 개발 인력, Windows/Intel 장비, 인증서 준비가 확인되기 전에는 확정하지 않는다. M0 종료 후 기능별 작업량·불확실성·담당·선행 조건을 산정한다. 범위 전체를 짧은 UI 시제품 일정으로 약속하지 않는다.

## 6. 변경 관리

기능 상태는 `planned → implementing → implemented → verified`를 사용한다. `blocked`, `platform-adapted`, `not-applicable`은 이유와 증거가 필요하다. implemented는 빌드 가능한 코드가 있다는 뜻이고 verified만 완료로 집계한다.

PR 또는 변경 단위에는 기능 ID, 바뀐 동작, 테스트 결과, UI 캡처, 데이터 손상 위험과 잔여 차이를 포함한다. 원본 버전 업데이트는 새로운 비교 작업으로 처리하며 개발 도중 기준을 조용히 바꾸지 않는다.
