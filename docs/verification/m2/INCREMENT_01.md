# M2 첫 개발 단위: 실제 복사

날짜: 2026-09-09. M2 진행 중이며 전체 기능 완료가 아니다.

## 사용 흐름

목록에서 항목 선택 → 파일 메뉴 또는 문맥 메뉴의 **선택 항목 복사…**(⇧⌘C) → 시스템 폴더 선택창의 **여기에 복사** → 복사 창에서 단계·항목 수·결과 확인. 현재 한 작업씩 실행한다. ⌘C/⌘V 파일 클립보드는 다음 구현 범위다.

## 구현과 데이터 보호

- `CopyEngine`: 비동기 실행, 파일·디렉터리·패키지·심볼릭 링크 복사. FIFO 등 특수 파일은 사전 거부한다.
- 원본과 대상의 실제 경로를 비교하여 디렉터리 자신의 하위 위치로 복사하는 요청을 거부한다.
- 대상 내부에 작업별 임시 디렉터리를 만들고, 복사 전 원본·복사 후 출력·복사 후 원본의 트리/일반 파일 SHA-256/POSIX mode/링크 대상을 비교한다. 원본을 변경하거나 삭제하지 않는다.
- `renameatx_np(RENAME_EXCL)`로 최종 이름을 확정한다. 기존 항목 및 확정 직전에 생긴 항목을 덮어쓰지 않는다. 폴더 충돌도 통째로 건너뛴다.
- 대상·임시 디렉터리의 descriptor/identity를 재확인하며, 임시 디렉터리 identity가 바뀌면 자동 삭제를 생략하고 남은 경로를 표시한다.
- 취소 시 이후 항목은 시작하지 않는다. 완료된 결과는 유지하고 현재 임시 출력만 정리한다. 단일 파일의 FileManager 복사 호출 중에는 즉시 중단되지 않으며 호출 반환을 기다린다. 해시 계산은 청크마다 취소를 확인한다.
- 앱 일반 종료는 진행 중 작업이 있으면 보류하고 복사 창에서 취소/완료를 기다리도록 안내한다.
- Application Support의 앱 bundle ID 하위 `operations/<UUID>.json`에 버전 1 저널을 원자적 파일 교체 방식으로 저장한다. 시작 저널 저장 실패 시 복사를 시작하지 않는다. 결과 확정 후 저널 저장 실패는 완료 항목을 실패로 바꾸지 않고 별도 오류로 표시한다.

## 검증

환경: 현재 Apple Silicon macOS 26.6.2, Swift 6.3.3 / Xcode 26.6. 최소 버전·Intel 검증이 아니다.

| 검증 | 결과 |
|---|---|
| Swift Testing | 기존 26 + 신규 복사 7 = 33개 통과 |
| 파일 트리/Unicode/POSIX mode/깨진 심볼릭 링크/완료 저널 | 통과 |
| 기존 깨진 링크 및 확정 직전 대상 생성 경쟁 | 덮어쓰기 없이 충돌 처리 |
| 심볼릭 링크 경유 하위 폴더 대상 | 거부 |
| 두 번째 항목 검증 중 취소 | 첫 결과 유지, 현재 임시 출력 정리, 이후 미실행 |
| 복사 중 원본 내용 변경·일부 원본 누락 | 해당 항목 실패, 나머지 완료, 부분 완료 결과 |
| 시작 저널 경로가 파일인 경우 | 출력 생성 없이 실패 |
| Xcode Debug / Swift release | 빌드 통과 |
| ad-hoc bundle 서명 검증 | 통과 |
| 실제 AppKit UI: 경로 입력 → 다중 선택 → ⇧⌘C → 대상 선택 | 파일+하위 폴더 완료 2/2, 충돌 0 |
| 실제 AppKit UI: 같은 대상에 재실행 | 완료 0/2, 충돌 2 |
| UI 작업 뒤 원본·출력 SHA-256 비교 | 두 파일 일치, 남은 임시 출력 0 |

코어 실행: `CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache" swift test --disable-sandbox -Xswiftc -gnone`.
Xcode 실행: `xcodebuild -project FilesMac.xcodeproj -scheme 'Files macOS' -configuration Debug -derivedDataPath .build/xcode CODE_SIGNING_ALLOWED=NO DEBUG_INFORMATION_FORMAT=dwarf build`.

실제 UI는 독립 bundle ID `org.taro6222.files-for-mac.copy-qa`로 실행했다. 원본/대상 fixture는 `/private/tmp/files-copy-ui-20260909/`, 해시 비교 기록은 무시되는 `build/copy-ui-verification.json`에 있다. 기존 M1의 4조합 UI 전체 검사는 반복하지 않았다. UI 취소·종료 보류의 실제 조작 검증은 아직 하지 않았으며 취소 데이터 처리는 코어 테스트로 검증했다.

## 남은 범위와 제한

- 교체/병합/양쪽 유지, 이동, 삭제, 이름 변경, 파일 클립보드, 실행 취소, 탭·분할은 미구현이다.
- JSON 저널은 첫 실행 기반이다. 설계의 SQLite 저널, 강제 종료 뒤 interrupted 판정·복구 UI·임시 출력 회수, fsync 기반 전원 장애 내구성은 후속 작업이다. 강제 종료 시 임시 출력이 남을 수 있다.
- 진행 막대는 최상위 항목 단위이며 바이트 전송률/남은 시간은 제공하지 않는다. 전체 해시 검증은 대용량 복사 성능에 비용이 있다.
- FileManager의 기본 메타데이터 복사를 사용하지만 xattr/ACL/resource fork/희소 파일/하드 링크 관계 및 모든 볼륨의 보존을 보증하지 않는다. 이번 비교는 내용·mode·링크 대상이다.
- 외부 프로세스의 임의 시점 원본 변경을 고정하는 파일 시스템 스냅샷은 아니다. 악의적 경로 교체 전 구간에 대한 보안 경계나 네트워크/외장 볼륨 내구성 완료를 주장하지 않는다.
- M1 환경 의존 검증은 별도 목록으로 유지하며 M2 개발을 막지 않는다. 이는 반복 검증 대신 핵심 기능으로 진행하라는 사용자 지시에 따른 우선순위 조정이다.
