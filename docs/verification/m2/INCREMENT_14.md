# M2 열네 번째 개발 단위: 네이티브 탭 기반

작성일: 2026-11-13

## 구현 내용

- AppKit의 `NSWindow` 탭 그룹을 사용해 macOS 네이티브 탭 표시·순서 변경·창 분리 기반을 연결했다.
- 파일 메뉴에 새 탭(`⌘T`), 탭 복제(`⇧⌘D`), 닫은 탭 다시 열기(`⇧⌘T`)를 추가했다.
- 각 탭은 별도의 `BrowserWindow`와 `BrowserModel`을 가져 탐색 위치·히스토리·선택·폴더 감시 작업이 다른 탭과 섞이지 않는다.
- 탭 복제는 현재 탭의 위치를 새 탭에서 연다.
- 표준 닫기(`⌘W`)로 닫힌 탭 또는 창의 마지막 위치를 최대 20개까지 LIFO 스택에 보관한다.
- 마지막 창을 닫아도 앱과 메뉴를 유지해 해당 창의 위치를 다시 열 수 있다.
- 닫은 탭이 없을 때 복원 메뉴가 비활성화되며, 홈 탭의 `nil` 위치도 정상 스냅샷으로 복원한다.
- `ClosedTabHistory`를 UI와 분리해 복원 순서와 보관 한도를 단위 테스트할 수 있게 했다.

## 검증

- `DEVELOPER_DIR=/Library/Developer/CommandLineTools CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache" SWIFT_TMPDIR=/tmp swift test`
- Swift Testing 62개 통과
- `FilesCore`, `FilesCoreTests`, `FilesMac` 빌드 통과
- 최근 닫은 탭 우선 복원, 홈 위치 복원, 20개 보관 한도의 코어 테스트 통과
- 기존 복사·이동·삭제·이름 변경·탐색 회귀 테스트 통과

## 제한 및 다음 단계

- 이번 스냅샷은 마지막 위치만 저장한다. 뒤로/앞으로 히스토리, 선택, 스크롤, 열 구성, 보기 설정은 아직 닫은 탭 복원에 포함하지 않는다.
- 닫은 탭 기록은 메모리에만 있어 앱 재실행 뒤에는 유지되지 않는다.
- 네이티브 탭 드래그 순서 변경·창 분리와 키보드 메뉴 동작은 실제 앱 수동 검증이 남아 있다.
- 전체 Xcode 라이선스가 수락되지 않은 환경이라 Command Line Tools로 빌드·테스트했으며, 기존 저널 디코딩 및 도구체인 링크 경고는 남아 있다.
- 다음 단계는 전체 탭 상태 스냅샷·재실행 세션 복원과 분할 보기의 활성 pane 모델이다.
