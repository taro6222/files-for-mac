# M2 열 번째 개발 단위: 교체 백업과 안전 실행 취소

작성일: 2026-09-10

## 구현 내용

- 교체 이동에서 기존 대상을 삭제하지 않고 대상 폴더의 작업별 숨김 백업으로 원자적으로 보존한다.
- 백업 예정 경로와 `backingUp` 상태를 이동 저널에 먼저 기록해 중간 종료 시 복구 단서를 남긴다.
- 이동 실행 취소 레코드에 다음 정보를 추가했다.
  - 이동 결과 identity
  - 교체 전 백업 경로와 identity
  - 교차 볼륨 여부
- 실행 취소 전 이동 결과와 백업을 모두 재검증한다. 어느 한쪽이라도 없거나 외부에서 변경됐으면 파일을 이동하지 않고 이유를 표시한다.
- 교차 볼륨 실행 취소도 임시 복사, SHA-256 검증, 결과 공개, 원본 재검증·삭제 순서로 처리한다.
- 교체 실행 취소가 성공하면 새 항목을 원래 소스 위치로 복원하고 백업을 대상 이름으로 되돌린다.
- 일부 실행 취소가 실패하면 완료 항목은 레코드에서 제거하고 실패 항목과 백업은 재시도를 위해 보존한다. 전체 성공 시 레코드를 소비 상태로 전환한다.

## 검증

- `SWIFT_TMPDIR=/tmp swift test`
- Swift Testing 55개 통과, `FilesMac` 앱 타깃 빌드 통과
- 동일 볼륨 교체 후 새 항목과 기존 대상 양쪽 복원
- 교차 볼륨 교체 후 검증된 역방향 이동과 양쪽 복원
- 교체 백업을 외부에서 수정했을 때 실행 취소 거부, 새 대상·변경 백업 보존, 재시도 레코드 유지
- 일반 이동 실행 취소 및 외부 변경 보호 회귀 테스트 통과

## 제한 및 다음 단계

- 백업은 실행 취소 성공 시 소진된다. 실패한 백업은 자동 삭제하지 않으며 재시도 레코드와 함께 남긴다.
- 장기간 실행 취소하지 않은 백업의 사용자 확인형 정리 정책은 설정·작업 기록 UI와 함께 설계해야 한다.
- 다음 개발 단위는 이동·복사의 취소 전달과 실시간 진행 단계 표시다.
