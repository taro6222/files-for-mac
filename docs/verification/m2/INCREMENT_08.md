# M2 여덟 번째 개발 단위: 안전한 이동 실행 취소

작성일: 2026-09-10

## 구현 내용

- 성공한 `skip` 정책 이동의 원래 위치, 이동 위치, 이동 직후 identity를 별도 실행 취소 레코드로 저장한다.
- 편집 메뉴의 `마지막 이동 실행 취소`(⌘Z)에서 가장 최근 레코드를 원래 위치로 되돌린다.
- 실행 취소 직전에 대상 identity·수정 시각·크기를 다시 확인한다.
  - 이동 후 대상이 수정되거나 없어졌으면 건너뛰고 이유를 표시한다.
  - 원래 위치에 같은 이름의 항목이 생겼거나 원래 상위 폴더가 없어졌으면 덮어쓰거나 폴더를 임의 생성하지 않는다.
- 실행 결과를 `undo-result-<operation-id>.json`에 기록하고 사용한 레코드는 `undo-consumed-<operation-id>.json`으로 전환한다.
- `replace` 정책 이동은 기존 대상을 복구할 백업이 없으므로 안전하지 않은 실행 취소 레코드를 만들지 않는다.

## 검증

- `SWIFT_TMPDIR=/tmp swift test`
- Swift Testing 51개 통과
- 추가 검증:
  - 이동 후 원래 위치와 내용 복원
  - 이동된 파일을 외부에서 수정한 뒤 실행 취소 시 변경 파일 보존 및 `changed` 보고
  - 교체 이동 후 실행 취소 메뉴 후보 미생성
  - 실행 취소 완료 후 레코드 재사용 방지

## 제한 및 다음 단계

- 최근 이동 레코드 한 건을 한 번 실행하는 범위다. 부분 실패한 레코드도 결과 보존 후 소비되며 실패 이유는 결과 대화상자와 저널에 남는다.
- 교체 이동의 실행 취소에는 기존 대상의 별도 백업과 수명 관리가 필요하다.
- 교차 볼륨 이동은 복사·내용 검증·소스 제거 순서로 확장해야 한다.
