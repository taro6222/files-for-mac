# M2 네 번째 개발 단위: 휴지통 이동과 항목별 결과 표시

날짜: 2026-09-10. M2 진행 중.

## 구현 내용

- `EntryOperations.moveToTrash(_:)`를 추가해 항목 배열을 받아 파일/폴더/심볼릭 링크를 `FileManager.trashItem(at:resultingItemURL:)`로 이동한다.
- 휴지통 이동은 시작 전 먼저 `entry-trash-<UUID>.json` 기록을 남기고, 각 항목 상태(완료/실패/미탐색)를 갱신해 쓰기 오류나 일부 실패를 남긴다.
- 시작 기록이 실패하면 작업을 시작하지 않는다.
- 앱에서는 파일/문맥 메뉴에 `휴지통으로 이동` 명령을 추가했다.
- 삭제 실행 전 확인 다이얼로그를 띄우고, 완료 후 새 창(`DeletionWindow`)을 통해 항목별 결과(대상 경로, 휴지통 경로, 메시지)를 표시한다.
- 삭제 진행 중에는 메인 종료 가드에서 앱을 즉시 종료하지 않도록 `DeletionWindow.isRunning`을 종료 조건에 반영했다.

## 검증

- 코어 단위 테스트에 휴지통 결과 검증 케이스를 추가했다.
- 기대 케이스: 실제 파일/폴더을 이동해 사라짐 확인, 존재하지 않는 항목은 `notFound` 상태 확인, JSON 저널에 `moveToTrash` 및 최종 `partial` 상태 기록 확인.

현재 통합 UI는 문맥/파일 메뉴 연결 동작, 확인 다이얼로그와 결과창 닫힘 제약을 중심으로 점검 대상으로 등록했고, 단계적으로 실제 창 자동화 UI 케이스(삭제 선택/항목별 실패/성공 표시)는 다음 실행에서 이어서 검증한다.

## 남은 범위

- 영구 삭제, 휴지통 복원(restore), 부분 실해제/취소 재개는 별도 단계.
- 현재는 휴지통 이동 결과를 항목 단위로 표시하되, 삭제 결과를 되돌리는 undo 흐름은 포함하지 않았다.
