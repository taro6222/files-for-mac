# M7 Increment 297 — 동기 목록 조회 실행 분리와 전체 UI 중간 기록

상태: 목록 조회의 실행 분리와 로컬 회귀는 검증했다. Intel의 이전 전체 UI 시간 초과 원인이 해결됐는지는 같은 소스의 원격 전체 실행으로 판정한다. M7 출시 완료로 표시하지 않는다.

`390cdb9`의 Intel 전체 AppKit 네 조합은 각각 프로세스 제한 180초에서 종료됐으며 최종 보고서가 없었다. 35~38개 화면 캡처와 스택이 남았지만 이를 검사 통과로 간주하지 않는다. 스택에는 파일 제공자를 거치는 동기 목록 열거, 정렬·레이아웃·아이콘 처리와 이벤트 대기가 관찰됐다. 한 시점의 표본만으로 교착 또는 특정 기능 실패를 단정할 수 없다. [원본 실행과 네 표본의 해시](full-appkit-390cdb9-intel-timeouts.json).

`LocalFileSystem.batches`의 동기 NSURL 조회·열거를 Swift 협력 실행기의 `Task.detached`에서 GCD 작업으로 옮겼다. 파일 제공자나 마운트된 서버의 동기 응답 대기가 Swift 실행기 스레드를 점유하지 않도록 한다. 기존 메타데이터·첫 128개/후속 1,024개 배치와 스트림 동작을 유지한다. 스레드 안전한 취소 토큰을 첫 조회 전과 배치 루프에서 확인한다. OS의 동기 호출 자체를 강제로 중단한다고 보장하지 않는다.

실제 프로덕션 목록 조회에 시험용 동기 대기를 주입한 신규 두 시험은, 파일 시스템 호출이 기다리는 동안 다른 Swift 작업이 재개되는지와 대기 중 취소 시 첫 배치를 내보내지 않는지를 확인한다. 제한된 Swift 협력 풀을 실제 테스트 호스트에만 적용한 기존 검증에 두 시험을 포함했다. Git 세 시험과 함께 다섯 시험이 통과했다. 이는 실제 외부 File Provider 서버 장애 시험을 대체하지 않는다.

전체 UI 검사에는 각 검사·캡처 단계의 경과 시간과 누적 결과를 원자적으로 저장하는 `progress.json`을 추가했다. 정상 종료 시 완료 상태와 최종 보고서의 283개 결과가 일치해야 한다. 오류·시간 초과 때에도 마지막 단계·완료된 검사·스택을 남긴다. 전체 실행 시간은 진단 지표이며 개별 조작의 성능 측정과 구분한다.

전체 회귀 프로세스 예산은 CLI로 30~900초 범위에서 명시한다. CI의 Apple Silicon은 180초를 유지하고 Intel 진단 실행은 600초로 한다. 검사 수와 개별 기능 대기 제한, 출시 성능 목표를 줄이거나 완화하지 않는다. Intel 예산 안에 전체 검사가 끝나는지 확인한 뒤 실제 단계별 병목을 판정한다. 실행 중간 자료만으로 성공 처리하지 않는다.

로컬 검증에서 앱·테스트 빌드, 전체 Swift 회귀, 제한 실행기 다섯 시험과 임시 디스크 이미지의 마운트 시험 7개가 통과했다. Swift Testing의 최종 집계는 287개 함수로, 성공 보고 269개와 별도 통합 fixture가 필요한 건너뜀 18개를 구분한다. 매개변수 하위 사례 수는 별도로 보존한다. 마운트 시험은 APFS·대소문자 구분 APFS·exFAT·FAT32·HFS+를 실제 마운트하여 실행했다. 같은 최종 앱의 파일 작업 UI는 네 언어·테마 조합에서 각각 79개, 파일 약속 제공·수신·복구 계약은 28개가 통과했다.

macOS 27.2.1의 한국어·영어와 밝음·어두움 네 조합에서 각각 283개 AppKit 검사가 통과했다. 중간 완료 기록과 최종 결과가 일치했고 전체 프로세스의 진단 시간은 약 45~46초였다. 이것을 Intel 시간 초과 해결이나 출시 성능 목표 전체 충족으로 확대 해석하지 않는다. [소스·바이너리 해시와 로컬 결과](directory-scheduling-verification.json).

초기 제한 환경 실행은 시스템 휴지통 시험과 테스트 호스트를 정상 완료하지 못했다. 정상 사용자 세션 접근으로 다시 실행한 결과를 최종 증거로 사용한다. 휴지통 복원 시험은 시스템 서비스가 항목을 반환하지 못하면 빈 배열을 인덱싱해 호스트 전체를 중단하던 사전조건을 `#require`로 검사하도록 보강했다. 서비스 실패를 건너뜀이나 성공으로 바꾸지 않는다.

실제 SDK 드래그 전달·수신 복구 화면 수용·검증된 보관소 정리, 최소 OS와 외부 서비스·VoiceOver, 최신 후보의 장시간 판정 및 준비 중인 Developer ID·공증은 계속 열린 항목이다. 기존 8시간 프로세스는 실제 실행 중임을 확인했으며 같은 실행을 재시작하지 않았다.
