# M7 Increment 110 — Git HTTPS 자격 증명 도우미

Apple Silicon macOS 27.2 (26B123)에서 `92ae7cb`의 Git 제공자를 시험했다. 루프백 TLS 서버는 인증된 요청을 실제 `git-http-backend`에 전달했다. 시험용 인증서를 Git의 CA 설정에 지정하고 TLS 검증을 사용했다. 원격 URL에는 자격 증명을 넣지 않았다.

같은 Swift 수용 시험을 두 환경에서 각각 통과했다. 첫 환경에서는 임시 도우미의 조회·저장·삭제 요청을 확인했다. 두 번째 환경에서는 macOS Git의 `osxkeychain`과 해당 루프백 포트에만 만든 시험용 항목을 사용했다.

- 두 복사본을 clone하고 첫 번째의 새 커밋을 push했다. 두 번째에서 fetch 후 한 커밋 뒤처진 상태를 읽고 fast-forward pull 후 파일 내용을 대조했다.
- 틀린 자격 증명을 반환하거나 서버에서 인증을 거부하자 clone과 fetch가 각각 종료 코드 128로 실패했다. 실패한 clone의 목적지와 스테이징 폴더는 남지 않았고, 기존 복사본의 HEAD·인덱스·파일 내용은 보존됐다.
- 서버가 인증을 거부한 뒤 Git 도우미로 조회해 시험용 Keychain 항목이 사라진 것을 확인했다. 첫 시험에서 시스템 도우미가 저장한 별도 루프백 항목도 정리했다. 서버, 임시 비밀번호와 TLS 개인 키를 정리했다.

검증 대상은 루프백 서버의 HTTPS Basic 인증이다. 외부 호스팅 서비스의 로그인 및 토큰 갱신은 별도 출시 검증 항목이다.
