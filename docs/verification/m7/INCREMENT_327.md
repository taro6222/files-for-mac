# M7 Increment 327 — 창별 탭 세션 복원

상태: 구현·Core·네 조합 AppKit·Debug/Release·이전 배열 형식 호환 검증 통과. 최신 소스 원격·장시간·정식 배포 수용은 미완료다. M7 출시 완료가 아니다.

이전 종료 경로는 탭을 생성 순서대로 저장했고, 재시작은 모두 한 창으로 합쳤다. 따라서 탭을 재정렬하거나 분리한 결과가 재실행 뒤 사라졌다. 이제 실제 BrowserTabs 구성원의 순서를 저장하며 각 창의 선택 탭과 마지막 활성 창을 복원한다. 각 탭의 두 pane·활성 pane·축·비율·탐색 이력·보기 상태는 기존 SplitTabState로 보존한다.

workspaceSessionV2의 평면 배열과 기존 pane 필드를 유지하고 창 그룹 UUID·선택/초점 표시만 추가한다. 이전 버전의 SplitTabState 배열 읽기로 되돌아갈 수 있고, 이전 버전이 다시 저장하면 한 창의 평면 세션으로 읽힌다. 새 읽기는 손상된 탭을 건너뛰되 건강한 창·탭의 순서를 보존한다. 기존 평면 세션은 한 창으로 읽으며, 저장된 원래 인덱스로 선택을 복구한다. 비어 있는 창·잘못된 선택 인덱스·잘못된 선택 표시를 정규화한다.

현대 세션이 명시적으로 비어 있거나 손상됐으면 이전 tabSession을 다시 가져오지 않는다. tabSession 가져오기는 workspaceSessionV2 자체가 없을 때만 수행한다. 모든 탭을 닫은 뒤 과거 탭이 되살아나는 것을 막는다.

실제 앱의 시작/종료 경로는 AppKit 검증에서 사용하는 동일한 snapshot·restore helper에 연결한다. 기존 창을 모두 닫고 저장 데이터를 새 컨트롤러로 복원해 별도 창·탭 순서·선택과 pane/이력 상태를 검사한다. 준비 중인 Developer ID·공증과 실제 포인터/VoiceOver·원본 전체 UI·지원 환경 및 최신 소스 장시간 수용은 계속 별도 항목이다. 이전 76fda96의 장시간 실행은 중단하거나 새 소스 결과로 집계하지 않는다.

예: 생성 순서 A/B/C/D에서 창 1의 탭을 C/A/B로 재정렬하고 B를 선택하며 D를 창 2로 분리한다. 이전 경로는 재실행 뒤 A/B/C/D를 한 창으로 합쳤다. 새 경로는 창 1 C/A/B(선택 B), 창 2 D와 저장된 활성 창 정보를 복원한다. AppKit 검사는 실제 창을 닫고 새 컨트롤러 네 개를 만들어 창 두 개만 보이고 각 그룹의 선택 탭과 저장 pane/이력 상태가 같은지 확인했다. 실제 전역 초점·키보드/VoiceOver 동선은 실사용 수용으로 남긴다.

최종 Swift 385개 중 성공 366개·환경 건너뜀 19개, 제한 실행기 10개, 네 조합 전체 UI 각각 294개, Debug·일반 Release·최적화 QA 빌드, 프로젝트 생성·parity 목록 감사가 통과했다. 새 Core 시험 다섯 개와 AppKit 검사 네 개를 포함한다. [소스·바이너리·검증 보고서 해시와 전체 검사 결과](session-groups-327-verification.json)를 보존한다. 이 세션/UI 단계에서 실제 볼륨 매트릭스와 외부 서비스 시험을 다시 실행하지 않았다.

이전 76fda96의 8시간 실행과 원격 전체 검증은 별도 소스로 추적한다. 새 소스의 원격·최신 8시간·원본 UI 전체 상태·지원 환경·외부 서비스·실제 포인터/접근성·정식 서명/공증 수용은 남아 있다. 인증서·공증 프로필은 사용자 준비 중이다.
