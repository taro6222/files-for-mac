# 385 — 추출 창 수명·암호 입력 요청·실패 정리

7e31fc6의 [45882828053](https://github.com/taro6222/files-for-mac/actions/runs/45882828053) ARM에서는 한국어 두 조합이 각각 369개를 통과했다. 영어 조합은 압축 worker의 세부 값 없는 오류와 암호 prompt 누락/후속 실패가 기록됐다. 기존 `localizedDescription`은 enum 번호만 남겨 원인을 구분할 수 없었다. Intel은 같은 실행을 유지한다.

## 앱 작업 수명

추출 창이 실제 닫히면 해당 task에 취소를 전달한다. 닫힌 창의 작업도 정리가 끝날 때까지 등록 상태를 유지하고 완료 시 task 참조/등록을 정리한다. backend 준비와 목록 읽기 직후 취소를 다시 확인해 닫힌 창에서 후속 암호 입력·추출로 진행하지 않도록 했다. 원본/게시/취소 안전 지점은 기존 Core 경로를 사용한다. 이 변경을 강제 삭제·즉시 rollback으로 설명하지 않는다.

## 암호 시험 요청 추적

기존 시험은 전역의 마지막 weak prompt와 sheetParent만 확인했다. 같은 부모에서 응답을 마친 sheet가 끝나는 동안 이전 요청이 다시 조회될 수 있는 경로가 있었다. DEBUG 도우미를 창별 weak 요청 등록으로 변경하고 제출·취소·응답 즉시 해당 요청을 제외한다. 이전 응답 callback은 자기 요청만 제거해 새 요청을 지우지 않는다. 기존 5초 prompt 기한은 유지한다. 잘못된 암호 재시도 검사에는 이전/다음 prompt가 다른 객체라는 조건을 더했다.

이 구조 수정이 모든 간헐 압축 오류의 원인 해결을 증명하지는 않는다. 실제 암호를 기록하지 않으며 Release의 암호 입력 방식은 바꾸지 않았다.

## 실패 정리와 원인 기록

배치 시험은 새로 생성한 추출 controller를 식별한다. prompt를 못 찾으면 새 작업 여부·진행·상태·오류 case를 기록하고 소유 task를 취소한 뒤 5초 안의 종료 여부를 확인한다. 정리가 끝나지 않으면 실패를 유지하고 중단한다. 이전 작업을 새 작업으로 오인하거나 입력 대기 작업을 남긴 채 후속 검사를 진행하지 않는다. 전체 QA의 오류 종료에서도 소유 추출 작업을 취소·정리한다.

worker의 세부 오류 값, 마지막 QA 단계와 편집 내부의 복사/ZIP 생성·검증/빈 ZIP/빈 7z 생성·삭제·열기 단계를 기록한다. 코드 이름과 fixture 경로만 남기고 password 값은 기록하지 않는다. 기존 오류 전파/성공 조건과 5초·10초 기한을 완화하지 않았다.

원격 UI 정의에 `archiveExtractionCloseCancels` 한 개를 추가해 369→370개다. 프로그램 방식으로 닫은 추출 창이 작업 정지·성공 callback 미호출·출력 폴더 비어 있음·활성 작업 없음 상태인지 확인한 뒤 별도 cleanup을 수행한다. cleanup 후 상태로 검사 결과를 덮어쓰지 않는다.

## 검증과 한계

최종 Debug/Release 빌드가 통과했다. 기존 검사 키를 제거하지 않았고 신규 키 한 개·셸 구문·diff 공백을 확인했다. Core/SDK 데이터 처리 코드는 바꾸지 않아 이미 통과한 74개/native 회귀를 반복하지 않았다. 로컬 GUI/전체 AppKit/장시간 앱은 실행하지 않았다.

새 창 종료와 암호 요청 추적의 실제 UI 수용은 미완료다. 기존 Intel 실행은 재시작하지 않고, 이번 수정과 384의 경로 폭 수정이 포함된 소스를 한 번 검증한다. 383 DMG는 이전 프리뷰로 두고 덮어쓰지 않는다. 최신 두 CPU/지원 환경·실제 입력/VoiceOver·정식 서명/공증 등 F23/M7은 진행 중이다. [소스·빌드·이전 진행 기록](archive-lifecycle-385.json).
