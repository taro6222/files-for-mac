# 376 — 압축 편집 기록·명시적 복구·다시 실행

앱 재시작 후에도 압축 편집 기록을 찾는 화면과 현재 압축 창의 Redo를 연결했다. **F23/M7은 진행 중이며 새 화면의 실제 UI 수용은 미완료다.**

앱 메뉴 ‘압축 편집 기록 및 복구…’에서 기록·보존 위치를 확인한다. 시작 시 미완료/읽을 수 없는 기록 수만 메뉴에 표시하며 자동 창 표시나 파일 복원을 하지 않는다. 기록상의 상태와 실제 파일 검증 결과를 구분한다. 파일 상태 확인 전 Undo/Redo는 비활성이다. 두 파일의 내용·식별자·metadata를 확인한 뒤 사용자가 복원을 확인해야 실행하며 교체 직전 다시 검증한다. 손상 기록과 이전 원본/수정본을 보존한다.

Redo는 Undo와 같은 두 버전 교체·검증·불변 저널 경로를 사용한다. 교체 전/후 프로세스 종료 뒤 다른 프로세스에서 실제 위치에 맞춰 저널을 정리한다. 외부 변경 시 교체를 거부한다. 새 편집은 현재 창의 Redo 스택을 비운다. 기록 화면의 복원 뒤 다른 창의 목록은 다시 열어야 하며 source-version 검사로 오래된 선택의 변경을 차단한다. 파일 복원 후 목록 갱신만 실패한 경우 완료된 복원을 실패로 안내하지 않는다.
