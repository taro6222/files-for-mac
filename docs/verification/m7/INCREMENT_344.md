# M7 Increment 344 — 독립 압축 구현 왕복과 7z 옵션 근거

상태: 로컬 독립 호환성 검증과 참조 도구 확보 완료. 제품의 7z 고급 백엔드 연결·두 CPU 재수용과 M7 정식 출시는 미완료다.

[공식 다운로드](https://www.7-zip.org/download.html)에서 연결되는 7-Zip 26.06을 고정했다. ip7z/7zip 릴리스의 ARM·Intel macOS 자산과 대응 소스의 게시 SHA-256을 내려받은 바이트와 대조했다. 실행 파일·License.txt·readme.txt의 개별 해시도 고정한다. 전역 설치 없이 build에 두며 다운로드 실행 파일이나 소스 압축 파일은 커밋하지 않는다. 앱 번들 연결은 아직 없다.

## 독립 구현 왕복

새 Core integration 검사는 현재 ZipArchiveProvider를 직접 호출한다. 앱 서비스가 ASCII 및 한글/emoji 암호로 만든 저장/최고 수준 AES ZIP 네 개를 공식 macOS 7-Zip에서 추출해 Unicode 파일의 원문과 비교했다. 공식 도구가 ASCII 암호로 만든 저장/최고 수준 AES ZIP 두 개도 앱 서비스에서 추출해 비교했다. 각 방향에서 틀린 암호를 거부하고 앱의 실패 staging이 공개되지 않으며 원본/아카이브 바이트가 보존되는지 확인한다. 실행 도구 해시와 버전도 검사해 다른 시스템 도구로 대체하지 않는다.

이 버전의 공식 ZIP 작성기는 IsSimpleAsciiString 검사로 비ASCII 암호 생성을 거부한다. 실제 CLI 결과와 대응 소스의 ZipHandlerOut.cpp를 확인했다. 이를 앱의 Unicode 암호 지원 축소로 처리하지 않는다. Unicode 암호의 앱 → 공식 macOS 도구 복호화는 실제로 통과했고, 공식 도구의 Unicode ZIP 생성은 지원되지 않는 경계로 기록한다. Windows Files/다른 OS의 모든 암호 인코딩 호환성이 수용된 것은 아니다.

암호는 CLI 인수에 넣지 않고 stdin으로 전달한다. 생성은 빈 -p로 입력을 요청하고 읽기는 -p를 생략해 암호 요청을 받는다. 처음 검증기에서 읽기에도 빈 -p를 주어 빈 암호로 처리됐다. 공식 도구가 만든 대조 ZIP에서도 동일 실패를 확인하고 입력 규칙을 고친 뒤 모두 통과했다. 제품 서비스 코드는 변경하지 않았다. 도구의 인수·출력에 암호가 나타나지 않는지도 검사한다. 비밀이 아닌 합성 시험 암호를 사용한다.

## 7z 고급 옵션의 실제 근거

공식 도구에서 Unicode 암호·헤더 암호화·LZMA2·64KiB 사전·워드 크기 32·요청 스레드 2·64KiB 분할을 함께 사용해 생성했다. 실제 분할 파일 5개가 생성됐으며 목록의 LZMA2:16으로 64KiB 사전을 확인했다. 암호 없는 목록에서 파일 이름이 노출되지 않았고 올바른 암호로 원문을 복원했다. 틀린 암호와 누락 part는 실패했고 해당 part를 복구한 뒤 검증이 다시 통과했다. 원본과 분할 바이트가 보존됐다.

이 실행은 참조 도구의 옵션 조합 검증이다. 실제 스레드 사용량이나 메모리 추정을 측정한 것이 아니며 제품 생성·목록·추출·취소·게시 복구의 수용이 아니다. [7z 백엔드 연결 계약](../../SEVENZIP_BACKEND.md)에 구조화된 SDK 경계·private 암호 채널·동일 원본 유지·분할 게시 저널·서명/패키징 순서를 기록했다. 현재 제품의 7z/RAR 암호·분할 capability는 미지원이다.

## 검증

참조를 활성화한 Core 전체는 396개 중 성공 377개·환경 건너뜀 19개로 통과했다. 새 함수 한 개의 독립 호환성 조건 15개와 참조 7z 옵션 조건 9개가 통과했다. 참조가 없는 기본 Core 실행에서는 이 새 integration 함수가 환경 건너뜀으로 표시되며 성공으로 집계하지 않는다. 전체 AppKit 수동 CI의 두 CPU에 참조 획득과 실제 실행을 필수 단계로 추가하고, 보고서가 없거나 함수가 실행되지 않으면 실패하도록 했다.

획득 보호 검사 5개로 해시 불일치·링크/중복 실행 파일·추출 경로 격리·변경된 캐시/외부 데이터 보존을 확인했다. 실제 네트워크 획득도 고정 해시와 notices 검사를 통과했다. Python 구문·workflow 파싱/단계 제한·parity 구조·diff 검사가 통과했다. 참조 ARM 바이너리의 코드 서명 검증과 양쪽 Mach-O 아키텍처/최소 배포 메타데이터도 확인했다. 이 메타데이터를 최소 OS 실제 실행으로 대신하지 않는다. [검증 해시·결과](archive-interop-344-verification.json).

앱·Package·Xcode 프로젝트 소스는 3e5c88f와 동일하여 Release/전체 UI를 반복하지 않았다. cf63dcf ARM 원격의 네 조합 각각 UI 318개·경계 18개와 새 ZIP 암호 검사가 실제 보고서에서 통과했다. 3e5c88f Spotlight 미마운트 native 단계는 macOS 15 ARM·Intel 양쪽에서 성공했으며 확인 시점 전체 작업은 진행 중이었다. 이 결과들을 새 독립 호환성 단계의 두 CPU 수용으로 집계하지 않는다.
