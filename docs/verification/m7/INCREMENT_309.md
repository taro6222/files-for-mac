# M7 Increment 309 — 태그를 보존하는 메타데이터 조회 병렬화

상태: 구현·로컬 기능 검증 통과. 두 CPU의 최적화 20회 성능 판정은 진행 중이며 2초 목표를 달성했다고 표시하지 않는다.

기존 `11e948a` 최적화 CI의 모델 열거 p95는 ARM 2.070초·Intel 4.145초로 목표에 미달했다. 같은 열거 코드를 사용한 `5284cb3` 최적화 QA 바이너리에서 소유한 100,000개 빈 파일을 읽는 별도 프로세스를 표본화했다. 스택에서는 정렬보다 디렉터리 URL의 메타데이터 prefetch와 File Provider 경로 확인이 많이 관찰됐다. API 대조에서도 전체 키 조회와 ubiquity 키를 제외한 진단 조회에 큰 차이가 있었다. 진단용 키 생략을 제품에 적용하지 않는다. [관찰된 스택](directory-profile-stack.txt), [원본 해시·측정·최종 검증](directory-metadata-parallel-verification.json).

제품은 URL 순회를 직렬로 유지하고 최초 128개·후속 1,024개 묶음의 메타데이터를 GCD에서 묶음당 최대 네 작업으로 조회한다. 각 결과는 원래 수집 위치에 결합한다. 태그·패키지·링크·숨김·크기·생성/수정 시각·identity·클라우드 상태를 유지한다. 모델에는 이후 작업에서 새 정보를 읽을 수 있는 별도 URL을 계속 보관한다.

태그를 prefetch하지 않는 시험 경로는 새 태그 보존 시험에서 태그를 잃는 문제가 확인됐다. 최종 경로는 태그의 명시적 prefetch를 유지한다. 태그를 제외한 느린 조회와 identity 구성은 제한한 작업에서 수행하며 요청하는 키는 그대로다. 이 선택은 태그를 생략해 빠른 결과를 얻지 않기 위한 기능 보존 조건이다.

취소는 대기 중인 Swift 소비자에 먼저 반환된다. 이미 진행 중인 동기 시스템 조회는 안전 지점에서 끝나며 늦은 묶음을 게시하지 않는다. 동시 실행 한도는 조회 한 건의 묶음에 적용되고 앱 전체 전역 한도라고 주장하지 않는다.

## 검증

- Debug·Release 빌드 성공. 고정 Debug SHA-256 `0292ce34f2d08b806b18d7c764b06e26df9e8a8614da510cd81812369999160b`.
- 전체 Swift 325개 보고: 성공 307개·별도 환경 건너뜀 18개. 새 세 시험은 태그·링크·숨김·유니코드·메타데이터 대조, 2,300개 항목의 묶음 경계·누락/중복, 차단된 제한 조회 중 취소 반환을 확인한다.
- Swift 실행기를 제한한 검사는 기존 아홉 개에 메타데이터 취소를 더한 열 개 모두 통과했다.
- 한국어/영어 × 밝게/어둡게 네 조합 각각 파일 작업 UI 78개·전체 UI 283개 통과.
- 로컬 전체 AppKit 표시 관찰값은 0.455–0.473초다. 네 실행이며 20회 p95·Intel 개선률·격리된 처리량 판정이 아니다.

독립 API 병렬화 probe는 일반 빈 파일에서 조회 비용을 나누는 효과를 확인한 진단이다. 최종 제품의 태그 prefetch·모델 갱신을 포함한 성능은 새 커밋의 두 CPU 최적화 실행으로 다시 판정한다. 기준 장비 16 GiB 이상, 실제 클라우드·최소 OS·정식 서명·공증·실제 접근성 및 최신 소스 장시간 검증은 남아 있다. 기존 8시간 두 실행은 각 이전 소스의 기준 실행으로 유지한다.
