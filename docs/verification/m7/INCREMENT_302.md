# M7 Increment 302 — 검증된 수신 보관본의 보관소 복원

상태: 구현·로컬 검증 통과. F17·M7 전체 완료가 아니다.

정리 기록 창에서 위치를 확인할 수 있는 보관본을 선택해 ‘보관소로 복원’을 실행한다. 새 정리 기록은 기존 폴더 identity에 더해 원래 보관소 부모의 identity와 보관본 전체 트리의 내용·권한 fingerprint를 기록한다. 복원 시 receipt에 있는 각 원본의 identity·내용·메타데이터와 보관본 전체 트리를 다시 검사한다. 등록되지 않은 파일·receipt, 원본 변경·교체·링크·권한·확장 속성 변경은 복원을 거부한다. 보관소로 되돌리는 동작이므로 외부 복사본이 지워졌더라도 검증된 보관본 자체는 복원할 수 있다. 예전 기록에 필요한 증거가 없으면 위치 조회를 유지하고 복원 버튼을 막는다.

원래 경로에 파일·폴더·링크가 생겼으면 덮어쓰지 않는다. 열린 원본·부모 디렉터리 핸들을 경로와 대조하고 탐색 전용 핸들로 원자적인 no-overwrite rename을 수행한다. 휴지통 부모의 내용 열거 권한을 요구하지 않는다. 서로 다른 볼륨에 대한 복사 후 삭제 fallback을 사용하지 않는다. 검사와 이동은 GCD에서 수행하며 안전 지점 취소, 작업 센터, 다른 파일 작업·종료 보호를 연결했다. 정상 복원 후 보관된 수신 파일 창도 새로 읽어 기존 복사 재개 흐름으로 이어갈 수 있다.

원래 정리 journal은 수정하지 않는다. 복원 전 의도와 완료·실패 결과를 각각 새로운 O_EXCL 파일에 기록하고 동기화한다. 최종 결과가 있으면 같은 시도의 의도 기록은 표에서 접고 원본 정리와 복원 결과를 작업 종류로 구분한다. 기록 파일은 남아 있다. 게시 후 변경·취소·부모 이동·기록 오류가 있으면 완료로 표시하지 않고 열린 vnode의 실제 위치를 확인해 보관본을 보존한다. 최종 기록을 만들 수 없어도 기존 의도 기록을 남기며 다른 파일을 덮어쓰거나 원본을 삭제하지 않는다.

추가 코어 시험 10개는 이동 위치가 기록된 중단 상태의 복원, 복사본 미존재, 기존 경로·동시 도착 충돌, 변경·추가·손상 receipt, 전후 취소, journal 변경, 원본·보관소·기록 부모 교체, 게시 후 내용·추가 파일·부모 변경, 이전 형식, 같은 바이트의 폴더 교체·링크·권한·확장 속성 변경을 검사한다. 중단 상태 코어 시험의 journal은 fixture에서 해당 체크포인트를 구성한 것이다. 실제 SIGKILL 후 알려진 위치를 복원하는 별도 프로세스 수용을 대신하지 않는다.

네이티브 계약은 실제 macOS 휴지통으로 옮긴 QA 보관본을 버튼으로 복원하고 원본 journal 미변경·작업 보호·반복 복원 방지를 확인한다. 그 뒤 같은 QA 보관본만 시험 폴더로 회수하며 사용자 휴지통은 비우지 않는다. 이름·작업 열의 최소 너비를 보장하고 상태 열이 남은 폭을 채우도록 배치했다. 최소 창의 버튼·헤더·셀 정렬도 검사한다. 캡처는 선택 행을 보존하고 AppKit 갱신을 처리한 뒤, 캡처 전후 열 너비가 안정되고 헤더와 셀 배치가 일치하는 상태에서 저장한다.

이전 소스 `05e2659`의 원격 결과는 [CPU별 원본 집계](05e2659-ci-verification.json)에 분리했다. Apple Silicon의 전체 UI 네 조합 각각 283개, 두 CPU Xcode는 성공했다. Intel 전체 UI는 폴더 크기·일부 원격 및 클라우드 준비 항목에서 실패했고, 시험 이미지 정리도 resource busy로 중단되어 강제 해제하지 않았다. 이 결과를 전체 워크플로 성공이나 이번 복원 소스의 성공으로 확대하지 않는다.

위치 저장 후 SIGKILL과 실제 설치 앱 재시작·키보드·VoiceOver·SDK 드래그 수용, 최신 소스의 두 CPU 결과, 최신 후보 장시간 판정과 정식 서명·공증은 남아 있다. 인증서·공증 프로필은 사용자 준비 중이다.

최종 고정 바이너리에서 네 언어·테마 각각 수신·정리·복원 계약 53개와 전체 AppKit 283개를 통과했다. 전체 Swift 315개 중 성공 297개·별도 환경 건너뜀 18개, 실제 위치 미기록 SIGKILL·새 프로세스 검증 14개도 통과했다. Debug·Release 빌드 성공과 Release의 QA 진입점 제외를 확인했다. 자체 Spotlight 시험 이미지는 읽기 전용 최종 검사 뒤 정리했다. 정확한 소스·앱 SHA와 결과는 [검증 기록](promise-restore-verification.json)에 저장한다. 중간 빌드와 캡처 보완 전 실행은 최종 고정 후보의 결과에 섞지 않았다.
