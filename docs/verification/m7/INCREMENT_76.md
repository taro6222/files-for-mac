# M7 Increment 76 — 홈에서 상세 목록 분리

홈이나 다른 보기로 전환할 때 상세 스크롤 뷰를 창에서 분리한다. 상세 보기로 돌아오면 동일한 테이블을 다시 붙인다. 상세 목록의 열 설정과 정렬 동작을 유지하면서, 창에 필요 없는 셀을 AppKit이 해제할 수 있게 한다. 장시간 시험은 폴더·보조 탭에서 상세 목록이 붙어 있고 홈에서는 분리되어 있는지 확인한다.

Apple Silicon macOS 27.2에서 최적화 QA 빌드의 탐색 대조를 비교했다. 아래 두 표본은 같은 125~126사이클 구간에 해당한다. 물리 메모리는 프로세스의 `phys_footprint`다.

| 빌드 | 사이클 | 보유 셀 | 물리 메모리 |
|---|---:|---:|---:|
| 분리 전 | 126 | 408 | 65.0 MiB |
| 분리 후 | 125 | 0 | 41.8 MiB |

분리 후 302.26초 동안 125사이클을 완료했다. 실행 중 모든 주기 표본에서 보유 셀이 44개였고 마지막 대기 이후 0개였다. 물리 메모리 최대값은 46.0 MiB였다. 행 단위 삽입·삭제, 초점 초기화 생략, 셀 레이아웃 변경, 숨은 목록 보존, 자동 초점 순서 비활성화 실험에서는 보유 셀이 계속 증가했다.

Swift Testing 213개와 한국어·영어 × 밝게·어둡게의 AppKit 검사 각 224개를 통과했다. AppKit 검사에는 기록에서 돌아올 때의 행 선택과 스크롤 복원, 보기 모드 전환, Git 셀 업데이트가 포함된다.

목록 부착 검증을 포함한 최종 QA 빌드에서 탐색 39사이클(90.74초, 최대 45.6 MiB)과 전체 부하 30사이클(92.16초, 최대 66.1 MiB)을 완료했다. 같은 바이너리(SHA-256 `0abb7f4a874969e162f8e127586c0a47fe629e1ae2c3b13bbfaf84238a79ffa9`)의 28,800초 전체 부하 시험을 시작했다. 원래 메모리 증가가 장시간에도 재현되지 않는지와 전체 시험에 남아 있는 증가분은 종료 보고서로 판정한다.
