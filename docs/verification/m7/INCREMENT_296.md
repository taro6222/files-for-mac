# M7 Increment 296 — 재시작 후 수신 파일 복구 화면

상태: F17 수신 개발 진행 중. 파일 메뉴의 ‘보관된 수신 파일…’에서 앱 전용 저장소에 남은 수신 작업을 다시 읽는다. 날짜·파일명·상태를 표시하고 여러 작업을 선택하여 대상 폴더를 고른 뒤 기존 충돌 정책·복사·실행 취소 흐름으로 전달한다. 사용자 화면에 내부 작업 UUID 선택을 요구하지 않는다.

`PromisedFileRecovery.discover`는 UI 밖에서 기록을 읽고, 아직 보관소가 없으면 빈 목록을 반환한다. 보관소를 새로 만들지 않는다. 일반 디렉터리만 조회하며 저장소 루트의 심볼릭 링크를 거부하고 작업을 가리키는 심볼릭 링크나 무관한 파일을 채택하지 않는다. 손상된 기록은 목록에 남겨 자동 복사를 막고 Finder에서 직접 확인할 수 있게 한다. 등록되지 않은 수신 파일도 임의로 채택하거나 삭제하지 않는다.

목록을 읽을 때는 큰 파일을 전부 해시하지 않는다. 복사 재개를 누른 뒤 선택한 모든 기록의 원본 identity·내용·권한·메타데이터를 다시 검증하고, 대상 폴더가 검증 도중 바뀌었으면 요청을 거부한다. 기존 복사 엔진은 충돌 정책 선택 후와 게시 전에도 원래 수신 기록을 확인한다. 취소·실패·성공 이후에도 보관된 원본은 유지하며, 보관소 자동 정리는 후속 작업이다. 수신·폴더 병합이 진행 중일 때 앱 종료 보호에도 포함했다.

신규 코어 시험 4개는 없는 저장소 조회 시 무변경, 정상·손상 기록과 외부 항목 구분, 목록 조회와 실제 데이터 재검증 분리, 심볼릭 링크 저장소 거부를 검사한다. 네이티브 복구 화면 계약은 실제 보관 기록을 다시 읽은 표의 행 수, 정상 기록의 복사 활성화, 손상 기록의 파일 보기만 허용, 혼합 선택 시 복사 차단을 확인한다. 이 검사는 실제 메뉴 마우스 조작·폴더 선택 패널·VoiceOver·새 프로세스 재기동의 수용 검증과 구분한다.

앱·테스트 빌드, 관련 55개 시험, 네이티브 AppKit 계약 28개, 대응표 감사와 Xcode 프로젝트 재생성 일치가 통과했다. 임시 경로의 표기 차이로 실패하던 시험은 실제 항목 identity와 이름을 비교하도록 수정한 뒤 전체 관련 시험을 다시 통과했다. 검증 결과와 소스 해시는 [복구 UI 검증 기록](promise-recovery-ui-verification.json)에 저장한다. 실제 SDK 드래그 전달, 새 수신·복구 화면의 언어·테마·접근성 수용, 검증된 보관소 정리 및 준비 중인 Developer ID·공증은 열린 항목이다. F17이나 M7 전체 완료로 판정하지 않는다.

별도 소스 `390cdb9`의 전체 UI 재실행은 Apple Silicon 성공·Intel 실패로 종료했다. Intel은 네 조합이 각각 180초 시간 초과였다. 이전 `3a65d40` Intel 통과를 새 실행의 성공으로 간주하지 않으며, 수집한 스택과 진행 기록으로 원인을 추가 조사한다. 이번 복구 UI 검증 결과와 구분한다.
