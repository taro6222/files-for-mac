# M7 Increment 343 — Spotlight 마운트 해제 상태의 정리

상태: 재현·수정·로컬 실제 볼륨 검증 완료. 원격 재수용과 M7 정식 출시는 미완료다.

b57d3e4 ARM 작업은 네 조합 전체 UI 각각 312개/경계 18개를 통과한 뒤 Spotlight 시험 볼륨 정리에서 `Image mount does not match the owned mount point`로 실패했다. 기존 소유 mmap을 유지하는 일반 EBUSY 검사는 로컬에서 통과했다. 별도의 소유 APFS 이미지에서 파일 시스템만 정상 마운트 해제해 이미지 연결이 남게 하자 기존 정리 코드가 같은 오류로 거부했고 이미지 파일이 보존됐다. 이는 실패 상태의 실제 재현이며 원격에서 그 상태가 만들어진 정확한 순서까지 확인한 것은 아니다.

## 수정

정상 마운트와 이미지 연결만 남은 상태를 구분한다. 마운트된 경우는 기존 경로·UUID·소스 내용 검증을 유지한다. 마운트가 없으면 빈 호스트 마운트 디렉터리인지 확인하고, 기록한 볼륨 UUID를 diskutil에서 다시 조회한다. 현재 APFS 컨테이너의 유일한 볼륨 UUID·장치와 유일한 물리 저장소가 해당 소유 이미지의 현재 장치 매핑에 연결돼야 해제를 허용한다. 저장된 과거 imageDevice를 그대로 사용하지 않는다.

이 시험 이미지는 GPT 장치·물리 저장소·APFS 컨테이너·볼륨 각 하나인 구조를 요구한다. 추가 파티션·볼륨, 다른 물리 저장소, 다른 마운트 경로, 누락/변경 UUID, 빈 마운트 디렉터리의 외부 데이터나 링크는 거부한다. backing 이미지와 소유 폴더의 identity/표식도 계속 검사한다. 상태별 현재 장치·시도 횟수·결과 및 EBUSY 뒤 소유 이미지의 장치/마운트 정보를 state.json에 남긴다.

마운트가 없는 상태의 장치 해제는 이미지 삭제 허가가 아니다. 이미지를 지우기 전에는 다시 읽기 전용으로 붙여 정확한 공개 소스·표식·허용 메타데이터만 있는지 확인한다. 알 수 없는 데이터가 발견되면 읽기 전용 마운트와 backing 파일을 보존한다. 강제 해제는 사용하지 않으며 EBUSY 최대 5회·각 명령 제한도 유지한다.

## 검증

소유권 단위 검사 23개가 통과했다. 기존 14개에 미마운트 현재 장치, UUID/컨테이너 멤버 변경, 다른 물리 저장소, 추가 볼륨/파티션, 외부 마운트, 호스트 디렉터리 데이터/링크, 누락 UUID, 추가 마운트, EBUSY 뒤 파일 시스템만 해제된 상태를 추가했다. 이미지와 외부 합성 데이터의 보존을 함께 검사한다.

실제 APFS에서는 이전 코드가 거부한 미마운트 이미지가 수정 후 정상 정리됐고 읽기 전용 최종 검사도 통과했다. 추가 합성 파일을 넣고 미마운트 상태로 정리하면 읽기 전용 검사에서 거부됐으며 파일과 backing 이미지가 보존됐다. 검증 도구는 같은 UUID·파일 inode·합성 바이트를 확인한 뒤 자신이 만든 파일 하나만 제거하고 정상 정리를 마쳤다. 수정 후 기존 mmap EBUSY 16 재시도도 실제로 관찰하고 최종 정리까지 통과했다. 시험에 사용한 이미지 4개는 모두 cleaned=true이며 backing 파일·소유 리소스 폴더가 남지 않았다.

새 [실제 볼륨 검증 도구](../../../scripts/verify-spotlight-unmounted-cleanup.py)를 전체 AppKit 수동 CI의 ARM·Intel 양쪽에 추가했다. 새 상태/보고서 두 파일은 기존 Spotlight 진단 아티팩트에 보존한다. 5분 제한으로 실행하며 기존 빌드·UI 시간 기준을 늘리지 않았다. workflow 파싱·분기/제한 검사, Python 구문 검사·parity 구조 감사·diff 검사가 통과했다. [소스·보고서 해시와 결과](spotlight-cleanup-343-verification.json).

앱·Package·Xcode 프로젝트·Core 시험 소스는 cf63dcf와 동일함을 비교했다. 앱 빌드와 Core·전체 UI 검사를 반복하지 않았다. 현재 앱의 로컬 결과는 342단계의 Core 성공 376개·건너뜀 19개, 네 조합 전체 318개/경계 18개다. 새 시험 도구의 macOS 15 두 CPU 수용과 원격 오류 재발 여부는 아직 확인해야 한다. 원격 발생 원인이 확정되거나 전체 작업이 성공했다고 표시하지 않는다.
