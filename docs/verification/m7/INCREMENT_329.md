# M7 Increment 329 — 최소 창의 사이드바와 사용자 너비 유지

상태: 구현·Core·네 조합 전체 UI/경계·Debug/Release·짧은 메모리 진단 통과. 새 소스 원격/장시간 및 M7 출시는 미완료다.

설계의 사이드바는 기본 220pt, 드래그 범위 180~320pt다. 실제 900×600 창에 탭 12개와 긴 한글 제목을 연 검사에서 한국어 67pt·영어 98pt로 축소돼 글자가 잘렸다. 제목/경로의 압축 우선순위 변경만으로는 해결되지 않아 별도 BrowserRootSplitView로 기본값·허용 범위·사용자 선택 너비를 관리한다.

분할 뷰의 자동 fitting/layout 너비를 사용자 드래그 값으로 저장하지 않는다. 초기 크기가 0일 때의 네이티브 위치 보정도 기본값을 덮지 않는다. 창을 늘려도 사용자가 지정한 260pt를 유지하고, 숨기면 본문이 네이티브 구분선 폭을 제외한 공간을 사용하며 다시 보이면 260pt를 복원한다. 내부 분할 pane의 비율과는 별개로 사이드바에만 적용한다.

긴 폴더 제목은 한 줄 가운데 말줄임을 적용하고 전체 경로 도움말을 제공한다. 제목·경로가 좁은 공간에서 먼저 줄어들며 실제 문자열과 접근 가능한 탭 레이블을 유지한다. 최소 창 전체 캡처와 기본 220pt·180~320pt 드래그 범위·창 크기 변경·숨김/복원을 추가해 탭 경계 18개로 검증한다. 숨김 공간 검사는 실제 네이티브 구분선 두 개를 계산한다.

직전 bf263ae의 원격 실제 진단은 네 조합 모두 화면 영역 {{0,59},{1024,684}}, 요청 {{80,90},{1100,720}}, 원본 {{80,59},{1100,684}}, 대상 {{0,59},{1024,684}}였다. 화면보다 큰 요청이 네이티브 표시 과정에서 달라졌다. 검증은 사용 가능한 화면 안의 프레임으로 변경하고 원본·대상의 정확한 동일성·선택·숨김 기준을 유지한다. 원본도 요청 프레임과 같고 화면 안에 있는지 추가로 검사한다. 새 원격 재수용은 별도로 확인한다.

이전 5284cb3 실행은 28,802.3초·9,525사이클, 종료 0으로 완료됐지만 첫/마지막 60개 표본의 물리 footprint 중앙값이 52.08→160.09MiB로 상승했다. [실제 표본과 종료 근거](soak-5284cb3-final.json)를 보존하며 메모리 안정성이나 최신 소스 수용으로 집계하지 않는다. 이후 소스의 진행 중인 실행은 중단하지 않는다.

사이드바 보정 후 전체 UI에서 정보 패널 너비 검사가 실패했다. 바깥 분할 뷰가 두 고정 영역과 본문을 함께 배치하도록 정리하고 기존 정보 패널 고정 240pt 제약을 제거했다. 정보 패널은 설계의 기본 280pt·허용 240~420pt를 사용한다. 좁은 창에서는 본문 최소 공간을 고려해 두 패널의 허용 폭을 제한하고, 창을 넓히면 사용자 선호 폭을 다시 적용한다. 사용자 지정 320pt도 숨김/복원 뒤 유지된다. 이 변경은 실행 중 창의 패널 배치이며 창별 크기·위치를 세션에 저장하는 수용은 별도로 남아 있다.

최종 Swift 385개 중 성공 366개·환경 건너뜀 19개, 제한 실행기 10개, 네 조합마다 전체 UI 294개와 패널/탭 경계 18개, Debug·일반 Release·최적화 QA 빌드·프로젝트 생성·parity 감사가 통과했다. [소스·바이너리·전체 검사 해시](panels-329-verification.json), [너비 축소와 숨김 복원 실패](panels-329-before.json), [원격 실제 프레임](tabs-bf263ae-arm-frame.json), [짧은 메모리 결과](panels-329-memory.json)를 보존한다. 이 UI 단계에서 실제 볼륨·외부 서비스 매트릭스는 다시 실행하지 않았다.

짧은 full 진단은 182.4초·67사이클로 정상 종료했다. 5·40사이클에서 관찰 컨텍스트 1,031개·의존성 3,262개·BrowserWindow 1개·BrowserTabWindow 1개·NSStackView 14개가 유지됐다. 매 사이클 닫힌 창·컨트롤러·감시기의 weak 해제를 확인했다. 최신 소스 8시간 수용으로 집계하지 않는다.
