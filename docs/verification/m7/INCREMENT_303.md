# M7 Increment 303 — 메타데이터 조회 실행 분리와 비동기 완료 대조

상태: 구현·로컬 검증 통과. Intel 전체 UI와 정식 출시의 완료 판정은 아직 하지 않는다.

`05e2659`의 Intel 보고서에서 폴더 크기 검사 직전 10,000개 중 3,200~7,296개만 열거됐고 원격·클라우드 준비도 일부 평가 시점에 끝나지 않았음을 확인했다. 원본 결과는 [CPU별 집계](05e2659-ci-verification.json)에 남겨 둔다. 이 실행의 전체 AppKit 표시 시간은 약 5.7~8.3초여서 성능 목표를 만족했다고 표시하지 않는다.

폴더 크기·클라우드·마운트 볼륨의 동기 파일 시스템 작업을 Swift의 협력 실행기 밖 GCD 큐로 옮겼다. 공통 실행기는 continuation과 취소를 lock으로 직렬화해 완료·취소가 경합해도 한 번만 응답한다. 취소 시 기다리던 Swift 작업은 먼저 반환할 수 있으며, 이미 진행 중인 Foundation 시스템 호출 자체를 강제로 중지했다고 주장하지 않는다. 늦은 결과는 폐기하고 취소된 화면의 새 상태를 덮어쓰지 않는다. 폴더 항목의 identity 전후 검사, 링크 제외, 오류와 오버플로 처리는 유지한다.

파일 열거에서 매 항목의 URL을 만들 때 이미 알려진 디렉터리 유형을 명시한다. [Apple의 기존 URL API 설명](https://developer.apple.com/documentation/foundation/url/appendingpathcomponent%28_%3A%29)은 유형이 생략되면 파일 시스템 조회가 발생할 수 있다고 명시한다. 열거기의 prefetched 값을 모델 URL에 재사용하지 않고 새 URL을 유지하면서 중복 조회를 피한다. 파일 identity 검사와 태그·클라우드·기본 메타데이터를 생략하지 않는다. 특수 파일명과 디렉터리 힌트, 열거 후 파일 변경 시 모델 URL이 오래된 크기를 반환하지 않는지도 검사한다.

원격 모델은 현재 요청의 완료를 await할 수 있다. GUI 검사는 요청 직후 읽기 중 피드백을 확인한 다음 실제 요청 완료를 대조하며, 고정 50ms sleep을 완료 신호로 쓰지 않는다. 초기 클라우드·볼륨 검색도 실제 작업을 기다린 뒤 fixture를 바꾼다. 초기 창의 즉시 표시를 별도로 확인한다. 닫힌 원격 창은 진행 중 목록 요청을 취소하고 이미 취소·교체된 요청은 transport를 시작하지 않는다. 기존 다운로드 검사에는 창 닫기 취소도 연결하고 두 결과를 진단 필드에 분리한다.

폴더 열거와 크기의 기존 각 5초 대기, 전체 UI 283개 및 프로세스 180/600초 예산은 바꾸지 않았다. 첫 표시·전체 열거·입력 응답의 성능 목표도 그대로이며, 기능 준비가 끝났다는 사실을 성능 목표 달성으로 확대하지 않는다. Intel의 실제 후속 실행과 성능 판정은 남아 있다.

Spotlight 시험 볼륨의 연결 해제는 `hdiutil`의 실제 종료 코드 16일 때만 최대 다섯 번 재시도한다. 매번 자원 표식·이미지 identity·현재 연결 장치·APFS UUID·원본 전용 내용을 다시 검증한다. 다른 오류·추가 데이터·지속적인 busy는 중단하고 이미지를 보존한다. 강제 해제는 하지 않는다. 보호 시험 14개는 장치 번호 변경 재확인, 재시도 사이 새 파일 도착, 지속 busy와 다른 오류를 포함한다.

추가 Swift 시험은 차단된 크기·클라우드 조회 중 다른 Swift 작업의 실행, 취소의 선행 반환, 늦은 결과 폐기, 취소·완료 경합, 원격 실제 완료와 URL 메타데이터 신선도를 확인한다. 제한된 Swift 실행기에는 기존 다섯 검사에 네 메타데이터 검사를 더해 아홉 개를 수행한다. 동기화 watchdog과 앱 성능 예산은 구분한다.

실제 busy 정리 재현은 `scripts/verify-spotlight-busy-cleanup.py`로 수행한다. 소유한 시험 볼륨의 공개 Swift 파일만 mmap한 전용 자식과 cwd를 유지하고, 실제 EBUSY가 관찰되면 그 자식만 종료해 연결 해제 재시도를 확인한다. 상태·장치·읽기 전용 최종 검사 결과를 별도 보고서에 남기며 실제 busy가 관찰되지 않으면 재현 성공으로 표시하지 않는다.

위치 기록 후 실제 SIGKILL과 복원, 설치 앱·실제 SDK 드래그·키보드·VoiceOver, 최신 후보 장시간 및 정식 서명·공증은 남아 있다. 자격 증명은 사용자 준비 중이다. F17·M7 전체 완료로 표시하지 않는다.

최종 Debug·Release 빌드가 성공했다. Swift 322개 중 성공 304개·별도 환경 건너뜀 18개, 제한 실행기 9개, 원본 수신·복원 계약 53개, 전체 AppKit 네 조합 각각 283개, 실제 마운트 7개와 파일 작업 UI 각각 79개, 볼륨 보호 14개가 통과했다. 실제 mmap/cwd holder에서 EBUSY 16을 관찰하고 그 자식만 종료한 뒤 재시도·읽기 전용 검사·이미지 정리도 통과했다. 고정 바이너리 SHA와 원본 결과는 [검증 기록](async-metadata-verification.json)에 저장한다. 로컬 전체 표시 약 0.80~0.84초는 네 실행의 관찰값이며 Intel 개선률이나 20회 성능 백분위 달성으로 표시하지 않는다.

추가로 종료된 `bf8380c` CI는 [원본 상태](bf8380c-ci-verification.json)에 기록했다. 두 CPU Xcode는 성공, Apple Silicon 검증 작업은 취소, Intel은 마운트 시험 7개 통과 뒤 첫 M2 UI의 copy/merge 단계에서 Cocoa 1570으로 중단됐다. 이 실행은 수신 계약·재기동·전체 AppKit에 도달하지 못했다. 현재 소스의 로컬 결과와 구분하고 후속 두 CPU 실행에서 다시 판정한다.
