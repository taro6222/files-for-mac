# 368단계 — 프리뷰의 읽기 전용 마운트 실행 검증

## 결과

366 프리뷰와 SHA-256이 같은 이미지 `b66c2d82a678d9a8df36f2ea45297b33e95a7dc40428d6afa584ab1f9a70a9ea`를 `/private/tmp`의 고유 경로에 읽기 전용·Finder 미표시로 마운트했다. 루트 폴더 조회와 기존 DMG 내용물·서명·두 CPU·manifest 검사가 통과했다. 이후 같은 위치 정책의 별도 마운트에서 실제 제품 검증을 수행했다.

마운트된 앱의 Swift 클라이언트 57개가 17.236초에 통과했다. 실제 격리 helper 50개, 별도 진단 SDK 142개, 같은 권한의 native probe 15개도 통과했다. 35,000항목 목록, 4,000파일 생성·복원, 암호·분할·metadata·취소/원본 보호·변조 거부 회귀를 포함한다. 이 결과는 추출한 data fork가 아니라 마운트된 실제 앱에서 얻었다.

두 마운트 모두 강제 해제 없이 정상 detach했고 임시 마운트 폴더를 정리했다. 최종 hdiutil 조회에서 해당 이미지가 남지 않았다. 로컬 GUI 앱·전체 AppKit·장시간 시험은 실행하지 않았다. 이미지/제품 코드는 변경하지 않았다.

## 이전 실패와의 구분

366단계의 작업 폴더 아래 마운트는 루트 폴더 open에서 대기했다. 같은 이미지가 `/private/tmp`에서는 동작했으므로 현재 증거는 경로에 따른 차이다. 원인이 TCC·sandbox·파일 시스템 정책인지 확정하지 않으며 이전 실패를 통과로 다시 기록하지 않는다. 검증용 마운트는 작업 폴더 아래가 아닌 별도 시스템 임시 경로를 사용하고 읽기 전용·정상 detach·이미지 identity 확인을 유지한다.

이 확인은 DMG 안의 payload 접근/실행 검증이다. Finder에서 설치해 Gatekeeper를 거쳐 앱을 여는 동선이나 정식 서명·공증을 대체하지 않는다. 제품은 여전히 0420df1 프리뷰이며 검증 harness는 4a6c79d다. UI 검증 함수 분리 후 새 제품 소스 4a6c79d의 전체 AppKit 원격 실행 45847539460은 별도로 유지 중이다.

[이미지·마운트·검사·해제 증거](mounted-preview-368-verification.json). 제품 코드가 바뀌지 않는 증거 커밋에는 `[skip ci]`를 사용해 같은 원격 전체 검증을 중복 실행하지 않는다.
