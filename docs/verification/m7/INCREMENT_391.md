# 391 — 빌드 관찰 fixture 준비 동기화와 프리뷰 단계 분리

## 확인한 원인

0079406의 [45892370861](https://github.com/taro6222/files-for-mac/actions/runs/45892370861) Intel build artifact에서 관찰 대상 부모 PID 2050만 수집되고 이후 기록된 자식 PID 2052는 없었다. 수집된 부모 sample은 성공했고 실제 부모/자식은 정상 종료했다. 50ms 관찰 시점에 자식이 아직 생성되지 않은 준비 순서 문제였다. 프로덕션 수집 알고리즘이 자식을 필터링했다는 근거로 설명하지 않는다.

## fixture 수정과 통제

별도 세션 자식 생성에 200ms 지연을 넣어 이 순서를 확실히 재현한다. 해당 fixture에서만 준비 marker가 생길 때까지 최대 5초 기다린 뒤 원래 collect 함수를 호출하는 어댑터를 사용한다. 수집 결과/샘플/소유 프로세스 판정은 변경하지 않는다. 자식 종료 코드도 부모에서 전파한다.

같은 지연 fixture에서 어댑터를 쓰지 않는 통제 시험은 DifferentGroupChildCollected로 실패했다. 수정본은 실제 샘플·그룹/부모 관계·무관한 프로세스 제외·관찰 도구 회수·종료 코드·취소 정리 등 기존 30개를 모두 통과했다. 기존 검사 키나 단일 관찰 조건을 제거하지 않았다. fixture 8초·검증 12초·sample 도구 8초의 기한과 프로덕션 monitor는 그대로다. 새 어댑터의 준비 대기는 이 기존 전체 기한 안에서 동작한다.

## 프리뷰 단계

b6a999e의 [45890631779](https://github.com/taro6222/files-for-mac/actions/runs/45890631779) Intel은 전체 AppKit 단계가 성공했지만 결합된 프리뷰 단계의 15분을 초과했다. 로그/메타데이터를 대조하면 DMG가 단계 시작 883.08초 후 완성돼 설치 검증에 16.92초만 남았다. 46b8848의 45893345872도 같은 결합 단계에서 제한 시간을 초과했고 그 로그에는 DMG 완성 기록이 없었다. 앱 기동 자체의 원인 해결로 설명하지 않는다.

워크플로를 이미지 빌드와 설치/기동 검증으로 분리했다. 빌드는 기존 matrix의 빌드 예산(ARM 12분·Intel 20분)을 사용하고, 설치 검증은 기존 15분을 독립적으로 사용한다. --startup/--launch-services/CPU 확인과 설치 스크립트 내부의 개별 기한은 바꾸지 않았다. 기존 실행은 재시작하지 않으며 변경된 워크플로의 실제 수용은 대기 중이다.

## 범위

Python 구문·워크플로 YAML/명령 분리·diff 공백 검사가 통과했다. 앱/Core/SDK 코드는 바꾸지 않아 이미 검증한 85개 SDK 회귀나 로컬 앱을 다시 실행하지 않았다. 이는 제품 빌드 성공이나 전체 M7 수용 증거가 아니다. 로컬 GUI/전체 AppKit/장시간 앱은 실행하지 않았다. [소스·실제 실패·통제·최종 검사 기록](ci-readiness-391.json).

F23 생성 시각 소수 초·지원 볼륨/중단/긍정 재개 UI, 최신 원격 두 CPU/지원 환경·물리 입력/VoiceOver·장시간·정식 서명/공증 등 전체 기능/UI 동등성과 M7은 계속 미완료다.
