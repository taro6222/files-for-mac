# M7 Increment 328 — 중복 제목의 탭 목록과 다수 탭 경계

상태: 구현·Core·네 조합 전체 UI/탭 경계·Debug/Release·짧은 메뉴 수명 진단 통과. 이전 원격 프레임 실패·Intel 빌드 시간 초과와 M7 출시는 미완료다.

최소 900×600 창에 탭 12개를 열고 마지막 탭을 긴 한글 이름 폴더로 선택하는 실제 AppKit 검사를 추가했다. 같은 제목의 탭을 목록에서 선택하는 검사가 실패했다. 앱 코드가 없는 PopupTitleProbe에서 NSPopUpButton.addItem으로 Home 11개·긴 제목 1개를 추가했지만 목록은 안내 항목 포함 3개와 태그 0/10/11만 남았다. 같은 제목의 앞선 탭이 목록에서 사라졌던 원인을 확인했다.

목록을 만들 때 각 탭마다 별도 NSMenuItem을 추가하고, 항목은 탭의 약한 참조를 가진다. 메뉴를 연 뒤 탭 순서가 바뀌어도 숫자 인덱스의 다른 탭을 고르지 않고 원래 탭을 선택한다. 닫히거나 다른 그룹으로 이동한 탭의 오래된 메뉴 항목은 선택하지 않는다. 컨트롤러를 메뉴의 representedObject로 직접 보유하지 않는다. 캡처에서 함께 보이던 기본 팝업 화살표와 사용자 지정 화살표는 하나로 정리했다.

긴 제목 검사는 전체 접근성 레이블과 말줄임, 닫기 버튼과의 분리를 확인한다. 초기 검사는 닫기 버튼의 원시 frame 폭이 20pt일 것으로 가정해 실패했다. 실제 AppKit의 정렬 영역 20pt와 장식/정렬 여백이 포함된 frame 20.5pt를 구분하도록 검사를 바로잡았다. 이 차이를 제품 결함으로 집계하지 않는다.

새 경계 열 가지는 선택 탭 자동 스크롤, 목록/새 탭 버튼의 창 안 배치, 긴 제목의 전체 접근성 레이블, 중복 제목의 별도 항목, 숨은 탭 선택, 메뉴 추적 중 재정렬, 접근성 누르기, 방향키 순환, 실제 닫기 버튼의 백그라운드 탭 닫기, 다수 탭을 닫은 뒤 숨은 컨트롤 정리다. 직접 AppKit 동작을 호출한 검사이며 실제 포인터·키보드·VoiceOver 수용과 구분한다.

verify-ui.sh가 같은 결과 루트의 tabs-ko-light 등 네 디렉터리에서 경계 검증을 실행하도록 연결했다. 기존 CI의 AppKit 보고서/PNG 보존 패턴을 그대로 사용한다. 기존 전체 UI의 294개와 별도 경계 10개를 섞어 같은 검사 수로 표시하지 않는다.

최종 Swift 385개 중 성공 366개·환경 건너뜀 19개, 제한 실행기 10개, 네 조합마다 전체 UI 294개와 별도 탭 경계 10개, Debug·일반 Release·최적화 QA 빌드와 프로젝트 생성·parity 감사가 통과했다. [소스·바이너리·전체 결과 해시](tabs-boundaries-328-verification.json), [최초 실패](tabs-boundaries-328-initial-failed.json), [독립 AppKit 제목 중복 대조](tabs-boundaries-328-popup-probe.json), [짧은 메모리 결과](tabs-boundaries-328-memory.json)를 보존한다. 실제 볼륨/외부 서비스 매트릭스는 이 UI 단계에서 다시 실행하지 않았다.

수정 후 full 진단은 181.3초·67사이클로 정상 종료했다. 5·40사이클의 관찰 컨텍스트 1,033개·의존성 3,269개·BrowserWindow 1개·NSStackView 14개가 유지됐다. 매 사이클 닫힌 창·컨트롤러·감시기의 weak 해제를 확인했다. 이는 최신 소스 8시간 수용이 아니다.

최종 최소 창/오버플로 캡처: [한국어 밝게](tabs-boundaries-328/ko-light.png), [한국어 어둡게](tabs-boundaries-328/ko-dark.png), [영어 밝게](tabs-boundaries-328/en-light.png), [영어 어둡게](tabs-boundaries-328/en-dark.png). 실제 입력·VoiceOver 및 원본 전체 상태 대조는 여전히 미완료다.

이전 [76fda96 최종 CI](tabs-76fda96-ci-final.json)는 두 Xcode 빌드 성공, Intel SwiftPM 단계의 기존 20분 시간 초과, ARM 네 조합의 browserTabsRevealSynchronizesFrame 실패로 전체 실패다. ARM 나머지 289개 검사는 각 조합에서 성공했다. 현재 코드는 해당 프레임 검사와 시간 기준을 유지하며 요청 프레임·원본/대상 실제 프레임·화면 영역·선택/표시 상태를 진단에 추가한다. 로컬 네 조합은 요청·원본·대상이 {{80,90},{1100,720}}으로 같고 화면 영역은 {{0,63},{1800,1067}}이다. 원격 실제 값은 새 실행에서 확인하며 화면 제약이나 제품 결함이라고 단정하지 않는다. 이전 실패를 수정 완료로 집계하지 않는다.

새 소스의 원격·최신 8시간, 원격 프레임/Intel 빌드 실패의 원인 해결, 실사용/지원 환경·원본 전체 UI·외부 서비스·기준 Intel 성능·정식 서명/공증은 남아 있다. 이전 장시간 실행은 중단하거나 새 소스 결과로 집계하지 않는다. 인증서·공증 프로필은 사용자 준비 중이다.

짧은 진단의 최대 물리 footprint는 62.17MiB이며, 최종은 50.03MiB였다.
