# M7 Increment 299 — 독립 APFS Spotlight 검증 환경

상태: 로컬 검증 통과, 두 CPU의 원격 전체 실행은 진행 대상으로 유지한다. M7과 F17은 완료하지 않는다.

기존 원격 실패는 Swift importer가 원본 내용을 읽어도 호스트 Data 볼륨의 실제 색인이 생기지 않은 경우다. 전체 검색 검사를 축소하지 않고 시험 전용 256MB APFS 이미지를 만들고 그 볼륨에만 색인을 활성화한다. 원래 `LocalSearch.swift`를 SHA-256으로 대조하여 복사하고, 실제 `mdfind` 적중 후 NSMetadataQuery의 하위 폴더·현재 폴더·전체 색인 위치·빈 결과 네 조건을 확인한다. 호스트 Data 볼륨 설정은 바꾸지 않는다.

이미지·디렉터리 identity, 외부·내부 소유 표식, 현재 hdiutil image-path 연결, APFS UUID와 원본 바이트를 검사한다. 알 수 없는 파일·휴지통 내용·심볼릭 링크·특수 파일·교체된 이미지는 정리를 거부하고 보존한다. 연결 해제 후 읽기 전용으로 다시 마운트해 최종 내용을 검사한 다음 알려진 시험 이미지와 빈 자원 디렉터리만 제거한다. 강제 연결 해제와 사용자 데이터 재귀 삭제는 하지 않는다. 중간 준비 실패도 공개 원본의 부분 복사만 허용하며 다른 바이트는 보존한다.

네이티브 검증 전용 예상 URL을 standardize하여 `/tmp`와 `/private/tmp`의 같은 파일을 같은 URL로 비교한다. 제품 검색 어댑터의 동작과 원본 일치·범위 검사는 유지한다. 별도 `/private/tmp` 시험에서 이 경로 차이로 실패했던 네 조건도 수정 후 모두 통과했다.

검증 결과:

- 앱 빌드 성공. 실제 APFS 원본 콘텐츠 색인과 네이티브 범위 검사 4개 통과.
- 전체 AppKit은 한국어·영어와 밝음·어두움 각각 283개 통과.
- 소유권·내용 변경·링크·특수 파일 보호 단위 시험 10개 통과.
- 실제 마운트 상태에서 추가 파일이 있으면 정리를 거부하고 원본을 보존했다. 이후 읽기 전용 최종 검사·연결 해제·이미지 정리 및 재정리의 멱등성을 확인했다.
- 최종 보호 코드로 새 볼륨을 다시 만들어 실제 색인·읽기 전용 정리까지 통과했다. 초기 실험용 이미지도 현재 연결·UUID·원본을 대조해 안전하게 정리했다.
- 대응표 구조 감사 통과(명령 202, 설정 143, 화면 33). 전체 수용 완료율을 의미하지 않는다.

정확한 소스·앱 SHA와 결과는 [검증 기록](spotlight-isolated-verification.json)에 저장한다. 기존 `8a06e92`의 원격 Xcode는 두 CPU 모두 통과했다([실행](https://github.com/taro6222/files-for-mac/actions/runs/45654995926)). 이 결과를 새 소스의 전체 UI 통과로 표시하지 않는다. 새 CI에는 독립 볼륨 준비와 보호 시험을 연결하고, 네이티브 수신 정리 화면도 진단 산출물에 보존한다.

인증서·공증 프로필은 사용자 준비 중이다. 실제 SDK 드래그·키보드·VoiceOver, 미완료 정리 기록의 재시작 후속 처리, 최신 후보 장시간 및 설치·지원 환경 검증은 계속 남아 있다.
