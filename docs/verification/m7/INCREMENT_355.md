# M7 Increment 355 — 분할 생성 화면과 복구 기록 연결

상태: 생성/복구 화면 연결·로컬 컴파일/headless 검증 완료. 새 원격 AppKit/지원 환경 수용과 M7 정식 출시는 미완료다.

## 사용자 동작

생성 화면에 원본 고정 버전의 분할 안 함 및 10/100/650/700/1024/2048/4092/4480/5120/8128/23040 MiB 선택을 추가했다. CD/FAT/DVD/Blu-ray 설명을 유지한다. 분할 선택은 7z 구성 요소를 포함한 앱의 7z에서만 활성화된다. ZIP 전환은 실효 선택을 분할 안 함으로 바꾸지만 저장된 7z 선택은 보존한다. 설정 재시작·내보내기/가져오기를 연결하고 잘못된 값의 가져오기는 전체 설정 변경 전에 거부한다. 구형 설정은 분할 안 함으로 복원한다.

[원본 생성 창 ViewModel](https://github.com/files-community/Files/blob/99951c66928c4da714da8b1dd46039421182cbab/src/Files.App/Dialogs/CreateArchiveDialog.xaml.cs)의 목록과 CanSplit을 직접 다시 확인했다. 분할 크기는 선택한 대상 폴더에 .001부터 생성하는 API에 전달하고 완료 창에는 실제 part 경로들을 표시한다. 설정 크기와 실제 전체 출력 8 GB 상한을 구분해 화면에 안내한다.

앱 메뉴의 ‘분할 압축 생성 복구’는 앱 전용 기록을 백그라운드에서 읽는다. 정상 시작에서 미완료 기록이 있으면 이 창을 연다. 단순 열기·목록 읽기는 파일을 되돌리거나 삭제하지 않는다. 대상 볼륨이 없더라도 검증된 기록의 위치/상태를 보여주며, 손상·링크·잘못된 형식의 기록은 경로 정보를 신뢰하지 않고 확인 필요 행으로 남긴다. 기록 폴더가 없으면 새로 만들지 않는다.

사용자는 기록·출력 위치를 Finder에서 열 수 있다. 확인 가능한 prepared/publishing/discarding 작업만 ‘부분 생성 되돌리기’를 활성화하고 별도 확인 창 뒤에 Core 복구를 요청한다. Core는 클릭 시 저널·lock·현재 identity/내용을 다시 확인한다. 완료 기록과 모호한 게시·building·손상 기록은 자동 삭제하지 않는다. 복구가 필요한 생성 오류와 보존 staging은 생성 창의 복구 버튼으로 연결한다. 지원 창의 검증된 7z 분할 작업은 생성·탐색·추출로 표시한다.

## 검증 범위

Core 검사는 분할 선택의 저장/재생성·내보내기/가져오기·구형 기본값·잘못된 값의 원자적 거부를 확인한다. 기록 검사는 빈 레지스트리 비생성, active lock, 연결되지 않은 대상, 실제 prepared rollback, 완료 기록, 손상/링크 기록과 외부 데이터 보존을 확인한다. 기존 SDK 생성·추출·취소·충돌·재시작과 번들 검사를 함께 수행한다.

원격 AppKit 검사 세 개를 추가했다. 원본 크기 목록과 포맷 전환/설정 복원, 실제 생성 창의 10 MiB 두 part 생성·후속 볼륨 추출 왕복, 완료 복구 기록 창/되돌리기 비활성 상태를 확인한다. 기대 전체 332개는 아직 실행 통과 결과가 아니다. 로컬 GUI와 장시간 시험은 실행하지 않는다.

## 남은 항목

새 원격 두 CPU/332개 UI 및 실제 되돌리기 확인창 조작 수용, 원본 전체 화면 대조, 실제 입력/VoiceOver, 큰 파일/RSS·메타데이터·SDK 격리·외부 환경과 정식 서명/공증은 미완료다. 인증서/공증 프로필은 사용자가 준비 중이다.

## 로컬 결과와 빌드 환경

최종 소스와 최종 Release 번들에서 SDK·Swift·번들 검사 40개가 각각 건너뜀 없이 통과했다. Debug 80.68초·최적화 Release 35.06초와 ad-hoc preview 번들의 서명/해시 검증이 통과했다. 이전 native 경계 91개 산출물과 최종 번들 helper/library의 바이트 해시가 모두 같음을 확인해 해당 근거를 재사용한다. parity 구조 감사·셸/Python 구문·공백 검사도 통과했다. [소스/결과/로그 해시](split-ui-355-verification.json)를 보존한다.

설치된 CLT의 Testing.framework 검색 경로를 임시 빌드 명령에 명시했다. 기본 엔진은 getcwd/open, 새 링크 드라이버는 Foundation 확장 속성 getxattr에서 대기하는 스택을 확인해 해당 빌드 PID만 종료했다. 최종 Debug는 native 엔진·공식 호환 옵션 `-disallow-use-new-driver`·디버그 심볼 제외로 검증했다. 저장소의 빌드 스크립트나 검사 성공 기준은 변경하지 않았다. 초기 한 검사에서 실제 경로 /private/var와 별칭 /var를 직접 비교한 단언을 수정하고 전체 40개를 다시 통과했다. 이를 기능 실패나 원격 UI 통과로 혼동하지 않는다.
