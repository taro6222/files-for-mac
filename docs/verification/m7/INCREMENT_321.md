# M7 Increment 321 — ACL 계정 조회와 저장 수명 관리

상태: 구현·Core·네 조합 파일 작업/전체 UI·Debug·Release 검증 통과. M7 출시와 Intel 기존 ACL 실패 원인 해결은 미완료다.

ACL을 수동 편집한 뒤 계정 규칙 추가를 누르면 계정 확인이 끝나기 전에 저장할 수 있던 경합을 수정했다. 조회 중에는 저장과 규칙 선택기를 비활성화하고 수동 편집 알림으로 저장이 다시 켜지지 않게 한다. 확인이 끝나면 최신 편집 내용에 규칙을 추가하고 저장 가능 여부를 다시 계산한다. 오류 시에도 편집을 재개할 수 있다.

권한 시트를 닫으면 계정 목록·소유자 목록·규칙 작업을 취소하고 세대 번호를 바꿔 늦은 응답을 배제한다. Core 계정 열거는 호출자 취소를 내부 작업에 전달하며 열거 시작·반복·결과 반환 시 취소를 검사한다. 이미 실행 중인 네이티브 조회나 직렬 잠금 대기를 즉시 중단한다는 보장은 없다.

DEBUG 회귀는 실제 시트에서 이미 저장 가능한 수동 ACL을 만든 뒤 계정 응답을 gate로 보류한다. 이때 저장 호출이 파일을 변경하지 않는지, 응답 후 실제 ACL 저장이 가능한지, 닫힌 시트에 응답해도 UI·파일이 바뀌지 않는지 확인한다. 검증용 임시 창은 ARC 소유와 닫기 해제가 겹치지 않도록 설정했다. 첫 실행의 모든 조건은 참이었으나 종료 충돌이 있었으므로 해당 실행을 통과로 집계하지 않는다.

기존 전체 UI의 계정 목록·규칙 확인 합산 5초 기준은 유지한다. 계정 목록 대기·규칙 확인·저장 요청 단계, 경과 시간, 대기 상태, 저장 버튼, ACL 전후 값을 보고서에 남긴다. 이 진단 추가와 로컬 경합 수정만으로 이전 Intel 실패 원인이 확정되거나 해결됐다고 판정하지 않는다.

인증서와 notarytool 프로필은 사용자 준비 중이다. 서명·공증, 지원 환경 전체 수용, 메모리 안정성·최신 소스 8시간, 이동 선택 전체 데이터 집계는 남아 있다.

최종 Swift 실행은 368개 중 성공 349개·환경 건너뜀 19개다. 취소된 사용자·그룹 조회의 결과 배제와 이후 정상 조회를 검사한다. 제한 실행기 10개, 네 조합 각각 파일 작업 UI 83개·전체 UI 283개, Debug·Release 빌드가 통과했다. 실제 볼륨 행렬은 이번 단계에서 재실행하지 않았으며 Increment 320 증거와 구분한다. [최종 소스·바이너리·검증 결과](acl-rule-state-verification.json).
