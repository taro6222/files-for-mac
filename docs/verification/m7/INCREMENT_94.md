# M7 Increment 94 — 독립 창과 네이티브 탭 부하 비교

장시간 검증에 `windows` 모드를 추가했다. `tabs`와 동일하게 주 창에서 폴더를 연 뒤 보조 브라우저의 목록과 폴더 감시 준비를 기다리고 닫는다. 보조 브라우저는 독립 창으로 표시하고 양쪽 창이 탭 그룹으로 합쳐지지 않았는지 검사한다. 두 모드 모두 보조 컨트롤러와 디렉터리 감시 객체의 해제를 검사하고 파일을 전송하지 않는다. `full`은 기존처럼 네이티브 탭과 파일 전송을 함께 실행한다.

```sh
bash scripts/verify-release-soak.sh 1800 /private/tmp windows
```

Apple Silicon macOS 27.2의 동일한 최적화 바이너리에서 네 부하의 25초 예비 시험을 실행했다. 잘못된 부하 이름과 0초 입력이 스크립트에서 종료 코드 2로 거부되는 것도 확인했다. 독립 창과 네이티브 탭의 30분 결과가 나오면 비교한다.

별도로, 상세 목록을 분리한 `9a65f0e`의 8시간 전체 부하에서 약 150분 시점에 참조 트리를 수집했다. AppKit의 `previousKeyViews` 사전 아래에 약 17.4 MB, 그 하위 `BrowserFileTable` 아래에 약 14.6 MB가 집계됐다. 이 수치는 `leaks --forkCorpse --noContent --referenceTree`가 보고한 도달 가능한 할당이다. [이전 참조 트리](INCREMENT_56.md)에서 확인한 경로가 상세 목록 분리 후에도 남아 있으며, 네이티브 탭과 독립 창의 증가는 별도로 비교한다.
