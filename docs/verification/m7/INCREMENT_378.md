# 378 — 실제 ARM UI 결과와 탐색 fixture 격리·복구 상세 표시

원격 [45873718296](https://github.com/taro6222/files-for-mac/actions/runs/45873718296)의 ARM 작업은 **실패**다. 4개 언어/외형 조합의 report와 캡처를 내려받았다. 각 조합에서 새 압축 편집·Undo/Redo·기록 관련 28개는 모두 통과했고, 별도 탭 경계는 각각 18개 통과했다. 그러나 모든 조합에서 `multiwindowCycles`와 `remainingWindowUsable`이 실패했고 en-dark에서는 `sevenZipBatchPlacement`도 실패했다. 이를 전체 성공으로 집계하지 않는다. Intel은 같은 실행에서 계속 진행 중이었다.

## 수정

압축 편집 시험의 첫 원본은 10,001개 행을 확인하는 탐색 fixture 안에 있었다. 편집은 설계대로 archive 옆에 private 복구 디렉터리와 이전 버전을 보존한다. 따라서 숨김 항목을 켠 순회에서 fixture의 행 수가 바뀌었다. 원격 cycle 결과도 숨김 표시를 켠 회차의 `restoredRows`만 false였다. 편집 시험을 별도 root의 복사본으로 옮겨 탐색용 원본/행 수를 유지한다. 백업을 삭제하거나 기대 행 수를 늘려 시험을 통과시키지 않는다. 각 회차의 실제 행 수·숨김 이름·위치를 추가 기록한다.

한 조합의 일괄 압축 배치는 기존 결과에 세부 오류가 없어 원인이 미확정이다. 세 배치 방식별 실행/성공·암호 입력 정리·실제 내용·상태·출력 위치·자식 이름을 기록하도록 추가했다. 기존 10초 기한과 성공 조건은 유지하며 오류를 무시하지 않는다.

캡처 검토에서 기록 상세 영역의 경로가 비어 보였다. 실제 텍스트 영역에 초기 크기·수직 확장·폭 추적/줄바꿈을 설정했다. 경로 문자열뿐 아니라 실제 표시 영역의 glyph가 존재하는지 확인하는 검사를 추가해 360→361개로 확장했다. 기존 검사는 유지한다. 편집 캡처에는 기존 창 배경색 합성을 사용해 투명 배경이 표시를 방해하지 않도록 했다. 이 수정 후 실제 캡처·조작은 아직 원격 수용 전이다.

## 검증 범위

Debug 33.33초·Release 18.17초 빌드가 통과했다. DEBUG 검증과 복구 상세 레이아웃 변경을 컴파일했다. Core·probe·엔진 시험은 376 기록과 hash가 같아 반복하지 않는다. workflow YAML/쉘 구문·공백 검사와 ARM 8개 보고서의 실제 조건을 확인했다. 로컬 GUI·장시간 앱은 실행하지 않았다. 수정 후 양 CPU 원격 결과, 일괄 배치 원인 확인과 전체 F23/M7 수용은 미완료다. [소스·실제 보고서 기록](archive-ui-acceptance-378.json).
