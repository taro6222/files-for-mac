# M7 Increment 301 — 실제 앱 강제 종료 후 수신 정리 복구 확인

상태: 실제 디버그 FilesMac 프로세스의 중단·재기동 검증과 위치 미확인 작업의 파일명 표시 보완. F17·M7 전체 완료가 아니다.

300단계의 새 controller 재조회 검증을 실제 두 프로세스 검증으로 확장했다. 첫 FilesMac은 독립 QA 저장소에 수신 파일과 receipt를 만들고 기존 CopyEngine으로 외부 복사본을 게시·검증한다. 정리 journal을 저장하고 실제 macOS 휴지통 이동이 완료된 다음, 이동 위치를 journal에 기록하기 직전의 디버그 체크포인트에서 대기한다. 실행기는 해당 자식 PID가 살아 있고 journal의 마지막 상태가 `verified`인지 확인하고 그 자식만 SIGKILL한다. 종료 코드 -9와 체크포인트를 보존한다.

두 번째 FilesMac은 다른 PID로 새로 시작하여 실제 디스크 기록을 읽는다. 원래 경로가 사라지고 이동 위치는 journal에 없는 상황을 `위치 확인 필요`로 표시한다. 휴지통을 스캔해 위치를 추측하거나 기록을 수정하지 않으며, 보관 위치 버튼을 막고 기록 파일 보기만 제공한다. 원본과 게시된 복사본의 바이트, 원래 디렉터리의 불필요한 재생성 방지, 중단 journal 미변경, 최소 창과 캡처를 확인한다.

위치 미확인 작업도 어떤 파일인지 알 수 있도록 새 정리 기록에 수신 파일명을 선택 필드로 저장한다. 예전 기록은 필드가 없어도 읽을 수 있고 실제 위치를 확인할 수 있는 작업은 기존 receipt의 이름을 쓴다. 파일명은 위치·내용 검증의 대체 증거로 쓰지 않는다.

QA 실행기는 별도 nonce 표식이 있는 임시 디렉터리만 사용한다. 휴지통 위치를 아는 별도의 QA 체크포인트는 제품 복구 로직에 넘기지 않는다. 검사가 끝나면 체크포인트의 디렉터리 identity가 그대로인 시험 보관본만 휴지통에서 QA 폴더로 회수한다. 사용자 휴지통을 비우거나 다른 파일을 삭제하지 않는다. 실패·시간 초과 시 같은 작업을 자동 재시작하지 않으며 증거와 원본을 남긴다.

이 체크포인트와 QA 진입점은 `#if DEBUG`로 제한한다. 정상 앱의 실행 경로에 강제 종료나 대기를 추가하지 않는다. 생성된 Xcode 프로젝트에도 새 QA 파일을 연결하고 두 CPU CI에 실제 프로세스 재기동 검증과 결과 보존을 추가했다.

한국어·영어, 밝음·어두움 네 조합에서 각각 14개 검사를 통과했다. 기존 수신·정리 계약 45개와 전체 Swift 305개 중 성공 287개·별도 환경 건너뜀 18개도 통과했다. 이 단계에서 전체 AppKit 283개를 다시 실행했다고 주장하지 않으며 직전 소스의 결과와 구분한다.

검증 범위는 이동 위치 기록 전의 중단이다. 위치가 기록된 중단 작업의 명시적 복원·재시도 UI, 다른 저장 단계의 프로세스 중단, 설치 앱·실제 키보드·VoiceOver·SDK 드래그 수용은 남아 있다. 인증서·공증 프로필은 사용자 준비 중이며 M7 정식 출시 완료 판정을 하지 않는다.

최종 Debug·Release 빌드가 성공했고 QA 환경 진입점 문자열이 Debug에 존재하며 Release에는 없음을 확인했다. 소스·앱 SHA, 실제 두 PID·SIGKILL 종료 코드, 원본 journal SHA와 결과는 [검증 기록](cleanup-restart-verification.json)에 저장한다.
