# M7 Increment 234 — SMB 게시 전후 파일 식별자 확인

[SMB 3.1.1 실마운트 시험](https://github.com/taro6222/files-for-mac/actions/runs/43668744130)에서 이름 변경 뒤 같은 열린 파일 디스크립터와 게시 경로가 동일한 새 inode 값을 보고했다. 복사 장부의 게시 전 inode는 게시 경로의 값과 달랐고 데이터·모드·확장 속성·ACL·생성 및 수정 시각은 일치했다. 이동은 게시된 대상의 식별자 검사에서 원본을 보존하고 중단했다.

SMB의 복사와 교차 볼륨 이동은 준비한 항목의 디스크립터를 게시 전부터 연 상태로 유지한다. 게시 경로와 열린 항목이 일치할 때 게시 후 식별자와 상태 변경 시각을 장부에 저장한다. 이동의 교체 대상 백업에도 이를 적용한다. 원본 재확인과 대상 내용·메타데이터 검증, 비덮어쓰기 게시가 이어진다. 기존 장부의 이전 식별자 형식도 읽는다.

Apple Silicon에서 FilesCore 빌드와 선택된 Swift Testing 시험 9개가 통과했다. 열린 파일을 이름 변경한 뒤 인식하고, 같은 바이트를 가진 교체 항목을 거부하는 검사, 기존 장부 호환, 교차 볼륨 교체 및 취소·메타데이터 변경 중 원본 보존이 포함된다. 실제 SMB에서 복사·이동·실행 취소·교체가 통과하는지는 재시험에서 확인한다.
