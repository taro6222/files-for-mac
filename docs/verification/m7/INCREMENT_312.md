# M7 Increment 312 — 교차 볼륨 이동의 바이트 표시

상태: 구현·로컬 실제 볼륨 UI 검증 통과. 새 소스 원격 수용은 진행 중이다. 전체 F12·UI-10 및 M7 출시는 미완료다.

교차 볼륨 이동의 임시 복사에 기존 네이티브 복사 어댑터를 연결했다. 현재 파일·폴더의 논리 데이터 바이트·예정량·백분율·평균 논리 속도를 이동 창에 표시한다. 클론과 희소 파일 정책은 복사와 같다. 같은 볼륨의 rename에는 바이트 전송을 만들어 표시하지 않는다. 백업·임시 복사·전체 내용/메타데이터 검증·비덮어쓰기 게시·원본 재검증·원본 삭제의 기존 순서와 Undo 저널 형식을 유지한다.

내용 검증·게시·원본 정리 이후 도착한 이전 복사 바이트는 화면을 되돌리지 않는다. 실제 다른 장치의 공개 이동 API에서 수집한 이벤트를 AppKit 구성요소에 재생해 바이트 문구와 늦은 이벤트 거부를 확인한다. 이 검사는 실제 입력·프레임 표시·VoiceOver 수용이 아니다.

새 네 시험은 폴더 바이트 합·내용 검증·Undo, 전송 중 취소 시 교체 대상 복원·원본 유지, 전송 중 원본 변경 시 게시와 원본 삭제 거부, 같은 볼륨 rename의 바이트 알림 부재를 검증한다. 코어 시험의 강제 교차 볼륨 분기는 실제 다른 장치 시험과 구분한다. 전체 Swift 337개는 성공 319개·환경 건너뜀 18개로 통과했다. Debug·Release 빌드도 성공했다.

기존 태그 시험에서는 열거 결과에 저장한 태그가 있었지만 새 URL의 별도 조회가 빈 값으로 반환돼 실패했다. 일반 파일과 같은 inode의 hard link는 fixture에 실제 저장한 두 태그를 직접 요구하도록 기준을 수정했다. 태그를 쓰지 않은 심볼릭 링크의 대상 태그 노출 여부는 native 해석 차이로 분리하며 일부 태그만 유실된 값은 허용하지 않는다. 제품의 태그 prefetch와 메타데이터 필드는 변경하지 않았다.
