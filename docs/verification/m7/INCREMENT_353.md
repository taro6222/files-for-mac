# M7 Increment 353 — 분할 7z의 볼륨 탐색과 추출

상태: 분할 기능 개발 중. 읽기·추출 경로의 구현/로컬 headless 검증 완료, 분할 생성·게시 저널/복구와 새 UI 원격 수용은 미완료다. M7 완료가 아니다.

## 동작

앱 안에서 `name.7z.001`, `.002` 등 표준 분할 볼륨을 7z로 인식한다. 어느 볼륨을 열어도 같은 폴더의 연속 볼륨을 숫자 순서로 찾는다. `.1000` 이후 번호도 처리하지만 현재 한도는 1,024개·합계 8,000,000,000바이트다. `.01`·`.0001`·`.000` 같은 비표준 이름은 그룹으로 해석하지 않는다. 부모 파일 시스템의 대소문자 구분과 Unicode 정규화를 반영해 같은 base 이름만 모은다. 다른 압축 파일의 볼륨을 포함하지 않는다.

처음/중간 볼륨 누락은 번호를 포함한 오류로 표시한다. 링크·폴더·빈 파일·잘못된 볼륨 길이·한도 초과는 출력을 만들기 전에 거부한다. 유효한 표준 32바이트 7z start header의 CRC와 선언한 전체 길이를 검사해 마지막 볼륨 누락/잘림을 별도 오류로 표시한다. SDK의 physical size/offset도 확인해 완성된 아카이브 뒤에 다른 볼륨을 붙여 읽는 것을 거부한다. SFX 등 첫 signature 위치가 다른 경우에는 SDK 결과로 판정하므로 모든 손상을 정확한 누락 번호로 분류한다고 주장하지 않는다.

SDK의 IInStream을 볼륨 FD들의 seek 가능한 연결 스트림으로 구현했다. 전체 아카이브를 합친 임시 복사본은 만들지 않는다. 모든 볼륨 FD를 유지하고 목록 반복/추출 전후에 각 FD와 경로의 identity·mode·size·mtime/ctime을 확인한다. 작업 중 교체/변경된 볼륨은 실패 처리한다. 필요한 경우 짧게 실행하는 helper 자신의 FD soft limit만 조정한다. 호스트/시스템의 제한을 변경하지 않는다. 입력 FD를 부모에게서 직접 전달하는 강화와 decoder 자원 격리는 별도 미완료 항목이다.

여러 볼륨을 함께 선택한 일괄 추출은 첫 볼륨 URL로 중복을 제거한다. child 폴더 이름은 `name.7z.001`에서 `name`으로 정한다. 기존 여기/스마트/child 게시·충돌 보존·취소 정리를 사용한다. SDK 없는 개발 실행은 분할 볼륨을 일반 libarchive로 조용히 넘기지 않고 필요한 구성 요소 오류를 표시한다. 지원 창의 7z 분할 열은 ‘탐색·추출’로 표시한다. 완전한 분할 생성/추출을 뜻하는 Core capability는 false를 유지한다. 일반 생성 API는 `.7z.001`에 분할되지 않은 파일을 저장하지 못하게 거부한다.

## 검증

- 실제 앱 번들에 포함된 signed helper/library를 사용한 Swift·SDK/번들 및 기존 배치 회귀 34개가 건너뜀 없이 6.610초에 통과했다. 새 세 함수는 Unicode/줄바꿈 이름·평문/암호화·두 번째/마지막 볼륨에서 열기·원문 복원, 16바이트 볼륨으로 쪼개진 헤더와 256개 초과 볼륨, 부모 FD 제한 보존을 확인한다. 누락·잘림·링크·한도와 일반 생성 API의 잘못된 `.001` 출력 거부도 검증한다.
- native SDK 프레임 검사 86개가 통과했다. 새 15개 조건은 배열 스키마·실제 전체 크기·같은 세션 반복 목록/추출·볼륨 경계를 넘는 데이터·열린 볼륨 교체·링크·마지막 누락·무관한 후속 볼륨 거부를 확인한다.
- 최종 Debug 30.17초, native Release 54.88초와 새 ad-hoc preview 번들의 서명/해시 검증이 통과했다. Xcode 프로젝트 재생성 결과 변경이 없다(Core는 로컬 Swift package로 자동 발견). parity 구조 감사·셸 구문·공백 검사가 통과했다.
