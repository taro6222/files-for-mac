# M7 Increment 358 — 압축 helper 메모리 초과 중단

상태: 부모의 메모리 관찰·초과 종료와 headless 검증 완료. 전체 권한/자원 격리와 M7 정식 출시는 미완료다.

## 동작

부모 앱이 `proc_pid_rusage(RUSAGE_INFO_V0)`의 `ri_phys_footprint`를 독립 Dispatch timer에서 관찰한다. 주기는 25ms, leeway는 5ms다. 기본 예산은 물리 메모리의 절반과 256MiB 중 큰 값이며 명시적 provider와 검증된 bundled factory 모두 같은 정책을 적용한다. 0바이트 예산은 실행 전에 거부한다. 압축 수준·사전·스레드 선택은 변경하지 않는다.

초과를 관찰하면 소유한 자식만 SIGKILL하고 `memoryLimitExceeded`를 반환한다. PID 관찰·종료·waitpid 회수는 같은 lock으로 보호해 회수 후 재사용된 PID를 건드리지 않는다. 취소·정상 종료·실패에서 timer를 정리하고, 응답 없이 멈춘 helper도 부모의 IPC 루프와 별도로 감시한다. 관찰 API의 ESRCH는 이미 종료 중인 자식으로 처리하며 그 외 오류는 자식을 종료하고 실패한다. 앱에는 한/영 오류 설명을 연결했다.

이는 할당 자체의 하드 상한이 아니다. 표본 사이와 스케줄링 지연에 순간 초과가 가능하며 단명한 peak 전체를 보장하지 않는다. helper가 만든 별도 자식이나 임의 파일/네트워크 접근을 제한하는 sandbox도 아니다. 메모리 추정값과 실측 footprint 예산은 서로 다른 값이다.

## 검증

새 Release 번들의 실제 SDK·서명을 사용하는 47개 검사가 건너뜀 없이 모두 통과했다. 32MiB 시험 예산과 PID 기록 후 런타임 64MiB 할당을 사용해 목록·추출·일반 생성·분할 생성 각각에서 메모리 오류, 자식 회수, 원본과 기존 파일 보존, 미게시와 임시 출력 정리를 확인했다. 0바이트는 자식을 시작하지 않는다. 기존 암호·여섯 수준·분할·취소·복구·브로커·번들 변경 거부도 통과했다.

Debug 최종 빌드 14.02초, 시험 제품 최종 재빌드 7.54초, Release 컴파일 32.87초와 새 preview 번들 구성/서명 검증이 통과했다. 로컬 GUI·전체 AppKit·장시간 시험은 실행하지 않았다. SDK C/C++ 소스는 변경하지 않아 357단계 native 경계 114개를 새 실행 결과로 재집계하지 않는다.

최초 메모리 fixture가 PID 기록 전에 할당할 수 있어 증거 파일을 잃던 실패를 보존했다. 할당량을 런타임 값으로 바꾼 뒤 네 경로를 통과했다. 다음 실행은 실제 47개가 통과했으나 SwiftPM 경고가 test 이름 사이에 섞여 검증기가 실패했다. stdout/stderr를 분리한 최종 실행에서 47개 증거 일치를 확인했다. 최초 패키징의 SwiftPM 중첩 sandbox 제한도 보존하고 새 출력 경로에서 패키징을 완료했다. [소스·결과·로그 해시](memory-budget-358-verification.json)를 따른다.

## 남은 항목

파일/네트워크 권한 격리, CPU와 프로세스 트리 자원 경계, 메타데이터 복원, 기존 1MiB 생성 계획 프레임 상한과 대용량 수용은 남아 있다. 이전 357 소스 CI는 이번 조회에서 두 CPU가 실행 중이었다. 최신 두 CPU/지원 OS·실제 입력/VoiceOver·원본 전체 UI 대조·정식 서명/공증 완료로 확대하지 않는다. 인증서/프로필은 사용자 준비 중이며 장시간 시험은 자동으로 재시작하지 않는다.
