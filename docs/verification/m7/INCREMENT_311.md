# M7 Increment 311 — 복사 중 논리 바이트 표시

상태: 구현·로컬 회귀 검증 통과. 새 소스의 원격 수용, F12·UI-10 전체 대응과 M7 출시는 미완료다.

복사 창에 현재 원본 항목의 전송 중 데이터 바이트·예정 바이트·백분율과 평균 논리 데이터 속도를 연결한다. 폴더에서는 각 일반 파일의 데이터 포크를 합산하며 외부 심볼릭 링크의 대상을 포함하지 않는다. APFS 클론은 쓰기 콜백 없이 완료될 수 있어 완료한 파일의 논리 크기를 집계한다. 표시값은 디스크나 네트워크의 물리 전송 속도가 아니며 여러 원본 전체의 바이트 가중 진행률과 구분한다.

macOS SDK의 `copyfile` 콜백을 사용한다. 최초 파일·폴더 복사에는 배타적 생성과 링크 비추적, ACL·확장 속성·통계·데이터 복사 및 클론을 적용한다. 희소 파일 옵션을 함께 지정하고 지원하지 않는 파일 시스템에서는 일반 데이터 복사로 대체한다. 콜백 오류를 건너뛰지 않고 전체 현재 복사를 실패시킨다. 콜백마다 취소를 확인하며 최초 안내에서 취소한 경우 네이티브 호출 전에 반환한다. UI 게시 빈도는 최초 데이터·종료를 제외하고 최대 초당 열 번이다. 예정 크기보다 실제 집계가 커지면 백분율의 기준을 숨긴다.

기존의 비공개 임시 디렉터리, 원본·복사본 전체 해시 및 메타데이터 재검증, 비덮어쓰기 게시, 저널·실행 취소와 취소 시 identity 기반 정리는 유지한다. 디렉터리 수정 시각 불일치가 시험에서 확인돼 원본 기준 시각을 임시 디렉터리의 비추적 디스크립터로 복원한 뒤 기존 검증을 수행한다. 링크로 바꾼 디렉터리를 통한 시각 변경은 거부한다.

이 단계는 `CopyEngine`과 복사 창에 적용한다. 같은 볼륨 이동의 rename 경로, 교차 볼륨 이동·폴더 병합·원격 프로토콜의 복사 엔진은 이번 변경에 포함하지 않는다. 이동·병합 및 모든 원본을 합산한 전송 UI와 실제 Windows 대비 수용은 남은 구현이다. 취소 반응·공개·원본 삭제의 보장 범위를 넓혔다고 주장하지 않는다.

## 최종 검증

- Debug·Release 빌드 성공. 고정 Debug SHA-256 `ede47de7d11e64bec238c0a8c70952d613572d4bebb4e3f9d45c820bdddc68dd`.
- 전체 Swift 333개 보고: 성공 315개·별도 환경 건너뜀 18개. 새 8개 시험은 클론/일반 복사 바이트 합, 외부 링크 비추적, 파일 중간 콜백 취소, 기존 대상 보호, 검증·Undo, 임시 정리·원본 보존, 디렉터리 시각 복원의 링크 거부, 잘못된 예정량 숨김·최초 안내 취소, 희소 파일을 확인한다. 매개변수 두 경우를 포함한다.
- 64 MiB 희소 파일의 강제 비클론 복사에서 전체 내용 일치와 실제 할당량이 논리 크기의 절반 미만임을 확인했다. 같은 시험에서 최종 논리 바이트도 일치했다.
- 제한 실행기 10개와 실제 APFS·대소문자 APFS·exFAT·FAT32·HFS+의 7개 시험 통과.
- 한국어/영어 × 밝게/어둡게 네 조합 각각 실제 마운트 파일 작업 UI 79개·전체 AppKit 283개 통과. 파일 약속 수신 계약 53개도 통과했다.
- 검증 진입 직후 프로그램 버튼 취소 40회의 화면 피드백은 최대 0.063911625초, 최종 정리는 최대 0.064885625초였다. 데이터 전송 중 실제 키보드 취소나 느린 서버의 I/O 종료 지연을 측정한 결과가 아니다.
- [최종 소스·바이너리·원본 보고서 해시와 수용 범위](native-copy-progress-verification.json). [한국어 어둡게](native-copy-progress-captures/ko-dark.png), [영어 밝게](native-copy-progress-captures/en-light.png). 캡처는 빠른 클론의 데이터 준비 100%에서 내용 검증에 들어가기 전 상태이며 물리 전송 프레임 검증이 아니다. 새 중간 바이트에서 취소하는 경로는 비클론 코어 시험으로 별도 확인했다.

## 이전 성능 실행의 후속 결과

`4a19117` Intel 최적화 QA는 첫 표시 p95 0.558091120초·모델 열거 p95 3.137665203초로 두 기준에 미달했다. [원본 표본](optimized-performance-4a19117-x86_64-report.json), [원격 판정](optimized-performance-4a19117-x86_64-assessment.json). 이 실행은 14 GiB 호스팅 장비다. 로컬 24 GiB 장비의 통과로 원격 실패를 대체하지 않으며 500ms·2초 기준을 유지한다. ARM은 첫 표시 p95 0.343047초·모델 열거 p95 1.544533250초로 통과했다. [ARM 원본](optimized-performance-4a19117-arm64-report.json), [ARM 판정](optimized-performance-4a19117-arm64-assessment.json). 두 CPU 모두 원본 표본 재계산이 원격 판정과 일치했다. 전체 workflow는 Intel 미달로 실패다. ARM의 7 GiB·Intel의 14 GiB 호스팅 결과를 기준 장비 수용으로 대체하지 않는다. 기존 전체 AppKit 실행은 별도로 수집한다.

인증서와 공증 프로필은 사용자 준비 중이다. 정식 배포·최소 OS·CPU·실제 접근성·외부 서버·장시간 메모리 안정성 수용도 남아 있다.
