# M7 Increment 326 — 앱에서 관리하는 탐색 탭

상태: 구현·Core·네 조합 UI·짧은 메모리 진단·Debug/Release 검증 통과. 최신 소스 원격·8시간·지원 환경·정식 배포 수용은 미완료다. M7 출시 완료가 아니다.

공개 네이티브 탭 API의 창 재사용·탭 그룹 유지·명시적 제목/도움말 지정으로 관찰 컨텍스트 증가를 제거하지 못했다. 이 단계에서는 각 BrowserWindow와 pane 상태를 보존하면서 앱이 탭 표시·선택·순서를 관리한다. 네이티브 탭 막대를 생성하지 않도록 탐색 창의 tabbingMode를 disallowed로 설정한다. 창·감시기 해제와 물리 메모리 안정성은 별도로 측정한다.

BrowserTabs의 구성원과 선택 항목은 약한 참조다. 전환할 때 선택 창의 프레임을 다음 창에 적용하고 이전 창을 숨긴다. 백그라운드 생성·이전/다음·닫기 후 인접 항목 선택·순서 변경·다른 창 그룹으로 이동·독립 창 분리·탭 드래그 분할을 연결한다. 드래그 취소와 앱 창 안의 거절된 드롭은 창 분리로 처리하지 않는다. 탭 막대는 40px, 항목은 180px이며 가로 스크롤·새 탭·목록 메뉴·접근성 레이블/선택 값/누르기 동작을 제공한다. 닫힌 컨트롤러를 셀에서 보유하지 않으며 재사용 셀도 제한한다.

생성 직후의 화면 확인에서 배경 확대 이미지가 목록 영역 밖까지 그려져 상단을 가리는 기존 문제를 발견했다. AppBackgroundView의 그리기를 자신의 bounds로 자른다. 단순한 창 표시 여부와 별도로 막대·셀의 실제 배치 검사와 네 언어/테마 캡처를 추가했다.

정식 인증서·공증 프로필은 사용자 준비 중이다. 이 단계의 짧은 메모리 진단은 최신 소스 8시간 안정성·Intel 기준 장비·물리 입력/VoiceOver·지원 OS·원본 전체 상태·실제 서비스·정식 서명/공증 수용을 대체하지 않는다.

초기 두 180초 진단은 같은 31사이클 뒤 감시기 연결 15초 기준 초과로 실패했다. 재실행은 8초간 진행이 없을 때 소유 프로세스의 스택을 보존했다. 메인 스레드는 이벤트를 기다렸고, GCD는 64개 스레드 상한에 도달했으며 창 애니메이션의 NSAnimation._runBlocking이 작업 스레드를 점유했다. 이 앱의 탭은 서로 다른 창을 숨기고 표시하므로 탐색 창의 animationBehavior를 none으로 지정한다. 대기 시간을 늘리거나 감시기 완료 조건을 생략하지 않는다. 실패 결과와 스택을 보존하고 수정 후 같은 작업을 다시 실행한다.

애니메이션 수정 후 같은 full 작업은 180.7초·66사이클로 정상 종료했다. 5·40사이클의 NSKeyValueDependencyContext는 1,036→1,036개, NSKeyValueDependency는 3,268→3,268개, BrowserWindow는 1→1개, NSStackView는 14→14개다. 실제 창은 Swift KVO 런타임 하위 클래스이므로 기본 BrowserTabWindow 이름이 없는 것을 0개로 집계하지 않는다. 사이클마다 닫힌 창·컨트롤러·감시기의 weak 해제를 확인했고 기본 감시기 해제 횟수는 66회다. 최대 물리 footprint는 62.24MiB, 최종은 약 50.05MiB였다. 8초 진행 정지 진단은 발생하지 않았다. 이는 짧은 진단 결과이며 최신 소스 8시간 안정성의 통과가 아니다.

앞 단계 f2aa7e6의 [원격 최종 결과](watcher-history-f2aa7e6-appkit-ci.json)는 전체 성공이다. ARM·Intel 각각 네 조합 전체 UI 283개, 두 Xcode 빌드와 업그레이드/복구 검증이 통과했다. 최적화 성능 작업은 이 실행에서 건너뛰었다. 앞 단계 성공을 이번 새 탭 소스의 원격 통과로 집계하지 않는다.

최종 검증은 Swift 380개 중 성공 361개·환경 건너뜀 19개, 제한 실행기 10개, 네 조합 전체 UI 각각 290개, Debug·일반 Release·최적화 QA 빌드와 프로젝트 생성·parity 목록 감사를 통과했다. 실제 볼륨 매트릭스는 이 UI 단계에서 다시 실행하지 않았으며 앞 단계 결과와 구분한다.
