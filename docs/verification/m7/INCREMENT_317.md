# M7 Increment 317 — Git 복제 시간 초과의 상태 보존과 취소 수습

상태: DEBUG 검증 흐름 보완·Swift·파일 작업 UI·네 조합 전체 UI·Debug·Release 빌드 통과. 새 원격 수용은 미완료다. Intel 지연 원인 해결과 M7 출시는 미완료다.

`740ebf4`의 Intel 원본 아티팩트 `files-appkit-macos15-x86_64`(ID 15066282478)를 확인했다. 한국어/밝게와 영어/밝게 모두 `gitCloneWindow=false`로 실패했고 어두운 두 조합은 각각 283개를 통과했다. 기존 Increment 316의 영어/밝게만 언급한 요약을 두 언어/밝게로 바로잡았다. [원본 상태·캡처·해시](git-clone-timeout-verification.json).

두 실패 캡처는 모두 복제 중 상태, 비활성 Clone 버튼, 활성 Stop 버튼이었다. 오류가 표시된 종료 상태는 아니다. 기존 검증은 20초 대기를 마친 뒤 성공 여부와 관계없이 창을 닫아 복제를 취소하고, 미게시 대상 안에 `qa-untracked.txt`를 쓰려다 ENOENT로 중단했다. 해당 오류만으로 실제 복제 명령의 실패 원인을 판정할 수 없다.

현재 검증은 같은 원본 저장소와 20초 복제 대기·전체 프로세스 예산을 유지한다. 대기 직후 실행 여부·상태 문구·완료 여부·경과 시간을 기록한다. 실패한 복제의 후속 파일 쓰기를 중단하고, 아직 실행 중이면 소유한 앱과 직접 자식 Git 프로세스(찾은 경우 최대 두 개)의 스택을 먼저 보존한다. 그 뒤 취소를 요청해 최대 5초 동안 종료를 기다리고 종료 여부·취소 후 문구를 기록한다. 오류는 복제 단계에서 명확하게 보고한다. 성공한 경우에만 기존 Git 열·파일명·상태 검증으로 진행한다.

DEBUG AppKit 검증은 gate가 해제되기 전에는 정상 종료할 수 없는 실제 자식 실행 파일을 GitProvider에 주입한다. 짧은 50ms 진단 대기 후에도 실행 중임을 확인하고 앱 스택을 저장한 뒤 실제 백엔드 취소를 수행한다. 완료 콜백 0회, 작업 수 복원, 대상 미게시, staging 제거와 취소 문구를 검사한다. fixture 자식에는 자체 상한도 있다. 실제 전체 복제 검증의 20초 기준을 이 짧은 진단 시험으로 교체하지 않는다.

새 생성자·대기/진단/fixture 코드는 DEBUG에만 포함된다. 일반 Release 심볼을 검사해 새 진단 함수와 검증 실행 파일 생성자가 없고 기존 Git clone 구현은 남아 있음을 확인했다. 사용자 복제 동작이나 Git 실행기 정책은 변경하지 않았다.

전체 Swift 347개 보고 중 성공 329개·환경 건너뜀 18개, 네 언어·외형의 파일 작업 UI 각각 80개·전체 AppKit 각각 283개와 Debug·일반 Release 빌드는 통과했다. 정상 로컬 복제 네 번은 각각 20초 안에 끝났으며 실제 Intel 20초 초과의 스택은 원격 재현 시 확인한다. 각 파일 작업 실행은 gate 자식의 진단 시간 초과 상태 보존·부모 스택 저장·취소 종료·staging 정리를 통과했다. 실제 볼륨 시험은 제품 복사 엔진을 바꾸지 않은 이 단계에서 반복하지 않았다. 이전 단계의 볼륨 증거와 새 검증을 혼합해 집계하지 않는다.

원본 캡처의 투명 배경 때문에 검은 텍스트가 보이지 않아 진단용 흰 배경 합성본도 별도로 보관했다. 합성본은 원본 캡처를 대신하거나 시각 대응 합격 증거로 사용하지 않는다. 원본과 합성본의 해시를 각각 기록한다.

Intel 지연의 실제 스택·재현·해결, 전체 선택 바이트 합계, 잔여 메모리 증가·최신 소스 장시간, 성능·실제 접근성·정식 서명·공증 수용은 남아 있다.
