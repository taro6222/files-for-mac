# M7 Increment 06 — 대형 폴더 Release 계측과 메모리

- `scripts/verify-release-performance.sh`는 최적화 빌드에 검증 전용 진입점을 추가해 실행한다. 배포용 빌드는 이 진입점을 포함하지 않는다.
- 실제 AppKit 창에서 빈 텍스트 파일 10,000개를 20회, 100,000개를 3회 읽는다. 각 표본은 독립 프로세스에서 수집한다. 썸네일은 끄고 OS 캐시는 따뜻한 상태로 유지한다.
- 시작 시간은 프로세스 생성 요청부터 홈 창이 표시되고 사이드바에 포커스가 잡힐 때까지다. 검증 진입점은 메뉴 구성과 사용자 세션 복원을 건너뛴다. 첫 목록 표시는 행 100개 이상이 등록되어 가시 영역을 갖는 시점이다. 전체 표시는 마지막 배치 수신과 AppKit 레이아웃까지 포함한다.
- RSS는 폴더를 읽는 동안 주기적으로 샘플링한다. 유휴 RSS는 기본 창 하나를 5분 유지한 뒤 기록한다. 화면 합성 프레임, 장시간 메모리 추세, 실제 배포 앱의 콜드 시작은 아직 검증 대상이다.
- Foundation의 디렉터리 열거기가 미리 읽은 메타데이터를 사용하고 각 항목을 처리한 뒤 임시 Objective-C 객체를 해제한다. 파일 작업에 넘기는 URL은 메타데이터 캐시가 없는 별도 URL로 만들며, 파일 식별자 형식은 유지한다.

## 측정 결과

Apple Silicon, 메모리 24GiB, macOS 27.2 (26B123), APFS. 두 측정 동안 다른 로컬 검증 작업도 실행됐다. 전체 표시 시간은 파일시스템 열거와 UI 갱신을 합친 값이다.

| 지표 | 기준 | 변경 후 |
|---|---:|---:|
| 10,000항목 시작 p95 | 202 ms | 224 ms |
| 10,000항목 첫 표시 p95 | 123 ms | 136 ms |
| 10,000항목 전체 표시 p95 | 2.122 s | 2.607 s |
| 10,000항목 최대 샘플 RSS | 332 MB | 180 MB |
| 100,000항목 첫 표시 최댓값 (3회) | 126 ms | 154 ms |
| 100,000항목 전체 표시 범위 (3회) | 20.78–23.07 s | 27.35–29.43 s |
| 100,000항목 최대 샘플 RSS | 1,623 MB | 366 MB |

10,000항목 전체 표시 시간은 2초 기준을 넘는다. 메모리 개선을 유지하고 전체 표시 시간은 별도 개선 과제로 남긴다. 세 번 측정한 100,000항목 결과는 관측된 범위다.

5분 유휴 RSS는 기준 69 MB, 변경 후 86 MB였다. [기준 원시 표본](performance-release-baseline.json) · [변경 후 원시 표본](performance-release-optimized.json)

Swift Testing 201개, 한·영 두 테마의 AppKit 각 218개, 실제 APFS·대소문자 구분 APFS·exFAT 검증 3개가 통과했다. 갱신한 유니버설 DMG는 체크섬, 읽기 전용 마운트, 두 슬라이스 코드 서명 및 Apple Silicon 기동을 확인했다. 배포 이미지의 바이너리에서 성능 검증용 환경 변수 진입점이 제외된 것도 확인했다.
