# M7 Increment 351 — 7z 암호 생성과 생성 화면 연결

상태: 구현·로컬 headless 검증 완료, 새 UI의 원격 수용 대기. M7 정식 출시 완료가 아니다.

7z 저장 시 검증된 번들 SDK를 선택하고 여섯 압축 수준, Unicode 암호, 선택적인 파일 이름 암호화를 생성기에 전달한다. ZIP의 기존 생성은 유지한다. SDK가 없는 개발 실행에서는 일반 7z만 지원하고 암호 생성을 활성화하지 않는다. 선언된 SDK 검증 실패는 오류로 표시한다. 지원 창의 7z 암호 열은 검증된 SDK가 있으면 ‘생성·추출’로 표시한다. libarchive만을 위한 Core의 정적 password capability는 false를 유지하며 SDK 생성 API의 계약과 구분한다.

SDK worker의 create 요청은 기존 길이 프레임과 private 요청 파이프를 사용한다. 암호는 명령 인자·환경·로그에 넣지 않는다. 부모가 0600·O_EXCL로 만든 seekable 파일 FD만 출력으로 전달한다. helper는 경로로 결과 파일을 만들지 않으며 출력은 8 GB로 제한한다. 원본 목록은 기존 Core 경로/총량 validator를 통과해야 하고, 1 MiB 요청 프레임 한도도 적용한다. 현재 생성 스레드는 SDK에 2개를 요청하며 사용자 지정 스레드/사전/워드/분할 옵션은 아직 연결하지 않았다.

각 원본의 device/inode/mode/size/mtime/ctime을 전달한다. helper는 모든 경로 구성요소에서 symlink를 따라가지 않고 파일을 열며, stream 읽기 전·후 및 전체 생성 후 원본 일치를 확인한다. 부모는 게시 직전에도 계획을 재검증한다. Foundation이 `/var` 별칭을 보존하는 동작은 realpath로 정규화해 정상 임시 폴더가 거부되지 않게 했다. 원본 내부에 결과를 만드는 순환 생성과 링크·중복 경로는 거부한다. SDK 입력 경로를 parent FD로 직접 전달하는 강화와 자원/권한 격리는 별도 미완료 항목이다.

SDK의 성공 응답·정상 프로세스 종료·출력 FD identity·부모 디렉터리 identity를 확인한 다음 RENAME_EXCL로 게시한다. 기존 대상이나 게시 중 생긴 외부 파일을 덮지 않는다. 취소 시 소유한 helper를 회수하고 소유 inode와 같은 임시 파일만 지운다. 여러 생성 결과의 저널·전원 장애 복구를 보장하지 않는다.

생성 창은 실행 중 닫기를 취소 요청으로 처리하고 정리 후 닫는다. 게시가 이미 성공한 뒤 늦은 취소가 오더라도 창을 무한 실행 상태로 남기지 않는다. 생성 옵션에는 암호 표시/정리와 7z 파일 이름 암호화 선택을 연결했다. 원격 AppKit 검사에 실제 화면 생성→암호 요구→복원 확인을 추가했다. 350단계의 여섯 신규 검사를 반영하지 못한 verify-ui.sh의 이전 318개 단언을 새 총 325개에 맞췄다. 수량 변경만으로 UI 통과를 주장하지 않는다.

## 검증

native SDK/번들 검사 27개가 건너뜀 없이 5.298초에 통과했다. 여섯 수준의 생성 결과를 공식 7-Zip 26.06에서 복원해 Unicode/줄바꿈 이름과 빈 폴더·원문 일치를 확인했다. 암호 없음/Unicode 암호, 파일 이름 암호화 켜기·끄기, 틀린 암호 거부도 검사했다. 새 세 검사는 링크·중복/원본 내부 저장 거부, 게시 전 원본 변경과 대상 경쟁 시 외부 데이터 보존, 취소 후 임시 출력 정리를 확인한다. 실제 새 Release 번들에서 resolver를 거친 암호 생성→추출도 통과했다. 기존 목록/추출·IPC EOF·취소/기한·번들 변조 거부 회귀를 포함한다.

최종 Debug 빌드 12.52초, 새 native Release 앱 빌드 54.89초와 ad-hoc preview bundle 서명/해시 검증이 통과했다. Xcode 프로젝트 재생성 결과 변경이 없음을 확인했다. Core는 로컬 Swift package 제품을 참조하므로 신규 파일을 자동 발견한다. 전체 Core 및 로컬 GUI/장시간 시험을 반복하지 않았다. parity 구조 감사(202명령·143설정·33화면), 셸 구문, git diff 공백 검사도 통과했다. [결과와 소스 해시](archive-creation-351-verification.json)를 보존한다.

350 원격 실행 45791755783은 마지막 조회에서 두 CPU 모두 Build app and test targets 단계 실행 중이었다. 아직 성공으로 집계하지 않는다. 351의 새 생성 UI 조건을 포함한 원격 수용도 별도 진행한다.
