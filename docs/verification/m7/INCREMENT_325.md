# M7 Increment 325 — 이벤트 이력으로 초기 목록의 중복 재조회 줄이기

상태: 구현·Core·다섯 실제 볼륨·네 조합 UI·Debug·Release 검증 통과. 최신 Intel 실패 해결과 M7 출시는 미완료다.

기존 기본 창은 감시기 등록이 끝나면 변경 유무와 관계없이 전체 목록을 다시 읽었다. 등록 시 목록을 읽는 중이면 재조회가 예약돼 첫 읽기 직후 다시 시작했다. 이 중복은 목록 준비와 폴더 크기 작업을 지연시킬 수 있다. 이전 Intel 실패의 모든 원인이 이 경로라고 확정하지는 않는다.

이제 BrowserModel이 실제 열거 전에 배경 파일 시스템 작업으로 읽기 토큰을 준비한다. 토큰은 정규 경로·장치·이력 UUID·현재 이벤트 ID를 묶는다. 준비 통지는 일반 목록 변경 통지와 분리해 빈 목록 렌더를 추가하지 않는다. 준비 중 새 탐색이나 취소가 들어오면 이전 로더를 시작하지 않는다. 늦게 붙은 뷰도 같은 읽기의 토큰을 사용한다.

내부 볼륨의 유효한 이력이 있고 등록 시 경로·장치·UUID가 그대로일 때만 읽기 전 이벤트 ID부터 재생한다. 이 경우 등록만으로 두 번째 열거를 요청하지 않고 실제 변경 이벤트가 올 때 전체 목록을 읽는다. 외부·네트워크 볼륨, 이력 불가·불일치, 기존 SinceNow 사용자 정의 factory는 원래의 등록 후 재조회를 유지한다. 보조 pane도 재생 또는 재조회로 등록 공백을 처리한다. 이벤트 유실·ID 순환·루트 변경은 재조회 힌트로 처리한다. 이력 완료 표식인 HistoryDone은 의미 없는 경로를 해석하지 않고 건너뛰며, 같은 이벤트에 유실/루트 변경 표시가 있으면 재조회를 우선한다.

이는 메타데이터 키·태그·클라우드 상태·정렬을 생략하거나 목록을 완전히 읽었다고 먼저 표시하는 변경이 아니다. 같은 경로 탐색의 새 읽기와 명시적 새로고침도 유지한다. 이벤트 ID는 [시스템의 최근 이벤트 ID](https://developer.apple.com/documentation/coreservices/1442917-fseventsgetcurrenteventid)를 사용하며, [이력 UUID가 없으면 SinceNow 이외의 시작점을 사용하지 않는 조건](https://developer.apple.com/documentation/coreservices/1444453-fseventscopyuuidfordevice)을 따른다. [변경 감시·재스캔 지침](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html)처럼 읽는 중의 실제 변경도 재조회한다.

감시기 생성·중지도 GCD로 옮겨 동기 경로 해석·FSEventStream 작업이 Swift 협력 실행기를 점유하지 않게 한다. 이미 시작한 네이티브 호출은 안전 지점에서 끝나며 취소된 작업의 늦은 결과는 폐기한다. 느린 factory 검증은 작업 시작을 확인한 뒤 홈으로 이동해, 아직 시작하지 않은 작업을 건너뛴 결과를 늦은 결과 폐기 성공으로 잘못 집계하지 않는다. 두 탐색 호출의 합산 0.4초 기준과 폴더 크기 검사의 5초 기준은 유지한다.

새 Core 검사는 등록 전 생성·수정·삭제의 실제 이력 재생, 토큰 없는/다른 경로 토큰의 재조회 필요, 목록 읽기 뒤 감시기 부착, 준비 통지 중 새 탐색 시 이전 로더 미실행을 확인한다. 이력 검사는 내부 임시 볼륨의 실제 지원을 명시적 조건으로 사용한다.

최신 원격 Intel 재수용, Git 창 실패 원인, 제품 메모리 안정성·최신 소스 8시간·지원 환경·실제 서비스/접근성·원본 UI 상태 대조·정식 서명·공증은 남아 있다. 인증서와 공증 프로필은 사용자 준비 중이다.

변경 전 [이동 소스 `7651b8f` 최종 CI](move-selection-7651b8f-ci-final.json)는 ARM·두 Xcode 성공, Intel 한국어 밝게의 폴더 크기 두 검사 실패로 전체 실패다. 나머지 Intel 세 조합은 각각 283개 성공이며 Git 검사는 네 조합 모두 성공했다. 이 기준 소스와 이번 수정 소스의 결과를 구분한다.

이전 측정기 `f9e4f02`의 짧은 원격 진단은 두 CPU에서 성공했다. [Intel 40사이클·한 반복 결과](native-tab-f9e4f02-intel-short.json)는 독립 창 17→17개, 탭 71→211개다. 최초 힙 시간 초과의 원인이 밝혀진 것은 아니며 400사이클·제품 메모리 안정성 통과로 확대하지 않는다.

최종 Swift 380개 중 성공 361개·환경 건너뜀 19개, 실제 볼륨 시험 8개·제한 실행기 10개·네 조합 각각 파일 작업 UI 85개·전체 UI 283개, Debug·Release 빌드가 통과했다. 네 전체 UI에서 10,000개 목록 준비와 자동/수동 폴더 크기 21바이트를 확인했다. `HistoryDone` 경로를 읽지 않는 별도 이벤트 분류 검사도 포함한다. [최종 소스·바이너리·진단·보고서 해시](watcher-history-verification.json).
