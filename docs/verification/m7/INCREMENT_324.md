# M7 Increment 324 — 동일 바이너리의 SDK·런타임 대조와 힙 시간 초과 진단

상태: 로컬 비교·소유 자식 종료·정상 힙 수집 경로 검증 완료. 제품 메모리 해결 및 M7 출시는 미완료다.

이전 독립 AppKit 재현의 [원격 실행](https://github.com/taro6222/files-for-mac/actions/runs/45727101467)은 ARM 성공·Intel 실패로 전체 실패다. ARM은 Swift 6.2.4·SDK 26.2·최소 대상 14.0 바이너리로 macOS 15.8.2에서 세 번씩 독립 창과 탭을 400사이클 측정했다. Intel macOS 15.7.9는 첫 창 5사이클의 힙 수집에서 `heap -s`가 20초 시간 초과해 클래스 관측을 얻지 못했다. Intel 메모리가 안정적이거나 증가했다고 판정하지 않는다.

원격 ARM 바이너리의 커밋·소스·SHA-256·ad-hoc 서명을 확인한 뒤 같은 실행 파일을 macOS 27.2.1에서 세 번씩 측정했다. 바이너리 SHA-256은 양쪽 모두 `8e933a1401eee7d1ba37704b64051a232152222f8abb11e2150064459bdd6f4f`다.

| 빌드·실행 조합 | 독립 창 컨텍스트 5/40/400 | 탭 컨텍스트 5/40/400 |
|---|---|---|
| SDK 26.2 바이너리 / macOS 15.8.2 ARM | 17 / 17 / 17 | 71 / 211 / 1,651 |
| 동일 SDK 26.2 바이너리 / macOS 27.2.1 ARM | 104 / 104 / 104 | 413 / 1,113 / 8,313 |
| 앞선 SDK 27.2 빌드 / 동일 macOS 27.2.1 호스트 | 104 / 104 / 104 | 413 / 1,113 / 8,313 |

모두 세 번 같은 계수 추세가 관측됐고 각 새 창 400개는 해제됐다. SDK 26 빌드만으로 현재 호스트의 증가가 사라지지 않았으며, macOS 27에만 나타나는 현상도 아니다. 같은 원격 바이너리의 두 실행은 소스·컴파일러·SDK 차이를 제거하지만 OS 외에 호스트 환경도 다르므로 단독 OS 결함 귀속을 확정하지 않는다. 계수를 제품 물리 메모리 바이트나 전체 증가 원인으로 환산하지 않는다.

공개 API 대조도 따로 측정했다. [같은 보조 창을 재사용](native-tab-reuse-window.patch)하면 의도적으로 창 두 개를 보유하며 518→1,218→8,418개로 증가했다. [실제 부착 뒤 탭 그룹을 유지·직접 추가](native-tab-reuse-group.patch)한 대조는 보조 창 해제를 유지했지만 385→840→5,520개로 증가가 남았다. 이 단일 대조의 감소를 제품 개선이나 안정성 통과로 적용하지 않는다. 그룹 생성 전 nil을 강제 언래핑했던 최초 실험 종료는 제외하고, 실제 부착 뒤 그룹을 확보하는 대조만 집계했다. 패치는 제품이 아닌 별도 재현 복사본에만 적용한다.

측정기는 기존 실제 `heap` 20초 기준을 유지한다. 시간 초과 시 소유한 힙 도구의 PID·상태·스택을 제한 시간 안에 보존하고 그 자식만 종료한 뒤 원래 시간 초과를 전파한다. 대기 중인 원본 재현의 다음 체크포인트를 승인하지 않는다. 소유한 가짜 힙 자식의 1초 시간 초과 시험에서 진단 보존·자식 종료·실패 전파를 확인했다. 이는 실제 20초 기준을 바꾸는 옵션이 아니다. 실제 AppKit 창/탭 각 40사이클 정상 경로도 현재 측정기로 통과했다.

수동 workflow는 전체 기본값 400사이클·세 반복을 유지하고 원인 조사용 40사이클·한 반복을 선택할 수 있다. 요청한 사이클·반복 수를 결과에 기록한다. 짧은 진단을 전체 반복이나 제품 수용으로 표시하지 않는다. Python/YAML 검사와 제품 Sources·Package·Xcode 프로젝트 차이 없음을 확인했으며 제품 전체 시험은 이번 진단 수정에서 재실행하지 않았다. [소스·바이너리·원격/로컬 결과·대조·시간 초과 근거](native-tab-sdk-runtime-comparison.json).

[ACL 소스 `51ce8dd` 전체 CI](acl-51ce8dd-ci-final.json)는 ARM 검증·두 Xcode 성공, Intel 실패로 종료했다. Intel ACL 계정 규칙은 네 조합 모두 5초 안에 저장 요청까지 도달했다. 한국어 밝게/어둡게는 폴더 크기 자동 계산·상세 패널 요청이 실패했으며 당시 목록은 10,000개에 도달하지 않았다. 한국어 밝게의 Git 창 검사도 실패했다. 영어 두 조합은 각각 283개 성공이다. 기존 ACL 실패 원인이 밝혀졌거나 현재 전체 CI가 성공했다고 표시하지 않는다. 폴더 목록 지연과 Git 검사 실패는 다음 조사가 필요하다.

최신 이동 소스 `7651b8f`의 원격 전체 검증 종료, 메모리 해결·최신 제품 소스 8시간·지원 환경·실제 서비스/접근성·원본 전체 UI 대조·정식 서명·공증 수용은 남아 있다. 인증서와 공증 프로필은 사용자 준비 중이다.
