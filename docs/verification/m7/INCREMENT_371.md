# 371 — 압축 편집 앱 연결 진행 중

F23의 개발 중간 기록이다. **사용자가 화면에서 압축을 수정하는 기능은 아직 완료하지 않았다.**

## 이번 구현

- 실제 App Sandbox helper에 ZIP/7z 편집 세션과 묶음 계획 전송을 연결했다. 원본은 읽기 전용 FD 하나로 받으며 추가 파일은 결과 인덱스로 요청한 읽기 전용 FD만 받는다. 임의 경로를 받지 않는다.
- `edit-open → list → edit-begin → edit-items → edit-commit` 순서와 세션/업로드 UUID·개수·오프셋·정확한 요청 필드를 검사한다. 프레임 1MiB, 배치 256항목, 전체 계획 256MiB/10만 항목 상한을 유지한다. 계획 업로드 중 출력은 비어 있고 중도 close는 원본을 보존한다. 편집 중 예상하지 않은 EOF는 성공으로 처리하지 않는다.
- Swift의 공통 편집 계획과 내부 `writeEditCandidate`를 실제 helper에 연결했다. 폴더 이름 변경·삭제는 정확한 하위 경계로 확장하며 암시적 폴더도 처리한다. 새 파일·폴더의 충돌, NFC 중복, 경로 이탈, 파일/링크 아래 하위 항목을 거부한다. 기존 링크는 호스트에 풀지 않는 불투명 항목으로 보존한다.
- 편집 입력은 최종 archive 링크를 따라가지 않는다. 기존 읽기 동작은 유지하며 추가 입력 snapshot·원본 identity·취소/기한·자식 회수 계약을 재사용한다. 별도 출력 FD만 쓰며 반환 뒤 원본을 교체하지 않는다. 암호는 stdin 통신만 사용한다.

## 검증

최종 소스의 Debug 10.27초·Release 16.98초 빌드와 최종 패키지 검증이 통과했다.

| 범위 | 결과 |
|---|---|
| Swift 클라이언트 및 번들 정책 | 60개 통과 |
| 실제 App Sandbox helper | 87개 통과 |
| 비격리 SDK/helper 진단 | 179개 통과 |
| 네이티브 편집 probe | 83개 통과 |
| OS 권한 probe | 15개 통과 |

Swift에서 만든 비암호 ZIP/7z·ASCII 암호 ZIP·Unicode/헤더 암호 7z를 편집해 공식 7-Zip으로 복원했다. 이름 변경·삭제·추가 파일/폴더와 원본 bytes 보존, 추가 파일 내용, 링크 입력 및 잘못된 계획 거부를 확인했다. helper 검증에는 잘못된 세션/순서/오프셋/타입/추가 필드, 업로드 누락·EOF·중도 close, 잘못된 경로 거부가 포함된다. 기존 생성·읽기·취소·복구 회귀도 유지한다.

네이티브 단독 probe의 `productIPCExercised: false`는 그 probe의 검증 범위다. 제품 IPC 동작은 위의 별도 실제 helper/Swift 보고서로 확인한다.

## 남은 연결과 알려진 실패

전체 편집본의 내용·metadata 독립 검증, 원본의 안전한 교체·백업·저널/재시작 복구·Undo, Unicode AES ZIP 새 암호 데이터 추가, 실제 편집 UI 및 해당 입력/오류 수용은 남아 있다. 내부 candidate API를 제품 편집 완료로 집계하지 않으며 모든 update capability는 false다. F23와 M7은 진행 중이다. 인증서/공증 프로필은 사용자 준비 중이다.

이전 소스 `9340c1b`의 원격 실행 [45858253029](https://github.com/taro6222/files-for-mac/actions/runs/45858253029)에서 Intel의 한국어/밝은 테마 `gitCloneTimeoutCleanup` 검사가 false였다. 압축 패키지 단계까지 도달하지 못했으므로 원격 압축 편집 검증 성공으로 집계하지 않는다. 실패 원인은 아직 확정하지 않았다. 이번 로컬 통과로 그 실패를 해결했다고 표시하지 않는다.

로컬 GUI·전체 AppKit·장시간 시험 앱은 시작하지 않았다. [검증 기록](edit-client-371-verification.json)에 소스·보고서 해시와 범위를 보존한다.
