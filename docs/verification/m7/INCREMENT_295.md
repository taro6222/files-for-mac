# M7 Increment 295 — 파일 약속 수신과 복사 UI 연결

상태: F17 수신 개발 진행 중. 기본·보조 창의 상세·목록·그리드·열 보기에 외부 앱의 `NSFilePromiseReceiver`를 연결했다. 내부 URL 이동은 기존 경로로 처리하고 외부 파일 약속은 복사로 받는다. 드래그 호버에서는 타입만 확인하며 파일 제공을 요청하지 않는다.

수신 창은 수신기마다 독립된 `PromisedFileIntake`를 만들고 SDK의 coordinated read 콜백 안에서 경로·identity·내용·메타데이터를 등록한다. 서로 다른 제공자가 같은 파일명을 보내도 보관 단계에서 덮어쓰지 않는다. 파일 해시와 보관소 생성은 UI 스레드 밖에서 수행하며 SDK 콜백 큐의 동시 실행은 두 개로 제한한다.

SDK가 파일 수를 알려주고 모든 콜백이 성공하면 기존 충돌 정책 화면으로 전달한다. 파일 수를 알 수 없는 구형 약속이나 일부 실패는 완료로 추정하지 않고 받은 항목을 사용자가 복사할 수 있게 한다. 정책 취소나 브라우저 종료·다른 작업 실행 중에는 제출 상태로 바꾸지 않는다. 작업 센터에서 진행 상태와 자동 복사 중지를 볼 수 있다. 중지는 안전 지점에서 검증을 멈추며 외부 앱의 내보내기 자체를 강제로 취소한다고 표시하지 않는다.

기존 복사 엔진은 받은 데이터의 원래 기록을 복사 전·게시 전 다시 확인한다. 정책 선택 중 내용이 바뀌었거나 등록되지 않은 소스가 섞이면 거부한다. 폴더 병합도 계획 전후에 수신 기록을 확인한다. 독립 수신기의 같은 파일명은 양쪽 유지 정책으로 함께 복사하고 하나의 실행 취소 기록으로 묶인다. 기존 복사 창의 실패 항목 재시도에서도 수신 기록을 유지한다.

받은 파일은 취소·오류·창 닫기 뒤에도 보존한다. 수신 창의 ‘보관된 파일 보기’에서 접근할 수 있다. 승인된 복사 요청은 수신 창에서 중복 제출하지 않으며, 실패 뒤에는 기존 복사 창의 재시도 또는 보관된 파일로 다시 작업한다. 콜백이 남아 있는 수신기는 창을 닫아도 종료될 때까지 유지한다. 자동 보관소 삭제와 재시작 복구 화면은 아직 구현하지 않았다.

검증: 앱·테스트 빌드, 복사·병합·수신 관련 51개 시험, 네이티브 AppKit 계약 24개, 대응표 감사가 통과했다. 신규 4개 코어 시험은 수신 후 변경, 같은 이름의 독립 수신기 배치 복사·단일 Undo·원본 보존, 병합 전 변경 거부, 등록되지 않은 소스 거부를 확인한다. AppKit의 신규 6개는 실제 수신 기록을 사용한 프로덕션 handoff 호출로 정책 취소 재시도·배치 전달·승인 기록·중복 제출 방지·중지 보존·등록 타입을 확인한다. **이 검사는 SDK 실제 드래그 전달 성공을 뜻하지 않는다.** [소스 해시와 검사 결과](promise-receive-ui-verification.json).

별도 진행 중이던 소스 `390cdb9`의 macOS 15 Apple Silicon 전체 작업이 통과했다. 전체 AppKit은 한국어·영어와 밝음·어두움 네 조합에서 각각 283개 검사다. 이 결과는 이번 수신 UI 소스의 전체 UI 회귀 결과로 간주하지 않는다. Intel의 같은 실행은 확인 시 전체 AppKit 진행 중이었다. [Apple Silicon 원본 보고서 요약](full-appkit-390cdb9-arm64.json).

사용자는 Developer ID Application 인증서와 notarytool 프로필을 준비 중이라고 답했다. 정식 서명·공증은 계속 열린 출시 게이트다. 실제 마우스 드래그 전달, 재시작 복구 화면, 검증된 보관소 정리, 새 수신 UI의 언어·테마·접근성 수용도 남아 있다. M7이나 F17 전체 완료로 판정하지 않는다.
