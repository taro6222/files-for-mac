# M7 Increment 294 — 파일 약속 수신 저장소

상태: F17 수신 개발 진행 중. 수신 파일의 보존·검증·복구를 맡는 코어 저장소를 추가했다. AppKit 수신 콜백, 각 보기의 드롭 연결, 복사 결과와 연동한 보관소 정리 및 실제 드래그 수용 검증은 후속 구현 항목이다.

`PromisedFileIntake`는 앱 전용 저장소 아래 고유 작업 폴더와 비공개 수신·기록 폴더를 만든다. 사용자 대상 폴더로 직접 수신하지 않는다. 수신 콜백에서 사용할 등록 메서드는 지정된 수신 폴더의 직접 항목만 허용한다. 파일·폴더·심볼릭 링크의 identity, SHA-256 기반 내용·권한 스냅샷, 생성·수정 시각과 확장 속성·ACL을 기록하고 복사 준비 시 다시 검증한다. 일반 탐색 로직이나 사용자의 기존 파일을 변경하지 않는다.

헤더는 변경하지 않으며 파일마다 독립된 기록을 원자적으로 저장한다. 새 항목마다 전체 누적 기록을 다시 인코딩하지 않는다. 재시작 시 헤더·폴더 identity, 기록 파일명과 항목 이름을 검증하고 순서를 복구한다. 손상되거나 경로를 이탈하는 기록은 거부한다. 폴더 교체·심볼릭 링크 전환, 내용·identity·메타데이터 변경도 거부하며 받은 데이터는 유지한다. 취소되거나 객체가 해제돼도 받은 파일을 삭제하지 않는다.

파일 시스템 검증은 UI 스레드 밖에서 호출한다. 등록·복구 검증의 직렬화와 화면에 제공할 이름·개수의 상태 잠금을 나누어, 긴 내용 해시 동안 화면 조회가 같은 I/O 잠금을 기다리지 않도록 했다. 취소 토큰은 기존 복사 엔진의 스냅샷 검증에 전달한다.

앱·테스트 빌드와 관련 25개 시험이 통과했다. 이 중 신규 수신 저장소 10개는 재시작 복원, 폴더·링크, 중복 콜백, 경로 이탈, 변경·교체, 손상 헤더, 취소, 권한 변경, 특수 파일, 심볼릭 링크 루트와 이탈 이름을 검사한다. [소스 해시와 실제 통과 목록](promise-intake-core-verification.json). 앱 수신 완료나 F17 수용 완료로 판정하지 않는다.
