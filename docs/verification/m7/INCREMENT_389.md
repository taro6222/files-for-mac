# 389 — 압축 저장 속성 최초 생성의 충돌 보존

## 수정

388의 압축 저장 생성은 최초 속성 부재를 확인한 뒤 일반 fsetxattr 쓰기를 사용했다. 확인 뒤 다른 속성이 추가되면 처음 쓰기에서 덮을 수 있었다. ResourceFork 최초 생성과 decmpfs header 생성에 XATTR_CREATE를 적용해 기존 속성을 덮지 않고 오류로 정지한다. 인라인 방식은 flag 적용 전 별도 리소스 포크가 생기지 않았는지도 재확인한다. 이미 이 작업이 만든 블록/테이블을 갱신하는 쓰기는 기존 경로를 유지한다. 원본 아카이브에는 쓰지 않는다.

## 검증의 강도

처음 만든 시험은 check callback이 내용 해시 도중 속성을 추가해, 최초 생성 경계 이전에 다른 이유로 실패할 수 있었다. 내용 proof를 확보한 직후의 내부 fault-injection 지점을 추가했다. 제품 호출은 이 callback을 제공하지 않는다. 인라인/블록 × header/fork 네 조건에서 속성을 추가하고 정확한 metadata 오류·논리 바이트·속성 바이트 보존·미압축 flag를 확인한다.

같은 강화 시험에 기존 비독점 쓰기/인라인 검사를 적용하지 않은 통제 구현을 한 번 실행했다. 네 조건 모두 실행돼 12개 assertion 실패를 확인했다. 종료 시 수정 소스를 복원하고 실제 수정본의 Debug/시험과 Release 번들을 다시 빌드했다. 최종 실제 SDK 클라이언트 검사 81개는 전부 통과했다. 이전 약한 시험의 성공을 이 경계의 수용 증거로 사용하지 않았다. [소스·통제/최종 결과 해시](archive-attribute-389.json).

이 시험은 속성 생성 전후의 순서를 제어한 fault injection이다. 여러 독립 프로세스의 모든 동시 스케줄이나 생성 뒤 자신이 쓰는 fork의 외부 교체까지 검증했다고 설명하지 않는다. 이미 생성한 저장 속성의 모든 동시 변경 경계·전원/자원/대용량/지원 환경 수용은 남아 있다. 원본과 보존 파일을 삭제하는 변경은 없다.

## 앞선 GUI 수용

[c4c4f6e 실행](https://github.com/taro6222/files-for-mac/actions/runs/45888418153)의 ARM 작업 성공과 원본 AppKit artifact를 확인했다. 네 언어/외형 조합이 각각 370개, 네 탭 경계 조합이 각각 18개를 모두 통과했다. 새 창 종료 취소와 상세 경로 가시성 조건도 네 조합에서 true다. 원본 보고서는 build/edit-389-ui385-arm에 보존하고 위 JSON에는 원본 해시·검사 수·해당 조건을 파생 요약으로 기록했다. 원본 전체 보고서라고 표기하지 않는다.

이는 385 소스의 프로그램 방식 수용으로, 387 이후 휴지통 UI나 이번 소스의 전체 UI·물리 입력/VoiceOver·전체 M7 성공으로 승계하지 않는다. 기존 Intel/375개 UI/388 기본 검증 실행은 재시작하지 않았다.

## 미완료

388 DMG에는 이번 보강이 아직 없다. 로컬 GUI·전체 AppKit·장시간 시험 앱은 실행하지 않았다. F23 다른 게시 방식·전체 압축 저장/지원 볼륨 경계, 전체 기능/UI 동등성과 M7 지원 환경·실제 입력·장시간·Developer ID/공증/정식 설치는 진행 중이다. UI 정의 375개와 helper/native 코드는 유지하며 이미 검증한 native 85개 등의 전체 반복은 하지 않았다.
