# M7 Increment 39 — 대형 폴더 정렬

폴더를 읽는 중에 받은 항목은 구간별로 정렬하고, 이전에 표시한 결과에 병합한다. 첫 배치를 바로 표시하고 이후 갱신 횟수를 제한하는 동작을 유지한다. 사용자가 읽는 중 정렬 기준을 바꾸면 누적 항목을 새 기준으로 정렬한다. 최종 목록에서 선택을 복원하는 방식은 기존과 같다.

Apple Silicon macOS 27.2 (26B123)의 APFS에서 최적화된 AppKit 앱을 측정했다. 매회 새 프로세스, 공유 OS 캐시, 빈 텍스트 파일, 썸네일 끔 조건이다. 다른 장시간 시험도 실행 중이었다. 첫 표시는 100개 이상이 테이블에 등록되고 표시 영역에 행이 생긴 시점이다. [원시 표본](performance-streaming-sort.json)

| 지표 | 변경 전 | 변경 후 |
|---|---:|---:|
| 10,000개 첫 표시 p95 (20회) | 60.7 ms | 62.1 ms |
| 10,000개 전체 표시 p95 (20회) | 1.331 s | 1.320 s |
| 100,000개 전체 표시 범위 (3회) | 11.63–12.37 s | 11.42–12.33 s |
| 100,000개 전체 표시 중앙값 (3회) | 12.21 s | 11.44 s |
| 100,000개 최대 샘플 RSS (3회) | 266.7 MB | 270.2 MB |

표본 범위가 겹친다. 전체 표시 성능의 차이는 이번 측정 조건에서 관찰한 수치다. 장시간 메모리와 화면 합성 프레임은 이 시험에서 판정하지 않는다.

Swift 테스트 204개가 통과했다. 읽기 중 정렬 방향 전환, 첫 배치 표시, 취소와 오래된 탐색 결과 폐기 회귀를 포함한다. AppKit 파일 작업 검증은 한국어·영어와 밝은·어두운 모드 네 조합에서 각각 48개를 통과했다.
