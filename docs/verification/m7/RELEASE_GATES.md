[정식 출시 기준](../../VALIDATION_AND_RELEASE.md)은 이 표의 환경별 실행 결과가 갖춰진 뒤 판정한다.

[Samba 서버 대조](INCREMENT_96.md)에서 Linux 클라이언트의 파일 왕복은 통과했고, 같은 공유의 macOS 게스트·인증 마운트는 디렉터리 조회 단계에서 제한 시간을 초과했다.

이후 루프백 Samba를 임시 포트와 고정 포트에서 다시 띄웠으나 Docker 실행 명령이 각각 20초와 45초 제한을 초과했다. 네트워크와 공유 폴더를 제외하고 같은 이미지에서 `/bin/true`만 실행한 대조도 20초를 초과했다. 이 재시도는 공유 마운트나 Files 파일 작업에 도달하지 못했다. 시험 컨테이너는 정리했다.

[macOS CI의 Samba 실마운트 검증](INCREMENT_185.md)을 추가했다. 러너에서 직접 실행한 Samba로 마운트와 파일 작업을 확인한다.

[인증 마운트와 목록 조회](INCREMENT_194.md)는 통과했다. Samba에서 임시 폴더의 이름 변경이 거부돼 사전 검사가 중단됐으며, CI 전용 공유 설정을 조정해 재검증한다.

[후속 인증 실행](INCREMENT_200.md)에서 파일 작업 사전 검사를 통과했다. 앱의 복사는 POSIX 권한 검증에서 실패했고 Samba의 macOS 확장을 적용한 시험을 진행한다.

[macOS 확장을 적용한 인증 실행](INCREMENT_207.md)은 파일 작업 사전 검사를 통과했다. 앱은 내용 또는 구조 검증에서 중단됐으며, 원본과 별도 Foundation 복사본의 차이를 시험 로그에서 대조할 수 있도록 진단을 추가했다.

[후속 SMB 진단](INCREMENT_211.md)으로 데이터와 권한의 일치 및 SMB의 0바이트 리소스 포크 표현을 확인했다. 전송 비교를 수정했으며 인증 마운트의 복사·이동 왕복 시험으로 재검증한다.

[SMB 3.1.1 재시험](INCREMENT_216.md)에서 기본 파일 작업은 통과했고 앱 복사는 수정 시각 검증에서 원본을 보존하고 중단했다. 원본과 복사본의 경로별 수정 시각을 다음 실마운트 실행에서 대조한다.

[후속 SMB 실행](INCREMENT_223.md)은 앱 복사와 데이터 확인을 통과했다. 복사 실행 취소와 이동이 실패해 각 작업을 별도 폴더에서 실행하고 실패 원인을 기록하도록 시험을 보강했다.

[파일 식별자 대조](INCREMENT_234.md)에서 SMB 이름 변경 뒤 열린 파일과 경로의 식별자가 함께 바뀌는 것을 확인했다. 복사·교차 볼륨 이동·교체 백업의 게시 직후 열린 파일을 확인해 새 장부 값을 기록하도록 수정했다. 실마운트 재시험을 진행한다.

[후속 SMB 실마운트](INCREMENT_239.md)에서 교차 볼륨 이동과 실행 취소를 확인했다. 폴더 복사의 수정 시각 정밀도를 조정했고 교체 이동의 보존 상태와 오류를 기록하도록 시험을 갱신했다.

[SMB 교체 이동](INCREMENT_242.md)의 후속 SMB 3.1.1 실마운트에서 폴더 복사·교차 볼륨 이동·기존 대상 교체와 실행 취소를 통과했다. 교체 취소 시 기존 대상 복원, 변경된 백업 보존, 게시한 파일이 교체됐을 때 원본 보존을 확인했다.

[SMB 읽기 전용 공유와 세션 재연결](INCREMENT_253.md)은 SMB 3.1.1 실마운트에서 통과했다. 복사·교체 실패 시 원본과 기존 대상이 보존됐다. 세션 종료 뒤 같은 마운트에서 재연결 횟수가 증가했고 폴더 목록과 새 파일 내용이 갱신됐다.

[SMB 3.1.1 후속 실마운트](INCREMENT_275.md)에서 생성·수정·접근 시각과 이동의 실행 취소를 확인했다. 교체 이동에서 목적 파일을 게시한 직후 세션을 끊었으며 같은 마운트에서 재연결, 이동 완료, 기존 대상 복원까지 통과했다.

[SMB 파일 기록 도중 중단 시험](INCREMENT_277.md)이 실제 공유에서 통과했다. 기록 도중 세션을 끊은 뒤 재연결 횟수가 증가했고 이동은 실패 결과를 보고했다. 원본이 보존됐으며 공개 대상과 임시 출력이 남지 않았다. 장기 단절과 외부 서버 권한 변경은 추가 검증한다.

[후속 개발 프리뷰 후보](INCREMENT_266.md)의 유니버설 빌드와 Apple Silicon 설치·복원 및 기동 시험을 통과했다. [실제 Sonoma 14.8.7 arm64 게스트](INCREMENT_270.md)에서 최신 앱의 설치·교체·복원, 직접·Launch Services 기동 및 파일 작업 검사를 통과했다.

[파일 작업 센터 진행 막대](INCREMENT_255.md)에서 진행 중인 복사의 항목 수, 접근성 설명 및 취소 후 결과를 실제 AppKit에서 확인했다. Windows 화면 대조와 VoiceOver 탐색이 남아 있다.

[Windows 작업 센터 실행](INCREMENT_261.md)에서 실제 복사 완료 카드를 표시하고 지운 후 원본과 대상 데이터를 대조했다. [macOS 완료 기록 지우기](INCREMENT_263.md)는 활성 작업의 진행 막대와 열린 세부 창을 그대로 유지했다. Windows 전송 중 진행·취소 화면은 열린 항목이다.

[파일 작업 센터 키보드 검사](INCREMENT_269.md)에서 Return으로 세부 창을 열고 Command+마침표로 활성 복사를 취소했다. 실제 VoiceOver 탐색은 남아 있다.

[교차 볼륨 이동 재시도](INCREMENT_272.md)에서 게시 전 실패와 대상 충돌 시 양쪽 파일 보호, 재시도와 실행 취소를 실제 APFS 볼륨에서 확인했다. [AppKit 결과 창 시험](INCREMENT_273.md)에서 실제 마운트의 권한 오류 후 버튼 재시도와 실행 취소를 확인했다.

[파일 작업 진행 표시](INCREMENT_281.md)에서 내용을 검증하는 복사의 취소 문구와 진행 표시를 점검했다. Sonoma APFS의 클릭부터 상태 반영까지 40회 최대 92.56 ms였으며 전송 엔진 종료 시간도 따로 기록했다.

상세 목록을 창에서 분리한 뒤 [125사이클 탐색 대조](INCREMENT_76.md)에서 셀 보유가 누적되지 않았다. 닫힌 창 정리를 적용한 별도 QA 바이너리의 [8시간 전체 부하](INCREMENT_174.md)는 8,913사이클 후 정상 종료했고 시간대별 물리 메모리 중앙값은 계속 증가했다. 이전 프리뷰의 [8시간 전체 부하 시험](INCREMENT_199.md)은 9,631사이클 후 정상 종료했으며 시간대별 메모리 중앙값이 계속 증가했다. [권한·해시 프리뷰의 8시간 결과](INCREMENT_225.md)에서도 9,682사이클과 정상 종료를 확인했으며 시간대별 물리 메모리 중앙값의 증가가 계속됐다.

[장시간 시험 중간 힙 비교](INCREMENT_92.md)에서 상세 셀 수가 제한된 상태에서도 AppKit 관찰 객체와 물리 메모리 증가를 확인했다. [최근 위치 갱신 30분 대조](INCREMENT_93.md)에서는 두 빌드에서 비슷한 종료 표본을 기록했다.

[닫힌 창의 콘텐츠 해제](INCREMENT_95.md)를 적용한 뒤 독립 창 30분 시험의 종료 물리 메모리가 5,933.4 MiB에서 145.9 MiB로 줄었다. 탐색·탭·전송의 30분 시험도 완료했다. 8시간 검증과 독립 창의 잔여 증가분 확인이 남아 있다.

파일 작업의 동시 변경 검증에는 [교차 볼륨](INCREMENT_44.md)과 [같은 볼륨](INCREMENT_45.md)의 폴더 실행 취소 보호, [취소 시 변경된 백업 보존](INCREMENT_47.md)을 포함한다. 교체 이동의 실행 취소는 [테스트 프로세스 강제 종료 후 복원](INCREMENT_54.md)과 [중단 후 메타데이터 변경 보호](INCREMENT_145.md), [백업 복원 직전 중단과 재시작 충돌 보호](INCREMENT_146.md), [교차 볼륨 실행 취소의 비덮어쓰기 게시](INCREMENT_147.md), [같은 볼륨 이동·실행 취소 충돌 보호](INCREMENT_148.md)를 검사했다.

[백업 없는 교차 볼륨 이동의 실행 취소](INCREMENT_149.md)에서도 APFS 강제 종료 후 재개 및 복원본의 메타데이터 변경 보호를 확인했다.

[로컬 볼륨 재검증](INCREMENT_169.md)에서 다섯 파일 시스템을 마운트해 검사하고, APFS 강제 종료 후 재개 세 조합과 시스템 휴지통 왕복을 다시 확인했다.

[상세 목록의 행 단위 갱신](INCREMENT_173.md)은 탐색·탭·독립 창 대조에서 AppKit 관찰 객체의 증가를 줄였다. 장시간 메모리 안정성은 계속 검증한다.

[행 갱신 이전 빌드의 8시간 기준 기록](INCREMENT_248.md)은 9,792사이클과 정상 종료를 확인했다. 시간대별 물리 메모리 중앙값은 71.0 MiB에서 220.6 MiB까지 증가했다.

[행 갱신 후 8시간 재시험](INCREMENT_250.md)은 9,825사이클과 정상 종료를 확인했다. 마지막 시간대의 물리 메모리 중앙값은 202.5 MiB였으며, 지속 증가로 장시간 기준은 열린 상태다.

[상세 목록 중간 행 삽입](INCREMENT_175.md) 후 짧은 탐색 대조에서 관찰 객체 수가 유지됐으며, 탭과 독립 창에서는 증가가 남았다.

[이전 프리뷰와 시험 빌드 대조](INCREMENT_182.md)에서 Apple Silicon 후보와 진행 중인 Swift Build 시험의 Mach-O 최소 배포 대상 및 SDK 값이 각각 14.0으로 일치했다. 8시간 결과는 시험이 완료되면 판정한다.

[8시간 전체 부하 세 빌드](INCREMENT_262.md)는 각각 9,475·9,620·9,761사이클을 마치고 정상 종료했다. 이전 프리뷰 소스의 후반 4시간 물리 메모리 중앙값은 146.4~158.0 MiB였다. 최신 프리뷰에서 장시간 결과를 확인한다.

[홈 복귀의 폴더 감시 해제](INCREMENT_268.md)는 전체·탐색 앱 부하의 각 사이클에서 이전 감시 객체의 실제 해제를 확인한다. 짧은 최적화 검사를 통과했고 장시간 판정은 별도로 남아 있다.

[파일 작업 센터](INCREMENT_188.md)에서 복사·이동·병합의 진행과 결과를 한 목록으로 제공한다. [닫힌 결과](INCREMENT_237.md)도 같은 앱 실행 중 최근 50건을 확인할 수 있다. 전체 전송의 바이트 합과 원본 실행 화면 대조는 계속 검증한다.

[Windows 원본 UI-01 홈 실행 화면](INCREMENT_189.md)을 확보해 macOS 홈의 카드 배치, 접힌 네트워크 위치, 최근 항목을 대조했다. 다른 화면·상태와 동일 환경 설정으로의 비교는 남아 있다.

[UI-02·03 공통 폴더 실행 화면](INCREMENT_191.md)에서 Windows와 macOS의 다섯 항목과 기본 상세 열을 대조했다. 동일 창 크기·초점 상태와 나머지 화면 비교는 남아 있다.

[UI-04 그리드](INCREMENT_197.md)와 [UI-05 컬럼](INCREMENT_201.md)의 Windows·macOS 실행 화면을 공통 폴더로 대조했다. 컬럼 보기에서 선택에 따른 하위 항목 표시와 원본의 상위 경로 컬럼을 확인했다.

[UI-06 좌우 분할](INCREMENT_206.md)과 [상하 분할](INCREMENT_212.md)에서 두 앱의 패널별 경로와 하위 항목, 활성 상태를 대조했다. [제한 실행 수준으로 시작한 Windows 시험도 관리자 권한을 보고해](INCREMENT_236.md) 탭 드롭은 열린 항목이다. 동일 창 크기에서의 시각 대조도 남아 있다.

[UI-07 검색](INCREMENT_217.md)에서 Windows와 macOS의 공통 폴더 검색 결과와 표시 방식을 대조했다. Windows의 검색 복귀는 재실행한다.

[UI-08 정보 패널](INCREMENT_224.md)에서 같은 텍스트 파일의 상세와 미리보기 본문을 두 앱의 실행 화면으로 확인했다. macOS의 [생성일·태그 편집·속성 바로가기](INCREMENT_226.md)와 [선택 항목의 Git 상태](INCREMENT_229.md)를 검증했다. [설치 앱의 PNG·PDF 화면](INCREMENT_259.md)에서 이미지와 PDF 본문을 확인했다. Windows 동일 형식 대조와 대용량·손상 파일은 열린 항목이다.

[UI-09 속성·해시](INCREMENT_240.md)에서 동일한 24바이트 파일의 속성과 SHA-256을 두 앱의 실행 화면으로 대조했다. macOS 속성 창에서 [이름 편집·충돌 보호·확장자 변경 취소](INCREMENT_241.md)를 검증했다. [보안·서명](INCREMENT_244.md)에서 Windows NTFS 액세스 목록, macOS POSIX 권한·확장 ACL 및 두 앱의 네이티브 코드 서명 표시를 비교했다. [중첩 앱 서명 검사](INCREMENT_251.md)는 정상·무효 상태, 바깥 앱 식별자와 하위 구성 요소 진단을 화면에서 확인했다. macOS 인증서 기반 서명 검증은 열린 항목이다.

[코드 서명 검사 출력 처리](INCREMENT_247.md)는 서명 확인 도구의 큰 출력을 읽는 동안 진단 보관량을 제한한다. 1 MiB 출력과 실제 서명·미서명 파일을 대조했다.

[Windows 고급 보안 실행](INCREMENT_256.md)에서 원본 앱의 소유자와 보이는 세 권한 행이 파일의 실제 ACL과 일치했다. 편집·저장과 거부 ACE의 실제 실행은 남아 있다.

[Intel 전체 AppKit 회귀](INCREMENT_282.md)는 빌드와 파일 작업 검사 후 시간 제한에 도달했다. 스택을 수집해 후속 실행을 진단한다. 중단 전 8시간 시험의 최종 보고서는 현재 환경에서 회수하지 못해 미확인 상태다.
