# M7 Increment 314 — 저장된 Finder 태그를 우선 읽기

상태: 구현·전체 Swift·Debug·Release 검증 통과. 실제 볼륨·전체 UI·두 CPU 원격 검증은 진행 중이다. M7 출시는 미완료다.

`56d0ffc` ARM CI는 리소스 열거에서 태그가 빈 배열로 반환되는 경우를 검출했다. 기존 시험은 NSURL API로 설정한 값을 기대했지만 원격 실행에서 실제 저장 속성은 별도로 확인하지 못했다. 이 단계는 시험의 기대값을 낮추지 않고, fixture 설정 직후 실제 Finder 확장 속성과 두 이름을 독립적으로 확인한다. 원격 실패 원인이 저장과 읽기 중 어디에 있는지 새 실행에서 구분한다.

목록·로컬 태그 검색·속성·태그 편집 스냅샷은 저장된 `com.apple.metadata:_kMDItemUserTags` plist를 우선 읽는다. 정상 배열이면 Finder의 색상 접미사를 제외한 이름을 반환하며 명시적으로 저장한 빈 배열은 오래된 리소스 값을 덮어쓴다. 저장 형식이 없거나 지원되지 않거나 해석할 수 없으면 기존 리소스 공급자 값을 유지한다. 직접 속성 조회는 leaf 심볼릭 링크를 따라가지 않으며, 기존 native 링크·가상 메타데이터 fallback은 유지한다. 저장 데이터를 변경하지 않는다.

전체 Swift 342개 보고: 성공 324개·환경 건너뜀 18개. 새 다섯 시험은 binary/XML plist·색상 접미사, 명시적 빈 태그·알 수 없는 형식의 fallback, 링크 직접 비추적, 목록·검색·속성·편집 일치, 같은 경로의 반복 태그 변경을 검증한다. Debug·일반 Release 빌드는 성공했다. 제한 실행기·실제 볼륨·네 조합 UI는 실행 중이다.

기존 태그 prefetch와 다른 파일 메타데이터 필드는 유지한다. 이 변경은 동시 메타데이터 변경의 원자적 스냅샷이나 모든 공급자의 확장 속성 지원을 보장하지 않는다. 원격 수용, 잔여 메모리 증가·최신 소스 8시간, Intel 성능·실제 접근성·정식 서명·공증은 남아 있다.
