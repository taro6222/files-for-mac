# M7 Increment 08 — 장시간 탐색·탭·전송 검증

`scripts/verify-release-soak.sh`는 최적화된 검증용 AppKit 빌드를 만들고, 기본값으로 한 프로세스에서 28,800초 동안 실행한다. 일반 배포 빌드에는 이 진입점이 들어가지 않는다. 각 실행은 별도 설정 도메인과 `build/release-soak.*` 디렉터리를 쓴다. 기존 파일을 수정하지 않으며 생성한 파일로 검증한다.

한 사이클에서 129개 항목 폴더를 열고, 네이티브 보조 탭을 붙여 1 MiB 파일을 복사한다. 실제 디렉터리 감시 이벤트로 생성·삭제가 목록에 반영되는지와 복사한 바이트를 검사한다. 닫기 콜백을 기다린 뒤 보조 탭 컨트롤러와 감시 객체가 해제됐는지도 확인한다. 홈으로 돌아오면 해당 사이클의 RSS를 읽고, 보고서는 주기적 표본과 사이클별 최댓값을 담는다. 프로세스 종료 여부와 마지막 보고서 상태, 장시간 RSS 시간대를 함께 판정한다.

각 실행의 `report.json`은 완료된 사이클 수와 경과 시간, RSS 표본, 실패 이유를 보존한다. `source-sha`, `binary.sha256`, `macos.txt`, `filesystem.txt`에서 실행 대상과 파일 시스템을 확인할 수 있다. GUI 세션에서 진행하며 `caffeinate -i`는 실행 중 유휴 잠자기를 억제한다. 8시간 완료 보고서가 나올 때까지 장시간 검증은 진행 중이다.

작업 폴더와 경로 영향을 비교할 때는 기존 디렉터리를 두 번째 인자로 지정할 수 있다. 예를 들어 `bash scripts/verify-release-soak.sh 28800 /private/tmp`는 임시 폴더 아래에 별도의 빌드·시험 디렉터리를 만든다. 첫 출력 줄은 해당 디렉터리의 경로다.

앱 실행이 끝나면 `exit-status`에 프로세스 종료 코드가 기록된다. 완료 판정에는 이 코드와 보고서의 완료 상태, 전체 실행 시간, 메모리 추세를 함께 확인한다.

최신 보고서는 RSS와 함께 macOS의 물리 메모리 사용량도 기록한다. [계측 검증](INCREMENT_67.md)

출시 후보를 다시 시험할 때는 [고정 소스 빌드](INCREMENT_20.md)를 사용한다.

90초 예비 실행은 93.80초 동안 28사이클을 완료했다. 사이클 종료 시 최대 RSS는 189 MB였다. Swift Testing 201개와 셸 구문 검사도 통과했다. [예비 실행 보고서](release-soak-smoke.json)
