# M7 Increment 322 — 이동 선택 전체의 임시 복사 데이터 집계

상태: 구현·Core·실제 다섯 파일 시스템·네 조합 UI·Debug·Release 검증 통과. M7 출시는 미완료다.

여러 원본 이동의 교차 볼륨 staging 바이트와 예정량을 합산해 진행 창과 최종 결과에 표시한다. 같은 볼륨 이름 변경에는 staging이 없으므로 0바이트로 집계한다. 데이터 100%는 검증·게시·원본 삭제 완료를 뜻하지 않으며, 취소되거나 게시하지 못한 복사 시도의 바이트도 포함한다. 항목별 완료·실패·충돌·취소 수는 별도로 유지한다.

전체 예정량은 기존 교차 볼륨 무결성 검사에 필요한 원본 스냅샷을 미리 준비해 재사용한다. 별도 크기 순회나 동일 스냅샷의 중복 해시를 추가하지 않는다. 각 원본이 시작되면 준비 결과를 해제하고, 준비한 원본 identity와 현재 원본을 대조한다. 조회 실패·불명 크기는 미확인 예정량으로 남긴다. 알려진 충돌은 예정량에서 제외하고 실행 중 새 충돌도 아직 staging하지 않았으면 제외한다. 사전 확인 취소 시 원본 이동을 시작하지 않는다.

기존 retry·redo·flatten 원본 및 목적지 검사를 유지하며 사전 해시 전에 확인한다. 폴더 자신 또는 하위 목적지로 교차 볼륨 이동하는 요청도 해시·staging 전에 거부한다. 임시 복사·SHA-256 및 메타데이터 검증·비덮어쓰기 게시·원본 재검증 후 삭제·백업 복구·Undo의 순서는 유지한다.

진행 알림의 원본 순서·단계·합계 sequence·현재 바이트를 검사해 늦은 알림이 표시를 되돌리지 않게 한다. 최종 요약은 보고서의 합계로 확정한다. move 저널은 기존 version 1에 선택적 합계 필드를 추가하며 기존 Undo 형식은 바꾸지 않는다.

Core 회귀는 여러 원본과 충돌의 총량·최종 저널·Undo, 같은 볼륨 0바이트, 두 번째 원본 복사 중 취소와 첫 원본 Undo, 준비 후 외부 원본 교체, 크기 확인 중 취소, 100% staging 뒤 게시 충돌, 자기 하위 이동 거부를 검사한다. 최종 Swift 실행은 375개 중 성공 356개·환경 건너뜀 19개다.

DEBUG UI는 실제 같은 볼륨 이동·충돌·Undo 결과로 0바이트와 늦은 크기 확인 알림·완료 후 알림 차단을 검사한다. 실제 볼륨 UI의 교차 볼륨 실패 재시도 fixture는 두 원본으로 확장해 실제 바이트 합계·최종 요약·내용 보존·둘 모두의 Undo를 요구한다. 물리 입력·화면 합성·VoiceOver 수용을 대신하지 않는다.

앞선 ACL 단계 `51ce8dd`의 원격 전체 검증은 아직 완료 판정 전이다. 인증서·공증 프로필은 사용자 준비 중이며, Intel 전체 수용·메모리 안정성·최신 소스 8시간·지원 환경 및 외부 서비스 수용은 남아 있다.

최종 실제 볼륨 시험 8개·제한 실행기 10개·네 조합 각각 파일 작업 UI 85개·전체 UI 283개와 Debug·Release 빌드가 통과했다. 합계를 둘째 줄에 추가한 뒤 기존 남은 수 검사가 문장 전체의 끝을 비교해 실패한 첫 실행은 통과로 집계하지 않았다. 검사는 첫째 줄의 동일 남은 수 조건을 유지하도록 수정했고 최종 바이너리를 재검증했다. [최종 소스·바이너리·검증 결과](move-selection-verification.json).

원격 [Undo 커밋 `28f8020` 검증 스냅샷](overlapping-undo-28f8020-ci-progress.json)에서는 두 CPU의 전체 AppKit 단계와 두 Xcode 빌드가 성공했다. ARM 검증 작업은 전체 성공했으며 Intel 프리뷰 교체·복원은 관측 시 진행 중이다. 전체 CI 완료나 최신 이동 집계 소스의 수용으로 판정하지 않는다. 이전 `34cae2c` Intel ACL 실패 원인도 이 성공만으로 확정하지 않는다.
