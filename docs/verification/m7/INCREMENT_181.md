# M7 Increment 181 — AppKit 파일 작업 시험의 호스트 의존성과 시간 초과 진단

파일 작업 회귀는 모의 네트워크·로컬 볼륨을 사용하는 구간에 들어가기 전에 호스트의 실제 볼륨 열거 작업을 기다리고 있었다. 시험용 브라우저에 격리된 볼륨 공급자를 사용하고 모의 볼륨을 게시하기 전에 진행 중인 새로고침을 취소했다. 일반 앱은 계속 macOS에서 실제 볼륨을 조회한다. 앞선 Intel 시간 초과의 당시 스택이 없어 원인을 확정할 수 없다.

파일 작업 회귀 프로그램은 복사·병합, 분할 보기, 실행 취소·재실행, 충돌, 미리보기, 취소, 감시 복구와 홈 탐색 단계의 진입을 기록한다. 실행 제한을 넘으면 스크립트가 앱 프로세스의 스택을 1초간 채집하고 앱을 종료한 뒤 검증을 실패로 판정한다. 스택과 로그는 시험 폴더에 남고 CI 로그에는 스택 앞부분을 표시한다.

Apple Silicon macOS 27.2에서 한국어·영어와 밝은·어두운 테마 네 조합마다 AppKit 검사 68개가 통과했다. 제한 시간을 줄인 격리 스크립트와 멈추는 대조 프로세스로 실패 반환, 마지막 단계 로그와 스택 채집을 확인했다.

## 장시간 메모리 대조의 SDK 메타데이터

실행 중인 네이티브 엔진 QA와 Swift Build QA의 앱 소스와 배포 대상 macOS 14.0은 일치했다. 링크 메타데이터의 SDK 값은 각각 27.2와 14.0이었다. 이전 [유니버설 로컬 프리뷰](PREVIEW_0.1.0.md)의 두 슬라이스에도 SDK 14.0이 기록돼 있었다. 네이티브 QA의 참조 트리에서 AppKit의 `previousKeyViews`가 `NSScrollPocket` 객체를 보유한 것을 확인했다.

두 QA 바이너리의 임시 복사본 각각에서 Mach-O SDK 필드만 14.0 및 27.2로 바꾸고 같은 방식의 ad-hoc 서명을 적용했다. 두 바이너리 모두 최소 배포 대상 14.0과 링커 버전을 유지했다. Apple Silicon macOS 27.2의 동일 세션에서 네 복사본의 전체 부하를 각각 155초 실행했고 모두 정상 종료했다.

| 실행 파일 | 기록된 SDK | 32~34사이클의 `NSScrollPocket` 관찰 객체 | 물리 메모리 최고치 |
|---|---|---:|---:|
| 네이티브 엔진 QA | 14.0 | 0 | 65.5 MiB |
| 네이티브 엔진 QA | 27.2 | 33 | 77.6 MiB |
| Swift Build QA | 14.0 | 0 | 65.7 MiB |
| Swift Build QA | 27.2 | 35 | 79.4 MiB |

두 바이너리에서 스크롤 객체의 증가 여부가 기록된 SDK 값과 함께 바뀌었다. 이 값은 장시간 비교에서 통제해야 하는 변수다. 제품 바이너리는 수정하지 않았다. 8시간 동안 안정적인지는 현재 실행 중인 시험의 종료 결과로 판정한다.

[커밋 `e440f77`의 macOS 15 CI](https://github.com/taro6222/files-for-mac/actions/runs/43649745323)는 Apple Silicon과 Intel 모두에서 통과했다. Intel 로그에서 네 언어·테마 조합의 AppKit 파일 작업 각 68개와 설치 프리뷰의 x86_64 실행도 확인했다.
