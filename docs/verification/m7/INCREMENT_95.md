# M7 Increment 95 — 닫힌 창의 콘텐츠 해제

브라우저 창이 닫히면 실행 중인 감시와 작업을 정리하고, 닫은 작업 공간을 저장하는 콜백이 끝난 뒤 AppKit 창에서 콘텐츠 뷰를 분리한다. 이 순서로 닫은 탭에 저장되는 선택과 패널 배치를 읽을 수 있다.

Apple Silicon macOS 27.2에서 독립 창을 반복해 열고 닫았다. 아래 수치는 사이클 종료 시점의 물리 메모리 표본이다.

| 실행 | 마지막 표본 | 최대 |
|---|---:|---:|
| 기존 종료 경로, 약 63초 | 255.7 MiB | — |
| 화면에서 내린 뒤 종료, 181초 | 578.0 MiB | 578.7 MiB |
| 닫기 직전 콘텐츠 분리, 102초 | 81.7 MiB | 90.2 MiB |
| 기존 종료 처리에서 콘텐츠 분리, 96초·38사이클 | 68.4 MiB | 75.3 MiB |

기본 `NSWindow`에서 열기·닫기를 35회 반복한 AppKit 대조는 마지막 물리 메모리 표본이 19.8 MiB였다. 사이드바와 동일한 반투명 효과를 추가한 별도 대조의 마지막 표본은 20.0 MiB였다. 두 실행 모두 닫은 창 객체가 해제됐다. Files에서도 창 객체 해제를 검사한 뒤 물리 메모리의 추가 증가를 확인했다.

같은 38사이클에서 기존 경로의 물리 메모리는 338.6 MiB, 콘텐츠 분리를 적용한 경로는 75.3 MiB였다. 제품 변경이 들어간 바이너리에서 독립 창과 탭·전송의 30분 검증, 탭·전송의 8시간 검증을 시작했다. 8시간 기준은 종료 결과와 메모리 추세로 판정한다.

한국어·영어 × 밝게·어둡게 조합의 전체 AppKit 회귀에서 각각 248개를 통과했다. 네 방향의 탭 드롭, 두 방향의 분할 세션 복원, 분할을 닫은 뒤 키보드 초점 복귀를 포함한다.

후속 회귀에서는 네 방향의 탭 드롭에서 닫히는 원본 탭의 저장 콜백을 직접 검사했다. 콜백 안에서 콘텐츠에 접근해 현재 폴더, 목록 보기, 앞으로 이동 기록을 저장하고, 콜백 이후 콘텐츠가 분리되는지 확인했다. 네 언어·테마 조합에서 각각 252개를 통과했다.

## 30분 확인

두 부하가 모두 완료 상태와 종료 코드 0을 기록했다.

| 모드 | 사이클 | 첫 → 마지막 물리 메모리 | 최대 |
|---|---:|---:|---:|
| 독립 창 | 798 | 57.0 → 145.9 MiB | 154.5 MiB |
| 탐색·탭·전송 | 571 | 63.9 → 62.7 MiB | 91.1 MiB |

독립 창의 마지막 표본은 [수정 전 대조](INCREMENT_94.md)의 5,933.4 MiB에서 145.9 MiB로 줄었다. 수정 후에도 독립 창의 시작·종료 표본에는 차이가 있다. 탐색·탭·전송의 8시간 시험은 진행 중이다.
