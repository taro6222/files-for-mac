# 387 — 미완료 압축 편집 출력의 명시적 휴지통 정리

## 제품 동작

압축 편집 기록 화면에서 실제 원본을 확인한 후, 게시되지 않은 출력만 별도 확인 창을 거쳐 같은 볼륨의 휴지통으로 옮길 수 있다. 원본·저장된 편집·Undo/Redo용 이전 버전·손상된 기록은 정리하지 않는다. 원본이 바뀌거나 출력 inode가 교체되었거나 하드링크가 추가되면 이동을 거부한다. 다른 파일·하위 트리를 재귀적으로 지우지 않는다.

새 기록에는 최초 출력 식별 정보를 남긴다. 기존 building 기록처럼 이 정보가 없는 미완료 출력은 자동으로 소유 파일이라고 추정하지 않고 보존한다. 기존 prepared 기록은 이미 검증한 내용/metadata 증거를 사용한다. 공개 복구 API의 discard 액션과 discarded 결과를 추가하고 프로세스 시험 도구도 새 결과를 처리한다.

## 휴지통 이동과 재진입

0700 전용 휴지통 폴더·출력 proof·이동 목적지를 연결 저널의 discardIntent에 먼저 동기화한다. 같은 볼륨의 RENAME_EXCL 이동으로 기존 항목을 덮어쓰지 않는다. 이동 전 원본/출력/디렉터리를 확인하고, 이동 후 취소가 도착해도 재확인과 완료 기록을 마친다. 이동 전 중단은 기존 출력에서 재시도하고, 이동 후 기록 완료 전 중단은 원본/휴지통 파일의 실제 배치와 내용을 확인해 완료로 조정한다. 양쪽에 파일이 있거나 identity/metadata가 다르면 보존하고 오류를 반환한다.

복구 기록과 빈 staging 디렉터리는 유지한다. 출력의 디스크 공간은 휴지통을 비운 뒤 회수된다. Finder의 자동 원위치 복구 metadata를 제공한다고 주장하지 않으며, 화면에서 보존 위치를 열고 사용자가 별도로 복사해 복구한다. 휴지통을 비웠거나 이후 파일을 바꾸면 재검증은 실패해도 기록은 남는다.

## UI

확인 전에는 정리 버튼이 비활성화된다. 원본 미교체 확인 뒤에만 활성화하며 확인 창에는 이동할 파일·원본/기록 보존·휴지통 이동을 안내한다. 취소하면 그대로 둔다. 완료 후 휴지통 위치를 표시하고 Undo/Redo/정리를 비활성화한다. 추가 버튼은 별도 행에 두고 창 높이/최소 높이를 늘렸다. 한국어/영어와 접근성 레이블을 연결했다.

## 검증

Debug/시험 및 Release 빌드와 새 앱 번들의 코드 서명/SDK 검증이 통과했다. 실제 번들 Swift 검사 77개가 모두 통과했다. 신규 세 시험은 실제 파일에서 이동·원본/기록 보존·멱등 재확인, 외부 교체/원본 수정/하드링크 거부·다른 sibling 보존·기존 기록 호환성, 이동 전/후 재진입·휴지통 충돌 보존을 검증한다. 기존 실제 SDK 기록/Redo 시험에는 게시된 백업의 정리 거부를 추가했다. 시험은 사설 임시 trash 폴더를 사용했으며 실제 시스템 휴지통/볼륨별 수용을 대신하지 않는다.

초기 시험의 /var와 /private/var 경로 별칭 비교를 실제 canonical 디렉터리로 수정했고, Swift Testing의 중첩 require 매크로를 분리했다. 최종 소스를 재빌드한 77개 결과를 기록한다. 이전 실패 결과를 성공 증거로 승계하지 않았다. [소스·결과 해시](archive-discard-387.json).

원격 UI 정의는 기존 370개를 유지하고 확인 전 비활성화·미게시만 허용·취소 보존·휴지통 이동/원본 유지·기록/비활성화 다섯 조건을 더해 375개다. 실제 새 GUI 수용은 대기 중이며 로컬 GUI/전체 AppKit/장시간 시험은 실행하지 않았다. SDK/helper 코드는 유지해 native 전체 회귀를 반복하지 않았다.

386 DMG에는 이번 정리 기능이 없다. F23의 다른 게시 방식·압축 저장 metadata·지원 볼륨/실제 중단 경계와 전체 UI 수용, 전체 기능/UI 동등성 및 M7 서명/공증·지원 환경·물리 입력/VoiceOver 등은 미완료다.
