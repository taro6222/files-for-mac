# M7 Increment 298 — 검증된 수신 보관본 정리

상태: F17 개발·수용 검증 진행 중. 보관된 수신 파일 화면에서 복사 기록을 확인하고, 실제 원본·복사본을 다시 검증한 뒤 보관본을 macOS 휴지통으로 옮기는 기능을 연결했다. 영구 삭제나 휴지통 비우기는 하지 않는다.

복사 엔진이 내용을 검증하고 게시한 항목에만 대상 경로·identity·내용과 권한 스냅샷·생성 및 수정 시각·확장 속성·ACL을 수신 기록에 추가한다. 기존 수신 기록에는 이 필드가 없으며 그대로 복구할 수 있다. 복사 엔진의 게시용 identity와 수신 저장소의 생성 시각 포함 identity를 구분해 연결했다. 기록 저장 실패는 완료된 복사를 되돌리거나 실패로 오표시하지 않고 보관본을 유지하는 안내로 남긴다.

‘복사 완료 보관본 정리’는 각 수신 항목에 대해 아직 동일한 복사본이 남아 있는지 실제 파일 시스템에서 검사한다. 최신 복사본이 바뀌었더라도 이전의 다른 복사본이 그대로라면 그 복사본을 검증한다. 원본 변경, 대상 교체·권한 변경, 건너뜀·부분 병합, 등록되지 않은 수신 파일 또는 알 수 없는 보관소 파일은 정리를 거부한다. 같은 수신 저장소 안의 다른 경로를 외부 복사본으로 인정하지 않는다. 모든 수신 항목을 검증할 수 없는 작업은 보존한다.

휴지통 이동 전 작업 기록을 원자적으로 저장하고, 이동 뒤에도 폴더 identity·원본·대상·추가 파일을 다시 검사한다. 그 사이 변경·취소·기록 오류가 발생하면 identity가 같은 보관소만 원래 위치로 되돌리는 것을 시도한다. 원래 위치에 새 항목이 생겼으면 덮어쓰지 않고 휴지통의 실제 보관 위치를 남긴다. OS가 이동 결과 위치를 제공하지 못한 경우에는 위치를 안다고 표시하지 않고 검토가 필요한 기록을 남긴다. 복원 후 원래 경로가 다른 부모를 가리키면 열린 부모의 실제 경로를 확인하며, 확인되지 않은 위치를 복원 완료로 표시하지 않는다.

수신 콜백이 끝나지 않았거나 복사 정책을 고르는 작업은 정리 대상에서 제외한다. 정리는 UI 밖의 GCD 작업에서 수행하고 안전 지점 취소를 제공한다. 작업 센터에는 항목 진행과 결과·중지·상세 화면을 연결했으며, 정리 중 새 파일 작업과 앱 종료도 보호한다. 정리된 수신 항목은 완료된 수신 창에서 해제하고 남은 항목만 유지한다. ‘정리 결과 보기’로 실제 보관 위치 또는 검토 기록을 열 수 있다. 재시작 후 미완료 정리 기록의 자동 후속 처리와 실제 메뉴·키보드·VoiceOver 수용은 별도 남은 항목이다.

신규 코어 시험 12개는 재시작 후 복사 기록 복구와 정리, 미복사·충돌, 원본·대상 내용 변경, 같은 바이트의 대상 교체, 추가 파일, 취소·기록 실패, 이동 중 변경·복원·복원 충돌, 이전 복사본 재검증, 폴더·링크, 권한 차이·휴지통 서비스 실패, 이동 후 취소 및 결과 위치 미확인을 검사한다. 실제 휴지통 이동을 포함한 네이티브 화면 계약은 시험용 폴더만 옮긴 뒤 그 identity가 그대로인지 확인하고 시험 디렉터리로 회수한다. 사용자 휴지통을 비우지 않는다.

최소 창의 한국어·영어와 밝음·어두움은 각각 레이아웃과 캡처를 확인한다. 표의 기록 상태는 현재 대상이 검증됐다고 오해하지 않도록 ‘복사 기록 있음’으로 표시하고, 정리 시 다시 검증한다. 긴 안내와 오류는 주요 버튼을 밀어내지 않도록 줄 수를 제한하고 전체 내용은 툴팁에서 확인할 수 있다.

최종 앱·테스트 빌드, 전체 Swift 집계 299개 중 성공 281개·별도 fixture 건너뜀 18개, 제한 실행기 5개가 통과했다. 수신·정리 네이티브 계약은 네 언어·테마 조합에서 각각 40개, 같은 최종 바이너리의 전체 UI 회귀는 각각 283개, 파일 작업 UI는 각각 79개, 임시 마운트 시험 7개가 통과했다. 검증 결과와 소스·바이너리 해시는 [수신 정리 검증 기록](promise-cleanup-verification.json)에 저장한다. 이 결과를 실제 SDK 마우스 드래그 전달 성공으로 확대 해석하지 않는다.

별도 소스 `ca827fc`의 원격 실행은 두 CPU Xcode 빌드가 모두 통과했다. 전체 AppKit은 Intel의 동기화 시험과 Apple Silicon의 Spotlight 준비에서 중단되어 어느 쪽도 도달하지 못했다. [원본 결과](ca827fc-ci-blockers.json). Intel 시험은 3초 대기 장벽이 먼저 끝난 후 취소를 요청한 상황이므로, 전용 관찰 큐와 10초 동기화 감시 제한으로 보강했다. 소비자가 취소를 완료할 때까지 동기 I/O 장벽을 해제하지 않으며 실제 장벽이 유지됐음을 검사한다. 개별 조작 성능 예산을 바꾸거나 취소 검사를 제거하지 않는다. Spotlight는 importer가 Swift 내용을 읽었지만 실제 색인 항목이 없어 준비 실패를 계속 추적한다.

F17 전체와 M7은 완료 판정하지 않는다. 실제 드래그·재시작 후 정리 복구·접근성, 같은 최신 소스의 두 CPU 전체 UI·Xcode, 최신 후보의 장시간 판정, 준비 중인 Developer ID·공증이 남아 있다.
