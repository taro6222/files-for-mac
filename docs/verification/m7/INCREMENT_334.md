# M7 Increment 334 — Intel 초기 Git 창 조회 진단

상태: 진단 구현·로컬 검증 완료. 새 원격 수용과 Intel 지연의 원인·해결, M7 출시는 미완료다.

`81524f8`의 [두 CPU 실행](https://github.com/taro6222/files-for-mac/actions/runs/45752296059)이 실패로 종료됐다. ARM은 기존 세션 객체 비교가 네 조합에서 실패했다. Intel은 세션 검사가 모두 통과했고 한국어 밝은 테마의 `gitWindow` 한 개만 실패했다. 나머지 세 조합은 각각 전체 302개, 탭 경계는 네 조합 각각 18개가 통과했다. 기존 87675c5에서도 같은 Intel 초기 Git 창 실패가 있었다.

Intel 실패 PNG는 빈 변경 목록, 비활성 작업 버튼과 활성 중단 버튼을 보여 준다. 하지만 기존 보고서에는 최초 창 조회의 경과·백엔드 단계·상태 문구·작업 존재 여부가 없어 정확한 대기 원인을 판정할 수 없다. Git clone의 별도 대기 기록으로 이 최초 상태 조회를 설명하지 않는다.

10초 Git 창 대기와 기존 전체 프로세스 예산을 유지한다. 이제 대기 직후 창 표시·단계·실행 여부·상태 문구·현재 경로·스냅샷 존재·브랜치·행 수와 경과 시간을 기록한다. 단계는 스냅샷 조회와 브랜치/원격 정보 조회, 완료·취소·오류를 구분한다. 실패한 경우 창을 닫기 전에 소유 앱 및 직접 Git 자식(찾은 경우 최대 두 개)의 스택을 기존 진단기로 보존한다. 추가로 기다려 완료한 결과를 원래 10초 성공으로 바꾸지 않는다.

기존 투명 캡처는 검은 배경에서 상태 문구를 읽기 어려웠다. 새 Git 상태 캡처는 해당 AppKit 외형의 창 배경색을 포함한다. 이전 이미지는 그대로 보존하고 새 결과와 혼동하지 않는다.

변경은 DEBUG 진단·캡처와 catch 구문의 줄 배치다. DEBUG를 제외하고 공백을 정규화한 두 Swift 파일의 소스를 기준 커밋과 대조한다. Git 명령·상태 조회 순서·취소·출력 검증·사용자 기능은 바꾸지 않았다. Core/실제 볼륨 시험과 기존 81524f8 8시간 실행은 다시 시작하지 않는다.

## 검증

네 언어/테마 조합에서 전체 UI 각각 303개와 탭 경계 각각 18개가 통과했다. 각 진단은 loaded·작업 없음·스냅샷/브랜치 존재·창 표시를 확인했다. 밝음/어두움의 배경을 포함한 캡처도 직접 확인했다. Debug 빌드·parity 감사·Windows 수집 보호 시험 19개가 통과했다. [소스·보고서·이전 Intel 결과 해시](git-window-334-verification.json), [이전 실패의 원본 투명 캡처](git-initial-81524f8-failure.png)를 보존한다. 새 소스 Intel 재현 스택·원인 해결·두 CPU 전체 수용, Windows 압축 상태 수집, 8시간 메모리 안정성, 실제 입력/VoiceOver와 지원 환경·원본 전체 UI·외부 서비스·Intel 기준 성능·정식 서명/공증은 남아 있다. Mac 로그인 세션은 최근 확인에서 잠겨 있어 실제 입력 검증을 위한 사용자의 잠금 해제 응답을 기다린다. 인증서·notarytool 프로필은 사용자 준비 중이다.


## 압축 창의 Cancel과 탭 닫기 ID 충돌

보완 후 [Windows 실행](https://github.com/taro6222/files-for-mac/actions/runs/45754753555)은 압축 창까지 도달했다. 정상 이름·포맷·압축 수준·활성 Create/Cancel을 [실제 화면](windows-archive-dialog-scope-failure.png)에서 확인했지만 검증기가 정상 창을 거부해 종료됐다. 새 접근성 트리에는 압축 창의 Cancel과 창 밖 Close Tab이 모두 CloseButton ID로 표시됐다. 전체 창에서 ID의 유일성을 요구하던 조건이 충돌했다. 입력·오류·취소 수집과 취소 후 manifest 검증은 아직 도달하지 못했다. [실패 해시·경로](windows-archive-dialog-334-failure.json).

대화상자 자체의 표시·제목이 유일한지 먼저 확인하고 그 내부 컨트롤만 검사한다. 실제 취소 클릭도 Create archive 창 내부의 활성 Cancel 버튼으로 제한한다. 같은 ID의 탭 닫기를 선택하지 않는다. 이름 오류 팝업은 WinUI에서 대화상자 밖에 배치될 수 있어 표시된 해당 경고의 확인을 유지한다. 실제 실패 트리에 보완한 조건과 Cancel 선택이 각각 맞는지 확인했다. 창 밖 닫기 ID 충돌, 누락/복수 대화상자, 바깥 오류 팝업 보호를 포함한 로컬 시험은 19개다. 수정 후 실제 Windows 실행 수용은 남아 있다.
