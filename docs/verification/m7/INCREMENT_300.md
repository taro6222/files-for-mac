# M7 Increment 300 — 재시작 후 수신 정리 기록 조회

상태: 디스크 기록 재조회와 화면 구현·로컬 검증 통과. F17·M7 전체 수용 완료가 아니다.

보관된 수신 파일 창의 ‘이전 정리 기록…’에서 이전 정리 작업을 확인한다. 새 controller가 디스크의 정리 기록을 다시 읽으며 원래 위치, 기록된 이동 위치, 위치 미확인, 이전 형식, 손상 기록을 구분한다. 작업 이름에는 복구한 수신 기록의 파일명을 사용한다. 선택한 작업의 실제 위치나 기록 파일을 Finder에서 확인할 수 있다.

새 정리 기록은 이동 전에 원본 폴더 identity를 함께 저장한다. 경로에 남은 폴더가 같은 identity인지, 수신 manifest와 내부 디렉터리·receipt를 복구할 수 있는지 다시 검사한다. 같은 경로의 대체 폴더나 링크는 채택하지 않는다. 표시는 보관 위치와 수신 기록의 일치만 뜻하며 원본·복사본 바이트가 현재도 일치한다고 표시하지 않는다. 복사·정리 시에는 기존 엔진이 다시 검증한다.

정리 중 종료되어 실제 이동 위치를 기록하지 못했다면 위치 미확인으로 남긴다. 휴지통 전체를 뒤져 위치를 추측하지 않는다. 기존 기록에 identity가 없으면 이전 형식으로 표시하고 기록 파일만 열 수 있다. 손상되거나 알 수 없는 상태·다른 저장소의 기록은 자동 이동·삭제·기록 수정 없이 보존한다. 기록 읽기는 UI 밖의 GCD에서 수행하고, 크기를 1MiB로 제한하며 no-follow로 연 일반 파일과 경로 identity를 대조한다.

정상·중단 상태, 실제 이동과 같은 경로의 교체, 이동 직후 기록 미갱신, 이전 형식·손상·다른 기록 보존, 기록·보관 경로 링크, 다른 저장소·손상된 receipt·과대 기록의 여섯 코어 시험을 추가했다. 네이티브 계약은 새 controller의 디스크 재조회, 실제 시험용 휴지통 위치 확인, 손상 기록의 위치 버튼 차단, 최소 창과 캡처를 검사한다. 시험 폴더만 identity를 확인하고 QA 폴더로 회수하며 사용자 휴지통을 비우지 않는다.

이 단계의 네이티브 검사는 같은 프로세스 안의 새 controller로 디스크를 재조회한다. 별도 프로세스 종료·재기동과 실제 키보드·VoiceOver 동선의 수용을 대신하지 않는다. 중단 작업의 명시적 복원·재시도 흐름은 후속 개발 항목이며 현재 화면은 조회와 Finder에서 확인하는 동작을 제공한다.

최종 앱·테스트 빌드가 성공했고, 전체 Swift 305개 중 성공 287개·별도 환경 건너뜀 18개, 수신·정리 네이티브 계약은 네 조합 각각 45개, 전체 AppKit은 각각 283개를 통과했다. 네 최소 창 캡처를 시각 확인했다. 정확한 소스·앱 SHA와 결과는 [검증 기록](cleanup-history-verification.json)에 저장한다.
