# M7 Increment 316 — 폴더 병합의 실제 복사 진행

상태: 구현·Swift·Debug·Release·실제 볼륨·네 조합 전체 UI 검증 통과. 새 소스 원격 수용과 전체 M7 출시는 미완료다.

기존 병합 창은 최상위 원본 처리가 끝난 뒤에만 갱신됐다. 이제 누락 항목의 네이티브 복사 콜백을 병합 실행기→다중 원본 실행기→진행 창으로 전달한다. 현재 복사하는 파일·하위 폴더의 논리 데이터 포크 바이트, 예정량·백분율과 조건을 만족하는 평균 논리 속도를 표시한다. 클론·희소 파일을 위한 기존 NativeFileCopy 어댑터를 사용한다. 충돌로 보존한 파일은 전송 바이트에 합산하지 않는다.

표시는 현재 누락 항목의 staging 진행이며 여러 원본 전체의 바이트 가중 합계나 물리 장치 처리량이 아니다. 100% 복사 뒤에도 내용 검증과 게시 단계가 남는다. 검증 중에는 작업 표시를 유지하며, 이전 원본·이전 하위 작업·이전 단계·작은 바이트 값의 늦은 알림을 버린다. 취소 요청 이후의 알림도 취소 안내를 덮어쓰지 않는다.

네이티브 복사의 실패·취소 시 부분 출력이 남지 않도록 새 0700 staging 디렉터리 안에 payload를 만든다. staging 생성이 실패하면 기존 경로를 정리하지 않는다. 원본 재검증·복사본 내용/메타데이터 검증·폴더 수정 시각 복원·비덮어쓰기 게시·완료한 항목의 Undo를 유지하며 게시 직전 부모와 staging descriptor를 다시 대조한다.

병합 내부 일부 실패가 상위 결과에서 성공한 병합으로 표시되던 집계도 수정했다. 상위 결과가 실패와 원인을 유지하며 취소는 취소 상태로 전달한다. 기존 ‘첫 원본 완료 뒤 취소’ 시험은 더 많은 중간 알림에 반응하지 않도록 완료 상태에서 취소하게 수정했다. 완료한 첫 결과를 보존하고 뒤 항목을 건너뛰는 기대 조건은 그대로다.

새 Swift 시험 다섯 개는 일반 누락 원본과 기존 폴더 안 누락 하위 트리의 실제 바이트 전달·링크/날짜/충돌 보존·단일 Undo, 복사 콜백 중 취소와 staging 정리, 복사 중 원본 변경 거부, 게시 직전 새 대상 보존, 하위 실패의 상위 전달을 검사한다. 전체 347개 보고 중 성공 329개·환경 건너뜀 18개다. 실제 APFS/대소문자 APFS/exFAT/FAT32/HFS+의 기존 시험 7개와 네 조합의 파일 작업 UI 각각 80개와 전체 AppKit 각각 283개도 통과했다. 제한 실행기 10개·Debug·일반 Release 빌드도 성공했다. 고정 Debug SHA-256은 `6fb058840c505a93298904e9945ff872d0c1b1cbb63f41d53834d925ca175a0c`다.

DEBUG 검증은 실제 병합 엔진 콜백을 수집해 실제 진행 창에 재생하고 바이트·검증 단계·늦은 알림·취소 안내를 확인한다. [네 조합 캡처와 소스/바이너리/원본 보고서 해시](merge-live-progress-verification.json)를 연결한다. 컴포넌트 렌더링 검증이며 물리 입력·VoiceOver·화면 합성 프레임 수용을 대신하지 않는다.

별도 이전 소스 `740ebf4`의 [전체 CI](https://github.com/taro6222/files-for-mac/actions/runs/45705238611)는 최종 실패다. 양쪽 CPU Swift 시험·두 Xcode 빌드·ARM 전체 검증은 성공했으나 Intel 한국어·영어/밝게의 Git 복제 fixture가 없어 전체 AppKit이 실패했다. [종료 상태](stored-finder-tags-ci-final.json)와 [오류·원본 로그 해시](stored-finder-tags-intel-failure.json)를 보존한다. 원인 확인·수정은 후속 단계이며 관측용 `folderSizeAutomaticTaskPending=false`를 실패 검사로 해석하지 않는다.

전체 선택 바이트 합계, 잔여 메모리 증가 해결·최신 소스 8시간, Intel 전체 UI 재수용·성능, 실제 접근성·원본 상태 대조, 정식 서명·공증·설치는 남아 있다. Developer ID 인증서와 공증 프로필은 사용자 준비 중이다.
