# 364단계 — 많은 파일의 7z 생성 목록 전송

## 결과

기존에는 입력 스냅샷 전체를 JSON 요청 하나에 담아 1MiB를 넘으면 생성에 실패했다. 일반·분할 생성에 공통으로 시작/묶음/확정 전송을 연결했다. 요청별 1MiB 상한은 유지한다. helper가 반환한 UUID와 누적 항목 수가 맞아야 다음 묶음으로 진행한다.

한 묶음은 최대 256항목이며 부모는 item JSON 합계 512KiB로도 제한한다. helper는 전체 100,000항목·누적 계획 256MiB를 넘기지 않는다. 모든 항목을 받은 commit에서 기존 경로·중복·크기·metadata 검증을 수행한 뒤 SDK 실행과 원본 FD 요청을 시작한다. 잘못된 offset/UUID, 빈 묶음, 과다 항목이나 조기 commit은 출력 없이 거부한다. 원본 경로 대신 스냅샷을 전달하고 FD broker·취소·기한·메모리 관찰·게시/복구 절차를 유지한다.

## 검증

- Debug 테스트 제품 빌드 성공(최종 7.81초), Release 앱 빌드 성공(32.55초). 앱 실행 없이 새 경로에 패키징·서명·manifest 확인.
- 실제 App Sandbox 번들의 Swift 클라이언트 55개 통과(17.036초). 한글·개행 이름을 포함한 4,000개 파일의 기존 단일 목록 JSON이 1MiB 초과임을 검사하고 생성 후 제품과 공식 7zz 양쪽에서 전체 내용 복원 확인. 해당 회귀 검사는 2.942초에 완료했다.
- 초기/후속 ACK의 잘못된 UUID·누적 수·조기 종료 거부와 미게시·원본·임시 파일 정리 확인. 기존 잘못된 FD 요청 검사는 새 업로드를 완료한 뒤 broker 경계에 도달하도록 수정했다.
- 실제 격리 helper의 FD 검사 36개, 비격리 진단 SDK 128개 통과. 묶음 전송 중 출력 0바이트, commit 후 broker와 공식 복원, 잘못된 순서·UUID·누락·항목 상한 거부를 포함한다.
- 제품과 같은 권한의 별도 native probe 15개 통과. 제품 helper의 권한 확장은 없다.

[소스·번들·검사 결과와 로그 해시](creation-plan-364-verification.json)를 보존한다. 로컬 GUI·전체 AppKit·장시간 시험은 시작하지 않았다. 원격 상태 조회만 했으며 수동 재시작하지 않았다.

## 남은 항목

목록 응답 8MiB 제한은 이번 생성 계획 변경과 별개다. 4,000개 검사를 100,000개 최대 규모 수용으로 집계하지 않는다. 최신 양 CPU 원격·지원 환경, CPU/프로세스 트리 경계, 나머지 metadata, 원본 전체 UI·실제 입력·VoiceOver, 외부 서비스·장시간 수용과 정식 서명·공증/설치·업데이트는 미완료다. 인증서와 notarytool 프로필은 사용자 준비 중이다.
