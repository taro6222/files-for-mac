# M7 Increment 12 — 대형 폴더 파일 식별자 조회와 exFAT 이름 변경

로컬 목록은 파일 식별자를 얻기 위해 항목마다 Foundation 속성 사전을 생성하던 경로를 `lstat` 기반으로 바꿨다. 장치 번호·inode·생성 시각을 사용하고 심볼릭 링크 자체를 확인한다. `lstat`이 생성 시각을 제공하지 않는 경우 Foundation 속성으로 재시도한다. 이름 변경 직전에도 동일한 방식으로 원본 식별자를 다시 확인한다.

실제 exFAT 테스트 이미지에서 `RENAME_EXCL`이 지원되지 않아 단일 항목 이름 변경이 실패했다. 같은 이름이 있으면 충돌로 처리하는 기존 파일 게시 경로를 재사용해, 해당 호출을 지원하는 볼륨은 기존 방식으로 처리하고 그 외 볼륨에서는 대상 부재를 확인한 뒤 FileManager 이동으로 처리한다. 회귀 시험은 실제 APFS·대소문자 구분 APFS·exFAT에서 목록의 식별자로 이름을 바꾸고 기존 대상이 있을 때 내용을 보존하는지 확인한다. 끊어진 심볼릭 링크의 이름 변경과 잘못된 식별자 거부도 검사한다.

## 최적화 빌드 측정

Apple Silicon macOS 27.2 (26B123), APFS, 빈 텍스트 파일, 썸네일 끔, 따뜻한 OS 캐시에서 동일한 AppKit 검증 스크립트를 사용했다. 아래 표는 식별자 조회 변경 후 측정이다. exFAT 이름 변경 보완은 측정 완료 전에 이어서 적용했으며, 이 탐색 시험은 이름 변경을 호출하지 않는다.

| 지표 | 이전 | 이번 |
|---|---:|---:|
| 10,000항목 첫 표시 p95 (20회) | 70 ms | 70 ms |
| 10,000항목 전체 표시 p95 (20회) | 1.842 s | 1.350 s |
| 100,000항목 전체 표시 범위 (3회) | 14.01–16.72 s | 13.16–13.90 s |
| 100,000항목 최대 샘플 RSS | 275 MB | 275 MB |

100,000항목 비교는 3회 범위다. 당시 다른 검증 프로세스도 실행됐으며 화면 합성 프레임은 측정하지 않았다. [원시 표본](performance-entry-identity.json)
