# M7 Increment 319 — 병합 선택 전체의 데이터 집계

상태: 데이터 집계 구현·Swift·실제 볼륨·파일 작업 UI·제한 실행기 검증 통과. 최종 Debug·Release·네 조합 전체 AppKit도 통과했다. 겹치는 상위/하위 폴더 Undo는 추가 개발이 필요하며 M7 출시는 미완료다.

병합의 현재 누락 항목 데이터 외에 여러 최상위 원본·하위 작업을 합친 논리 staging 바이트·예정량·백분율을 표시한다. 하위 실행기의 누적값을 원본별 최댓값으로 반영해 반복 콜백을 중복 계산하지 않는다. 기존 파일·형식 충돌은 전송 예정량 0으로 처리하며 불명 크기는 백분율을 표시하지 않는다. 최종 결과는 보고서에 선택적 필드로 저장하고 기존 저널 읽기를 유지한다. 늦은 데이터·예정량의 갱신은 집계 순번으로 거부하고 종료 문구는 최종 보고서의 값을 사용한다.

일반 경로는 실제 복사에 필요한 원본 스냅샷을 사전 수집해 재사용한다. 내부 준비 API는 기존 CopyEngine의 검증·게시 경로를 그대로 이용한다. 누락 하위 항목 스냅샷은 소비 시 저장소에서 제거하며 공유 준비 객체에 사용한 스냅샷이 계속 남지 않도록 했다. file-promise admission 검증은 유지한다.

같은 이름의 폴더 여러 개를 선택하면 앞 원본의 결과로 다음 목적지 구조가 바뀐다. 앞선 결과에 대한 디렉터리 descriptor를 필요한 이름 그룹 동안 유지하고 현재 경로와 다시 대조한다. 자기 작업이 만든 구조가 확인되면 준비한 원본을 재검증하고 현재 구조에 맞춰 재계획해 하위 폴더도 병합한다. 이 경우에는 추가 스냅샷 조회가 필요할 수 있다. 실제 복사할 데이터로 예정량을 고치며 기존 충돌 내용을 덮어쓰지 않는다. 같은 이름 그룹의 마지막 원본 이후 descriptor를 해제한다.

목적지 shelf를 사전 확인 전부터 유지하고 실제 원본 처리 및 하위 게시 경로에서도 대조한다. 확인 후 목적지를 교체하면 새 위치에 쓰지 않는다. 재귀 계획은 취소를 확인하고, 자기 자신·하위 위치로의 병합은 조회/복사 전에 거부한다. 사전 확인의 UI 알림은 최대 10Hz로 제한하고 취소된 남은 하위 항목의 불필요한 알림 생성을 피한다.

새 Swift 시험 아홉 개는 여러 원본/하위 작업의 합계·충돌 제외·Undo·기존 저널 읽기, 불명 크기, 사전 확인 취소, 새 충돌의 예정량 교정, 게시 충돌의 시도 바이트, 계획 취소/하위 위치 거부, 같은 이름 폴더의 중첩 병합, 뒤 원본 변경 거부, 목적지 교체 후 쓰기 거부를 검사한다. 전체 361개 보고 중 성공 343개·환경 건너뜀 18개다. 다섯 실제 파일 시스템의 기존 시험 7개·제한 실행기 10개·네 조합 파일 작업 UI 각각 82개·전체 AppKit 각각 283개도 통과했다. Debug·일반 Release 빌드와 Xcode 프로젝트 생성 후 차이 없음도 확인했다. 고정 Debug SHA-256은 `f05337a4ce82eeeb4af41f63e7d417419626773d31844c1f2f376276a37d6007`이다.

기존 병합 UI 검사를 확장해 실제 엔진 콜백의 현재 파일 6바이트와 선택 전체 9바이트(앞 원본 3+하위 파일 6)를 구분하고 최종 요약까지 확인한다. 보존한 충돌 6바이트는 합계에서 제외된다. UI 검사 수를 별도 중복 검사로 늘리지 않았다. [소스·바이너리·보고서 해시와 네 조합 캡처](merge-selection-verification.json).

데이터 100%는 검증·게시·작업 성공률이 아니다. 실패한 staging 시도도 포함될 수 있고 취소·실패 시에는 마지막 콜백 관측값이다. 모든 복사 결과·충돌·실패를 별도로 확인한다. 이동 선택 전체의 집계, 원본 UI 상태·물리 입력·VoiceOver·원격 재수용은 남아 있다.

## 미완료: 겹치는 폴더 Undo

같은 이름의 두 원본에서 첫 원본이 폴더 전체를 만들고 두 번째가 그 안에 파일을 추가하면 Undo 대상이 상위 폴더와 하위 파일로 겹친다. 현재 시험에서 하위 파일은 삭제되지만 그 삭제가 폴더 수정 시간을 바꿔 상위 폴더의 엄격한 메타데이터 검사가 거부된다. 결과는 `partiallyCompleted`이며 첫 원본의 파일을 보존한다. 이것을 전체 Undo 통과로 집계하지 않는다.

재현은 `mergeSelectionSameNamedRootsStillMergeNestedContentsAndPreserveOverlappingUndoSafely`다. `shared/common=first`, `shared/sub/a=a`, 두 번째 원본 `shared/common=second`, `shared/sub/b=bb`를 병합하면 common의 first를 보존하고 전체 데이터 8바이트를 복사한다. 현재 Undo 뒤 b는 없어지지만 a와 상위 폴더는 남는다. 이 시험의 부분 복원 기대값은 안전한 현재 동작을 기록하기 위한 것으로, F13의 최종 수용 기준을 대체하지 않는다.

다음 보완은 변경 없는 경우 하나의 Undo로 모든 자체 생성 결과를 되돌리고, 외부 내용·권한·xattr·시각·identity 변경은 계속 보존하는 것이다. 수정 시간을 무시하거나 현재 폴더 전체를 무조건 새 Undo 기준으로 수용해서 해결하지 않는다. 이 문제가 해결되기 전까지 겹치는 Undo·F13 전체·M7은 미완료다.

검토할 보완 방향은 자체 생성한 상위 트리와 이후 자체 생성 하위 결과를 하나의 Undo 대상으로 묶는 것이다. 현재 폴더를 그대로 새 기준으로 채택하지 않고, 기존 기준에 게시한 하위 결과만 합친 예상 내용·메타데이터를 만들고 실제 결과와 엄격하게 대조해야 한다. staging 생성·게시·정리가 부모 날짜를 바꾸므로 자체 변경 직후의 부모 날짜 기록도 필요하다. 열린 descriptor로 원래 상위 디렉터리임을 확인하고 모든 검증이 맞을 때만 겹치는 기록을 압축한다. 외부 변경·불명 기록·검증 실패가 있으면 보수적 보존을 유지한다. 이 설계는 아직 구현·수용되지 않았다.
