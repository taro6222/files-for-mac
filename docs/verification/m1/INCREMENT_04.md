# M1 네 번째 개발 단위 검증

검증일: 2026-09-09. M1은 진행 중이다.

## 변경

- `scripts/verify-ui.sh`: DEBUG 실행 파일로 한국어/영어 × 밝음/어두움 조합을 검증한다. 프로세스별 언어·테마와 독립 UserDefaults suite를 사용하며 사용자 전역 설정을 바꾸지 않는다. 창·사이드바·열 자동 저장도 테스트에서는 사용하지 않는다.
- 900×600 창, 10,000개 fixture 목록, 경로/목록 초점, 끝 행 스크롤, 히스토리 선택·스크롤 복원, 없는 폴더와 실제 POSIX 권한 거부 오류를 검사한다.
- 홈 카드 배경을 동적 색상으로 그리도록 수정하고, 콘텐츠 배경도 명시적으로 그린다. 화면 캐시가 창의 배경에 의존해 투명해지는 문제를 제거했다.
- 목록 맨 위 복원 시 첫 행이 헤더 뒤에 가려지는 문제를 `scrollRowToVisible(0)`으로 수정했다.

## 결과

macOS 26.6.2 (25G83), Apple Silicon, Swift 6.3.3. Swift Testing **21개 통과**, UI 검사 **10개 × 4조합 통과**, Swift release 앱과 Xcode Debug 빌드 성공.

| 조합 | 첫 비어 있지 않은 AppKit 표시 | 전체 목록 AppKit 표시 | 끝 행 표시 |
|---|---:|---:|---:|
| 한국어/밝음 | 60.24 ms | 938.60 ms | 2.78 ms |
| 한국어/어두움 | 50.14 ms | 982.35 ms | 3.05 ms |
| 영어/밝음 | 82.41 ms | 982.41 ms | 3.09 ms |
| 영어/어두움 | 48.16 ms | 961.46 ms | 3.73 ms |

이 수치는 생성 직후의 로컬 fixture를 읽고 앱 내부에서 layout/display가 완료된 시점이다. 10ms 간격 관찰을 포함하며 compositor의 실제 첫 frame, cold start, 반복 p95, 연속 스크롤 FPS가 아니다. 단일 조합당 최종 실행 1회 수치다.

[한국어/밝음](increment-04/ko-light.json), [한국어/어두움](increment-04/ko-dark.json), [영어/밝음](increment-04/en-light.json), [영어/어두움](increment-04/en-dark.json)에 자동 검사 원본을 보관한다. 같은 이름의 PNG는 앱 콘텐츠 뷰 자체를 AppKit으로 그린 이미지이며 OS 타이틀바·compositor 캡처가 아니다.

대표 이미지 검토: 한국어 밝은 목록에서 첫 행과 Unicode 이름, 영어 어두운 홈에서 카드·용량 텍스트, 영어 밝은 오류와 한국어 어두운 권한 오류의 배치를 확인했다. 최소 폭에서는 열 전체가 한 화면에 들어오지 않으므로 가로 스크롤을 사용한다.

## 재현

로그인된 macOS GUI 세션의 일반 사용자로 저장소 루트에서 실행한다.

```sh
scripts/verify-ui.sh
```

`build/ui-verification/{ko,en}-{light,dark}/`에 홈·목록 상단/하단·오류·권한 오류 PNG, report.json, run.log를 만든다. fixture는 성공 시 삭제된다. 실패 시 진단용으로 남을 수 있다. 이 폴더는 Git 제외이며 이번 기준 결과만 본 문서 옆에 보관했다. FSEvents와 AppKit 실행을 허용하는 환경이 필요하다.

## 남은 항목

- 실제 키 입력 전체 흐름과 VoiceOver 음성 안내. 이번 초점 검사는 responder를 직접 호출한 앱 내부 테스트다.
- 한국어 화면에서도 Foundation의 상세 오류 문자열이 영어인 경우가 있다. 앱의 오류 안내 제목은 한국어지만 전체 오류 현지화는 후속 작업이다.
- 연속 스크롤·반복 p95, 장시간·다중 창 조작, 실행 도중 시스템 테마 전환의 실제 UI 검증.
- Windows 원본 캡처 비교, macOS 14/Intel, 네트워크 볼륨과 제거 시나리오.
- POSIX 권한 거부 검증은 TCC(개인정보 접근 권한)와 별개다.
