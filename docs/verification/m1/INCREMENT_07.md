# M1 일곱 번째 개발 단위 검증

검증일: 2026-09-09. M1 진행 중.

## 변경

- 폴더 읽기 중에는 도구 모음의 새로고침 버튼을 **읽기 중단**으로 바꾼다. 이동 메뉴의 읽기 중단(Esc)도 제공하며 읽는 중일 때만 활성화한다. 목록·사이드바의 Esc는 직접 처리하며 경로 편집기에서는 기본 텍스트 편집 동작을 유지한다. ⌘R은 기존과 같이 명시적 새로고침이다.
- 중단 시 요청 세대를 무효화해 늦게 도착한 결과를 무시한다. 이미 표시된 부분 목록은 보존하되, 상태 표시줄에 목록이 불완전할 수 있음을 표시한다. 항목이 없으면 빈 폴더 대신 중단 및 재시도 안내를 표시한다.
- 중단한 읽기는 자동 감시 이벤트로 재시작하지 않는다. 사용자가 새로고침하거나 다시 탐색하면 중단 상태를 해제한다. 중단된 위치는 성공한 최근 방문으로 기록하지 않는다.
- 로딩 중과 중단 상태의 부분 목록이 아직 복원되지 않은 히스토리 선택을 자동으로 덮어쓰지 않게 한다. 명시적 선택 변경은 유지한다.
- 창을 닫을 때 진행 중인 모델 읽기도 취소한다.

파일 복사/이동 작업의 취소 기능이 아니라 M1 폴더 목록 읽기 제어다. OS가 처리 중인 파일 시스템 호출 자체를 강제 종료하지 않으며, 반환 후 결과를 버리는 방식이다. Desktop 경로 대기의 근본 원인 또는 TCC 문제가 해결됐다는 의미가 아니다.

## 자동 검증

- Swift Testing 25개: 기존 23개와 취소를 무시하는 느린 로더의 늦은 결과 차단·재시도, 스트리밍 부분 목록 보존·홈 이동 초기화 테스트를 추가했다.
- UI 행렬은 한국어/영어 × 밝음/어두움, 각 20개 검사다. 기존 17개에 실제 도구 모음 버튼 실행으로 중단, 늦은 결과/감시 갱신 후 중단 유지, 같은 버튼으로 재시도를 추가했다.
- 느린 로더를 주입한 테스트 창과 독립 설정 suite를 사용한다. 실제 파일 변경 작업은 하지 않는다. 한국어 밝은 테마의 중단 안내·상태 표시줄 배치를 AppKit 이미지로 확인했다.

재현:

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache" swift test --disable-sandbox -Xswiftc -gnone
scripts/verify-ui.sh
scripts/build-app.sh
xcodebuild -project FilesMac.xcodeproj -scheme 'Files macOS' -configuration Debug -derivedDataPath .build/xcode CODE_SIGNING_ALLOWED=NO DEBUG_INFORMATION_FORMAT=dwarf build
```

환경: macOS 26.6.2 (25G83), Apple Silicon, Swift 6.3.3. 이전 단위에서 확인한 dSYM 도구 대기를 피하기 위한 검증 빌드 옵션을 유지했다.

## 남은 항목

VoiceOver 음성 안내, TCC, Desktop 경로 대기 원인, Windows 원본 비교, 최소 macOS/Intel, 실제 네트워크 볼륨과 장시간 안정성 검증은 남아 있다. M1 완료 또는 전체 기능 완성으로 표시하지 않는다.

## 최종 결과

코어 25개와 UI 80개(20×4)가 모두 통과했다. release 앱 빌드·서명 검증 및 Xcode Debug 빌드도 통과했다. [조합별 원본 결과](increment-07/)와 한국어 중단 화면을 함께 보관했다.

실제 키보드 검증에서 기본 NSTableView가 Esc를 소비하는 문제를 발견해 목록·사이드바에서 직접 처리하도록 수정했다. 수정된 release 앱을 별도 bundle ID의 `Files Keyboard QA.app`으로 실행해 일반 앱 설정과 분리했다. 실제 Desktop 테스트 경로의 읽기 대기 중 목록 초점에서 Esc → 중단 안내·새로고침 버튼, ⌘R → 읽기 중 재진입, ⌃⌘S 후 Esc → 사이드바 초점에서도 중단을 확인했다. 검증 앱은 종료했다. 해당 경로가 정상적으로 열렸다고 판단하지 않는다.
